# 골인 안전 0.4 실험

## 적용한 동작

- 기존 5.3, 즉시압박 0.2, 벽 투자 0.3은 유지한다. `Atlas 골인 안전 0.4 실험`을 별도 선택과 `/api/goal` 서비스로 제공한다.
- 목표까지 3칸 이내, 양쪽 최단거리 최대 6칸, 남은 벽 합계 6개 이하이고 상대가 벽을 보유한 루트에서 골인 방어벽을 우선 탐색한다. 내부 검색에서 상대 목표가 3칸 이하일 때 상대 경로를 늘리는 벽을 먼저 읽도록 정렬한다. 단 한 칸 지연이라도 무시하지 않는다.
- 모든 합법 수를 유지한다. 기존 깊이 축소 규칙 자체는 유지하고, 위협 벽을 앞에서 읽어 늦게 읽힌 수의 축소 위험을 줄인다. 넓은 탐색 연장과 모든 말 이동의 깊이 보호는 대전 퇴보로 채택하지 않았다.
- 최대 3개의 연속 벽으로 만들 수 있는 추가 우회 이득을 최대 24개 배치까지만 조사한다. 상대의 벽 설치와 내 이동·대응이 교대로 일어나는 전체 게임을 푼 결과가 아니라 정적인 노출 지표다. 이 지표를 확정 승패나 승률로 표시하지 않는다.
- 내 골인 길에 노출이 있고 상대 벽이 내 벽 이상일 때, 멀리 놓는 벽이 설치 1턴으로 상대 1칸만 늦추면 압박 보너스를 취소하고 작은 대응 벽 보존 비용을 준다. 직접 읽힌 승리·패배 수순 점수는 기존 mate guard로 보호한다.
- 화면과 JSON에 골인 경로 위험, 제한 탐색의 패배 수순, 완전 종반 해법의 확정 결과를 구분해 기록한다. 점수가 0이라고 무승부로 표시하지 않는다.
- 0.4의 실제 버전·빌드와 번들의 계약을 검증한다. 원본 5.3의 소스와 기본 프로필은 변경하지 않았다.

## 비교 결과와 채택 범위

서로 다른 후보의 승패는 합산하지 않는다. 아래 대전은 모두 500ms·4코어, 0.3 상대의 개발 확인이며 공식 홀드아웃이나 인간 상대 승률 검증이 아니다.

|후보|보고서|결과|판정|
|---|---|---|---|
|넓은 골인 분기 연장 + 무거운 내부 노출 평가 + 준비 벽 면제 변경|development/report.json|3승 5패|퇴보, 비채택|
|루트 범위를 좁힌 분기 연장|scoped/report.json|5승 3패|추가 확인 필요|
|좁힌 연장 + 대응 벽 보존 비용, 다른 배치|confirmation/report.json|3승 5패|퇴보, 비채택|
|선택적 방어벽 탐색 순서 + 대응 벽 보존, 연장·내부 가중 평가·준비 벽 변경 비활성|ordered/report.json|5승 3패: 일반 3승 1패, 미로 2승 2패|별도 실험 선택으로 제공|
|같은 최종 후보, 새 시드 4경기|ordered-confirmation/report.json|2승 2패: 일반 1승 1패, 미로 1승 1패|일반화 향상 입증으로 부족|

최종 후보의 두 보고서는 같은 바이너리와 같은 설정이다. 개발 8경기와 새 시드 4경기를 함께 보면 7승 5패지만, 새 배치에서 2승 2패였으므로 확정적 실력 향상이라고 주장하지 않는다. 기본 엔진은 승격하지 않았다.

거절된 방식도 연구용 코드로 남겨 두었다. `QUORIDOR_GOAL_DEEP_MODE`, `QUORIDOR_GOAL_EVAL_MODE`, `QUORIDOR_PREP_MODE`는 일반 서비스에서 명시적으로 비활성화한다. 이들의 결과를 최종 모델의 성능으로 취급하지 않는다.

## 회귀 검증

- 사용자 기보의 11·15·17·35·37·39·45수 위치만 개발 사례로 보관했다. 전체 기보·과거 경기·사용자 타임스탬프·상대 식별 정보는 추가하지 않았다.
- `check.json`: 독립된 새 프로세스 3회, 500ms·4코어에서 37수의 기록된 가로벽 대신 전진을 선택했다. 이는 다른 수를 고른다는 확인이며, 그 수가 승리나 무승부를 보장한다는 증명은 아니다.
- 같은 검사에서 39수의 패배 수순 경고, 취소 후 재사용, 기존 0.3 바이너리와 비활성 제어군의 깊이 3 결과 일치 4건을 확인했다.
- `pressure-check.json`: 기본 압박 기능의 원본 비활성 일치 6건, 벽 지표 743건, 전술 16건을 확인했다.
- 최종 8경기에서 후보 214수와 기준 213수 모두 지정된 초과 기준(605ms)을 넘지 않았다. 최대 관측치는 각각 약 520ms, 525ms였다. 실제 사용자 환경의 지연을 보장하지 않는다.
- Rust 21개, Node 152개, 브라우저 51개 검증 통과. 브라우저에서는 실제 0.4 Native 서비스와 위험 경고·기보 저장을 확인했다. 공유 영상 인식 부분은 합성 영상이다.

## 남은 추천 순서

1. 0.4 실제 대국 JSON을 모아 같은 상대·골인 방어벽 유형에서 재분석한다.
2. 별도 일반·미로 대전과 실전 표본을 늘려 속도와 퇴보 여부를 확인한다.
3. 이번에 채택하지 않은 초중반 준비 벽 면제 변경을 좁은 사례별로 다시 검증한다. 가까운 경로를 건드린다는 이유로 과대평가하는 문제는 아직 완전히 해결하지 못했다.
4. 남은 벽이 적은 종반에서 실제 이동·점프·교대 벽 설치를 포함한 정확한 승패 계산 범위를 확장한다.

앱을 새로고침한 뒤 0.4를 선택하고 화면 공유를 다시 연결해 사용한다. 현재 사용 서버 갱신 확인은 `live.json`에 별도로 기록한다.
