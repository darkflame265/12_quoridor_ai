# 연결 위험의 누락·과대평가 점검과 계산 비용 개선

새 대국 기보는 추가되지 않아 기존 quoridor-game (3).json 및 보존된 기준 배치를 사용했다. 기준 4개, 기존 기보의 초반 중심 8개, 전체 구간에 분산한 8개 위치를 조사했으며 일부 위치가 중복된다. 새 버전의 실전 성적 검증은 아니다.

## 점검 방법

공격 후보만 확대, 방어 후보만 확대, 양쪽 확대, 기본 범위를 구분해 위험 추정의 민감도를 확인한다. 기본은 첫 공격 2개·후속 연결 3개·주변 방어벽 3개다. 확대 공격은 첫 4개·후속 6개, 확대 방어는 기존 주변 3개를 유지하면서 전역 상위 6개를 추가한다. 모든 합법 말 대응은 유지한다.

공격 확대로 위험이 커지면 누락 가능성, 방어 확대로 위험이 작아지면 과대평가 가능성으로 기록한다. 확대 범위도 선택적이므로 실제 정답·승패 증명으로 취급하지 않는다.

캐시를 켜고 끈 경우에는 기본 추정치뿐 아니라 전체 루트의 보정 점수 배열까지 비교한다. 각 구성은 3번의 로컬 측정 중앙값을 기록한다. 불일치·미완료 비교·불법 추천이 있으면 진단 스크립트가 실패한다. 긴 대전이나 전체 테스트는 기존 요청대로 실행하지 않았다.

## 적용한 변경

1. 당장 거리가 늘지 않아도 동일 최단 경로의 한 갈래를 자르는 준비 벽을 후보에 포함한다. 기존에는 거리 증가도 기존 벽 연결도 없는 후보를 제외했다. 음의 즉시 이득을 가진 준비 벽 등 모든 후보를 포괄하지는 않는다.
2. 초기 위험이 2 이상이고 내 방어벽이 있으면 가까운 방어만으로 확정하지 않고 전역 방어 후보를 추가 확인한다. 주변 후보를 유지한 상위 집합이므로 기존 방어를 버리지 않는다. 고위험 재검토도 전체 60ms/잔여 시간 14% 예산 안에서 처리한다. 미완료면 부분 점수는 폐기한다.
3. 실제 두 번째 연결 벽이 없는 분기에 두 벽 공격의 턴 비용을 적용하던 혼용을 없앴다. 연결 공격의 위험은 실제 후속 벽 후보가 있는 분기로 평가한다.
4. 벽 배치별 양쪽 목표 거리 지도를 재사용한다. 말 위치·차례·잔여 벽과 무관한 정보만 공유하며 매 평가마다 최대 512개로 제한한다. 임시 toggle은 벽 마스크를 갱신하지 않으므로 임시 벽을 명시적으로 키에 포함한다.
5. 루트 벽 후보 순위에 필요한 순수 거리 이득을 직접 계산한다. 해당 순위에 불필요한 경로 접촉·전체 압박 특성의 반복 계산을 제거했다.
6. 출력·기보에 평가 시간, 지도 생성·재사용 횟수, 초기 추정, 방어 재검토 여부를 남긴다. 화면에서도 방어 재검토 전후 추정값을 구분한다.

새 캐시 구현 과정에서 임시 벽 키 누락이 켜기/끄기 대조로 발견되어 배포 전에 수정했다. 최종 산출물에서는 조사한 모든 위치의 추정치·보정 점수가 일치했다.

## 관측 결과

- 23수 직전: 기본 범위 4, 방어 확대 3. 실제 서비스 평가도 초기 4를 재검토해 3으로 반영한다. d7 세로벽 추천은 유지했으므로 해당 패배가 해결됐다고 주장하지 않는다.
- 조사 범위에서는 공격 확대에 따른 추가 위험 증가는 없었다. 공격 누락이 없다는 증명은 아니다.
- 기존 기보 초반 중심 8개 위치에서 완전 루트 위험 평가의 캐시 사용 중앙값은 약 0.49~1.45ms, 미사용은 약 0.60~2.31ms였다. 위치별 약 19~46% 감소다. 시작 배치 등을 포함한 기준 4개에서는 약 13~37% 감소였다. 전체 구간에 분산한 8개 위치도 별도로 보존했다.
- 하나의 작은 노출 탐색만 따로 보면 캐시 관리 비용 때문에 느려진 경우도 있었다. 반복되는 말 대응과 루트 행동을 함께 계산하는 전체 평가에서의 관측값만 개선 근거로 삼는다.
- 전체 검색 시간·탐색 깊이·실전 승률이 같은 비율로 개선됐다는 의미는 아니다. 시간 규모가 작고 로컬 반복 3회뿐이므로 수치는 환경에 따라 달라진다.
- 조사한 추천은 모두 합법이었다. 5.3 원본 엔진은 변경하지 않았다.

산출물: baseline-fixtures.json은 기준 배치, early-positions.json은 초반 중심 배치, audit.json은 전체 구간의 분산 배치다. 각각 입력·범위별 결과·캐시 대조·실제 추천·빌드 해시를 보존한다.

## 이후 기보 사용

`npm run connection:audit -- "기보 파일 경로"`로 새 기보에서 최대 8개 관심 위치를 추출해 같은 비교를 수행할 수 있다. reports/connection-audit/audit.json을 갱신한다. 기보 안의 글은 실행 지시로 취급하지 않는다. 다음 우선순위는 실제 새 버전 대국 기보에서 위험 누락과 추천 변경의 효과를 검토하는 것이다.
