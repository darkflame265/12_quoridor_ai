# 미로에만 적용하는 얕은 깊이 보호

이전 전 구간 guard 후보는 그대로 보존하고 별도 `5.3 maze-guard` 후보를 추가했습니다. 평가 함수·가중치·수 정렬 점수·종반 해법은 5.3 speed와 같으며, 바꾼 것은 깊이 축소의 적용 범위입니다.

- 탐색 위치의 벽이 **8개 미만**: 기존 5.3처럼 깊이 3부터 LMR 허용.
- 벽이 **8개 이상**: 내부 노드는 깊이 4, 루트 수는 깊이 5부터 LMR 허용.
- 기존 뒤쪽 수 순서·연결 벽·보호 수·재탐색 예외는 유지.

벽 수 8개는 첫 실험의 간단한 미로 구분 기준이며 경로의 실제 복잡도를 완벽하게 판정하는 기준은 아닙니다. 벽 개수는 후보 수를 두기 전의 현재 탐색 위치에서 계산합니다. 벽이 7개에서 8개가 되는 수 이후에는 다음 탐색 노드부터 새 조건이 적용될 수 있습니다.

## 고정 검사와 비용

기존 미로 12개 상태의 깊이 3·4, 총 24회에서 점수·PV·노드 수가 비축소 참조와 모두 일치했습니다. 열린 판 7개 상태의 깊이 3에서는 원래 5.3 speed와 점수·PV·노드 수가 모두 같았습니다. 열린 판 검사는 벽 수 경계를 넘지 않는 상태들이며 모든 벽 7개 상태의 이후 검색까지 같다는 주장은 아닙니다.

같은 미로 12개 상태를 수당 500ms·4코어로 비교한 평균 완료 깊이는 speed 4.67, maze-guard 4.33이었습니다. 총 노드는 각각 1,229,172 / 1,383,775였습니다. 축소 범위가 달라 같은 명목 깊이도 실제 탐색 범위가 다르며 노드 증가를 계산 속도 개선으로 해석하지 않습니다. 고정 깊이 정확도와 시간 제한 실력을 따로 검증합니다.

원본은 [검증 기록](maze-guard68/proof.json)에 상태·두 실행 파일 식별자와 함께 저장했습니다. 실제 승률 개선으로 해석하지 않습니다.

## 개발 비교와 기준

새 search68-v1 시드는 개발 687731, validation 259463, holdout 816379입니다. 기존 배치와 분리 사이 중복 국면을 제외합니다. 먼저 동일한 속도 최적화를 사용하는 **5.3 speed**와 같은 국면·진영 교환·500ms·4코어·최대 180수로 12판을 비교합니다.

개발에서 전체 승수 우위, 일반·미로 각각 승수≥패수, 전술 16개, 시간 초과 5% 미만, 동일 빌드, 미로 참조 일치와 열린 판 보존을 모두 요구합니다. 통과할 때만 원본 5.3 상대의 새 validation 100판과 별도 holdout 16판으로 진행합니다. 실제 기본 엔진 교체는 두 분리 모두 전체 승수 우위·배치별 비퇴보·전술·시간·동일 빌드 조건을 통과해야 합니다. 결과를 본 뒤 기준을 바꾸지 않습니다.

```powershell
node scripts/build-maze-guard.mjs
node scripts/check-maze-guard.mjs reports/maze-guard68/new-proof.json
node scripts/evaluate-maze-guard.mjs --out reports/maze-guard68/new-development --split development --pairs 3 --baseline speed --ms 500 --cores 4
node scripts/verify-maze-guard.mjs reports/maze-guard68/new-development --save
```

출력은 새 경로를 사용합니다. 고정 사례는 노출된 개발 자료입니다. 과거 기록의 소스 해시는 당시 커밋에서 검증합니다.

## 실제 대전 결과와 채택 판단

| 단계·상대 | 일반 | 미로 | 합계 |
| --- | --- | --- | --- |
| 개발 12판 · 5.3 speed | 4승 2패 | 3승 3패 | 7승 5패 |
| 별도 validation 100판 · 원본 5.3 | 25승 25패 | 24승 26패 | 49승 51패 |

개발 단계는 고정 사례·열린 판·대전 조건·전술·시간 기준을 통과해 별도 100판으로 진행했습니다. validation에서는 전체 승수 우위와 미로 비퇴보 기준에 미달했습니다. **기본 엔진은 원본 Atlas 5.3을 유지**하며 holdout 16판은 사용하지 않았습니다. 후보 실행 파일과 자료는 후속 비교용으로 보존하고, 실제 기본 엔진이 강화됐다고 표시하지 않습니다.

일반 25승 25패를 통계적인 동등성 증명으로 해석하지 않습니다. 전체 승패의 단순 Wilson 95% 구간은 약 39.4~58.7%이며 진영 교환 대전의 상관관계를 반영하지 않아 참고용입니다. 개발과 validation의 상대·시작 국면도 다르므로 두 승률을 직접적인 성능 변화량으로 해석하지 않습니다.

validation 전술 16개는 모두 통과했고 후보 시간 초과는 0회였습니다. Rust 14개·Node 82개 테스트, 웹 빌드와 개발·validation 기보 재검증을 통과했습니다. 시간 제한 비교와 대전이 모두 끝난 다음 테스트를 실행했습니다.

원본은 [개발 판단](maze-guard68/development-decision.json), [100판 기록](maze-guard68/validation/report.json), [계측·배치별 요약](maze-guard68/validation-summary.json), [채택 판단](maze-guard68/release-decision.json)에 있습니다. 채택 판단의 통합 검사에는 미사용 holdout이 없어 거짓인 항목이 있으며, validation만의 결과는 `validationChecks`로 구분했습니다.

## 남은 추천 우선순위

1. 단순 벽 개수 기준의 확대·축소 반복은 보류하고, 루트만 보호하는 후보와 실제 강제 대응·위협 수만 보호하는 후보를 분리 비교.
2. 고정 사례의 분기별 참조 값을 확인해 필요한 보호와 불필요한 계산 증가를 구분.
3. 수작업 평가의 위협 누락·벽 자원·우회로 취약성을 한 요소씩 개선. 평가 점수를 유지하는 캐시 최적화로 비용을 줄이는 방법도 별도 검증.
4. 새 대전·holdout과 외부 엔진·숙련자 검증을 통과한 변경만 기본 엔진 반영.
