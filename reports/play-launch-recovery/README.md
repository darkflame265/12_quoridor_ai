# 실행 잠금 오인 복구

2026-10-31 확인 당시 실제12324 서버는 연결 거절 상태였고, running.json의 이전 앱 PID10224는 현재 Windows svchost 프로세스였다. 기존 실행기는 process.kill(pid,0)의 ESRCH만 종료로 인정해서 EPERM이 발생하는 재사용 PID를 활성 쿼리도 실행으로 오인했다. 두 실행 로그 모두10초 대기 후 play.mjs의 acquired 검사에서 종료됐다. 브라우저 탭을 열어 둔 것이 원인은 아니다.

수정 후에는 PID뿐 아니라 Node 프로세스 이름·실행 명령·생성 시각으로 소유자를 확인한다. 다른 프로세스에 재사용된 PID의 잠금은 자동 정리하며 실제 프로세스를 종료하지 않는다. 잠금 정리 직전 상태를 다시 확인하고 별도 복구 잠금으로 동시 정리를 직렬화한다. 새 잠금은 시작 시각과 starting/ready 단계를 기록한다. 실제 준비 중인 실행은 최대2분 기다린 뒤 기존 서버로 연결하며, 이미 준비된 최신 서버는 그대로 재사용한다.

검증: 관련 단위 검사4개 통과. 실제 남아 있던 잠금 자동 복구 및12324 HTTP200 확인. 기존 서버 재사용·동일 주소 재시작·포트 충돌 검사를 통과했다. 별도 임시 상태 폴더에 준비 중 상태를 만들고11초 뒤 실제 준비 상태로 바꾸는 검사에서 동시 실행기2개가 모두 정상 종료했고 원래 서버 PID를 유지했다.
