# 즉시압박 0.2: 쓸 수 없는 보유 벽 평가 보정

## 적용

- 원본 5.3의 소스와 기본 선택은 유지한다. 선택 가능한 즉시압박 실험 엔진을 0.2로 갱신했다.
- 벽이 12개 이상이고 한쪽만 벽을 보유한 잎 위치에서, 놓을 수 있는 모든 합법 벽이 차단할 수 있는 변을 제거한 그래프를 만든다. 그래도 상대의 최단거리와 같은 길이의 목표 경로가 남으면 보유 벽의 재고 보너스를 제외한다.
- 유효한 벽 후보와 연결 벽의 가치, 실제 벽 재고, 합법 수는 그대로다. 계산된 경로는 해당 위치의 평가 근거이며, 미래의 말 이동에 따른 벽 유효성 변화나 점프·몸막기까지 해결한 완전 종반 해법이 아니다. 이 근거로 강제 승패 점수를 만들지 않는다.
- 계산은 기존 위치 평가·벽 배치별 목표거리 캐시를 활용한다. 비활성 제어군은 원본과 같은 결과를 낸다.
- 기존 정확한 무벽 종반 해법은 유지한다. 한쪽 벽이 남은 종반 전체를 정확하게 푸는 기능은 아직 구현하지 않았다.
- JSON에 표시한 추천과 실제 행동의 위치·차례·엔진 ID·실제 Native 빌드·탐색 깊이·평가·예산·소요 시간·일치 여부를 저장한다. 같은 분석의 중간 결과는 최신 결과로 합치고 기록은 최대 1000개로 제한한다. 재동기화된 구간도 해당 기록을 보존한다. 수 일치는 추천을 보고 뒀다는 인과관계 증명이 아니다.
- Windows에서 기존 실행 중 바이너리를 중단하지 않고 새 빌드를 만들 수 있도록 0.2 빌드 디렉터리를 분리했다. 이미 실행 중인 앱은 다시 실행해야 새 엔진 서비스가 올라온다.

## 확인된 결과

- Rust 17개 테스트: 상태 복구, 좌우 대칭, 원본 동작 보호, 전술·종반·취소 검증.
- Node 146개, 브라우저 46개 검증 통과. 실제 Native 즉시압박 서비스의 화면 연동·관전·AI 대전 및 기보의 엔진 빌드 기록을 확인했다. 브라우저 영상은 합성 공유 영상이며 실제 외부 대국 자동 검증은 아니다.
- `check.json`: 동일 깊이 3, 단일 코어 비교에서 패배 기보 27수 전 평가가 +221 → -12로 보정됐다. 41수 전도 +221 → -12. 51수 전 확정 패배 점수 -29998은 유지한다. 점수는 승률이 아니다.
- `pressure-check.json`: 비활성 제어군 원본 일치 6개, 독립 벽 지표 743개, 전술 16개, 취소 후 재사용 확인.
- `development/report.json`: 500ms·4코어, 원본 5.3 상대 일반 2승 0패, 미로 1승 1패, 합계 3승 1패. 재생 합법성 확인, 시간 초과 기준 위반 0회.
- 이 4경기는 소규모 개발 확인이다. 별도 검증·홀드아웃을 통과하지 않았으므로 기본 엔진 승격이나 인간 상대 승률 향상을 주장하지 않는다.
- 사용자 기보의 4개 위치만 개발 회귀 사례로 보관했다. 상대 식별 정보나 전체 과거 경기 기록은 추가하지 않았다.

## 남은 순서

1. 한쪽 벽만 남은 종반에서 말의 충돌·점프와 벽 설치를 포함한 정확한 승패 경계를 계산한다.
2. 상대 마지막 벽으로 경로가 고정되기 전의 연결 벽 위협 평가와 대응 수를 개선한다.
3. 보정 조건·계산 비용을 독립된 일반·미로 검증 대전으로 비교한다. 지금 개발 사례에 맞춘 개선이 다른 위치에 퇴보를 만들지 않는지 확인한다.
4. 다음 실제 대국 JSON의 추천·실제 행동 기록으로 인식 오류와 엔진 선택 오류를 구분해 재분석한다.
