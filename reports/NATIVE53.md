# 마지막 벽 이후의 정확한 종반을 탐색에 연결

## 변경

기존 Atlas 5는 실제 보드의 양쪽 벽이 모두 0개일 때 고정 미로의 정확한 승패를 계산했습니다. 마지막 벽을 놓기 전의 검색에서는 그 종반에 들어가더라도 일반 평가로 판단할 수 있었습니다.

5.3 후보는 루트에서 남은 벽이 총 1개 이하인 경우, 검색 도중 마지막 벽을 놓아 양쪽 벽이 0개가 되는 첫 국면에서 고정 미로 역산 결과를 읽습니다. 이를 통해 마지막 벽의 당장 우회 거리뿐 아니라 이후 말 이동의 승패를 점수에 반영합니다. 이전의 정밀 평가·전술 보호 실험은 비교 프로필로 보관하고, 이번 후보는 기존 정적 평가와 일반 탐색을 유지합니다.

- 새 종반 표를 만드는 데 전체 생각 시간의 최대 25%를 사용합니다. 500ms 설정에서는 검색 시작 후 125ms까지만 새 표를 만들고, 이후에는 일반 검색과 완성된 표 조회를 사용합니다. 이는 별도로 125ms를 더하는 것이 아닙니다.
- 4코어가 완성된 표를 공유하고, 벽 배치별 표는 최대 32개를 보관합니다. 취소되거나 미완성인 표는 공개하지 않습니다. 반복 경로에 이미 벽이 없는 국면이 들어 있으면 정확한 조회를 생략해 탐색의 반복 처리와 섞이지 않도록 했습니다.
- 표의 이용 가능성이 바뀌는 종반 검색에서는 이전의 근사 전이표 점수를 경계로 재사용하지 않고 수 정렬만 재사용합니다.
- 루트의 마지막 벽 이후 상대의 패배가 정확히 확인되면 그 벽과 종반 거리를 따로 보관합니다. 이후 깊은 반복 탐색이 시간 부족으로 끝나도 이 승리 수를 선택할 수 있습니다. 이 경우에만 마지막 벽에 대해 `exact: true`, `outcome: 1`을 표시합니다. 일부 가지의 패배나 무승부만으로 루트 전체가 패배·무승부라고 표시하지 않습니다.
- 조회·새 표 생성 횟수를 결과와 대국 기록에 저장합니다. 일반 노드 수에 역산 작업 전체가 포함되는 것은 아닙니다.

이 기능은 모든 벽이 남은 일반 국면을 완전히 푸는 알고리즘이 아닙니다. 루트에 벽이 2개 이상 남아 있으면 새 종반 표를 만들지 않습니다. 보장하는 것은 완성된 고정 미로 표가 직접 증명한 마지막 벽의 승리입니다.

## 독립 대조와 개발 기보

양쪽 진영의 마지막 벽 테스트에서 네이티브의 선택을 독립 JavaScript 종반 풀이와 대조했습니다. 두 경우 모두 마지막 벽을 놓은 다음 상대 차례의 정확한 결과가 패배여야 통과합니다. 캐시 재사용, 예산 소진, 취소, 반복 경로도 테스트합니다.

이전 5.2의 미사용 기보는 개발 자료로 전환했습니다. 그 기보에서 마지막 벽 국면 73개를 찾고 먼저 나온 서로 다른 12개를 깊이 1·500ms·4코어로 비교했습니다. 새 후보가 정확히 승리하는 종반으로 들어가는 행동을 선택한 경우는 6개, 기존 엔진은 1개였습니다. 벽을 보관하는 행동의 승패는 이 대조에서 미확정이며, 이 숫자를 전체 대국 승률이나 기존 엔진의 명백한 오답 수로 해석하면 안 됩니다. [전체 진단과 기보](native53/last-wall-review.json).

## 새 배치와 승격 기준

`v3` 시드(개발 590203, 검증 482917, 미사용 907123)를 사용합니다. 시드가 달라도 같은 보드가 생길 수 있으므로 실제 말 위치·남은 벽·차례·정렬한 벽 배치로 중복을 확인합니다. 미사용 배치는 이전 두 세대의 검증·미사용 배치와 이번 검증 배치를 제외한 고정 풀에서 선택합니다. 기존 `v1`, `v2` 재현 기능도 유지합니다.

500ms·4코어, 검증 12판과 미사용 16판을 진영 교환 방식으로 진행합니다. 일반·미로 각각 비퇴행, 미사용 전체 승수 우세, 전술 16개, 응답 시간 초과 비율 5% 미만, 기보·소스 해시 검사 조건은 유지합니다. 작은 표본의 배포 기준이며 초인적 실력이나 통계적으로 결정적인 우월성을 보장하지 않습니다.

## 완료 결과와 반영

| 구분 | 일반 배치 | 벽 미로 | 전체 |
|---|---:|---:|---:|
| 검증 | 3승 3패 | 3승 3패 | 6승 6패 |
| 미사용 배치 | 5승 3패 | 4승 4패 | 9승 7패 |

두 평가 모두 전술 16개와 시간 조건을 통과했습니다. 후보 응답 p95는 검증 약 500.8ms, 미사용 약 500.7ms였고 최댓값은 각각 약 501.9ms, 502.0ms였습니다. 정한 시간 초과 기준을 넘긴 수는 없었습니다. 검증 후보 338수 중 69수, 미사용 후보 322수 중 42수에서 새 종반 조회·생성 기능이 실제로 사용됐습니다.

[검증 전체 기보](native53/validation/report.json), [미사용 전체 기보](native53/holdout/report.json), [승격 결정](../evaluation/native-release.json). **기존 기준을 모두 통과해 Atlas 5.3을 기본 네이티브 프로필로 적용**했습니다. 미로 결과는 동률이므로 미로에서 뚜렷하게 우세해졌다고 해석하면 안 됩니다. 표본은 작고 여러 후보를 개발한 뒤의 평가이므로 대규모 실력 검증이 추가로 필요합니다.

Node 테스트 63개·네이티브 Rust 테스트 13개·프로덕션 빌드를 통과했습니다. 실제 로컬 HTTP 서비스에서도 `Atlas 5.3 · Native Rust ×4`와 직접 증명한 마지막 벽의 `exact: true`, `outcome: 1`을 확인하고 독립 JS 종반 풀이에 다시 대조했습니다. [서비스 검증](native53/service-smoke.json).

## 남은 추천 순서

1. **GPU 배치 자가대국**: 여러 게임의 신경망 추론을 묶어 RTX 3060 Ti를 효율적으로 사용하고 학습 데이터 생성을 늘립니다.
2. **정책·가치 신경망과 MCTS 본격 학습**: 보드 구조를 반영한 모델로 장기 벽 전략을 학습하고 기존 Atlas 5.3과 비교합니다.
3. **과거 모델 리그와 자동 승격**: 기존 엔진·이전 모델을 상대로 실력과 계산 시간을 함께 검사합니다.
4. **미로·회귀 평가 규모 확대**: 작은 표본의 우연을 줄이고 벽 자원·연속 함정·승부 전환 국면을 더 넓게 확인합니다. 이번 미사용 배치는 앞으로 개발 자료로만 사용합니다.
5. **외부 실력 검증**: 독립 엔진·숙련자와의 대전으로 실제 수준을 확인합니다.

## 재현

```powershell
npm run native:verify -- --apply
node scripts/review-last-wall.mjs
```

평가의 기본 배치는 `v3`, 개별 결과 기본 폴더는 `reports/native53`입니다. 이전 전술 보호 후보는 `--profile tactical`, 정밀 평가만 사용한 후보는 `--profile strategy`, 정밀 평가와 전술 보호를 합친 후보는 `--profile combined`로 비교할 수 있습니다. 현재 후보는 `--profile candidate`입니다.

신경망·GPU 학습·화면 방향·말 이동과 벽 조작은 바꾸지 않습니다.
