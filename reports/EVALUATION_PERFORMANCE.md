# 평가 중복 계산 최적화

실험 엔진의 위협 후보 평가에서 같은 벽을 반복 검사하는 비용을 줄였습니다. 후보의 순서, 동점 처리, 부동소수점 합산 순서는 유지했습니다.

- 같은 최단 경로 순회에서 벽의 배치 가능 여부와 연결도 기여값을 한 번 계산합니다. 배치 불가능 결과도 기억합니다.
- 후보 선택 시 128개 슬롯 전체 대신 실제 경로에 걸린 후보만 순회합니다.
- 캐시는 함수 호출 안에서만 유지하므로 말 이동·벽 배치 이후 오래된 결과를 재사용하지 않습니다.

## 수정 전후 검증

수정 전은 `47c0cd0`에서 빌드한 실행 파일입니다. 수정 후와 같은 컴파일 설정, 국면, 가중치로 실행했습니다. 기존 Atlas 5.3 패배 기록의 167개 국면에서 연결도 적용 범위 5가지 × 위협 가중치 2가지 × 평가 모드 6가지, 총 10,020개 평가 점수와 반복 합계가 모두 동일했습니다.

각 측정은 167개 국면을 50회 평가하며, 수정 전후 실행 순서를 번갈아 5회 측정한 중앙값입니다. 두 번의 독립 실행 결과를 함께 보존했습니다. 시간 측정 중에는 다른 테스트나 대전을 실행하지 않았습니다.

| 평가 모드 | 첫 측정 속도 배율 | 재측정 속도 배율 |
| --- | ---: | ---: |
| cache4 | 1.206배 | 1.089배 |
| reserve | 1.022배 | 1.069배 |
| coverage8 | 1.180배 | 1.117배 |
| combined8 | 1.114배 | 1.204배 |

기본 실험 평가 cache4는 두 측정에서 약 9~21% 빠른 처리량을 보였습니다. 수정하지 않은 baseline·reference8에도 변동이 있으므로 이 수치를 전체 탐색의 속도나 승률 개선으로 해석하지 않습니다. 원본 점수·시간·입력 및 바이너리 해시는 [첫 측정](performance60/profile.json), [재측정](performance60/confirmation.json)에 있습니다.

실제 앱의 기본 엔진은 **Atlas 5.3을 유지**합니다. 이번 변경은 별도 실험 엔진의 계산 최적화이며, 기존 실패 후보를 기본 엔진으로 승격하지 않습니다. 과거 대전 기록은 당시 커밋의 소스와 바이너리로 검증해야 합니다.

Rust 23개·Node 70개 테스트, 웹 빌드와 기존 기본 엔진 진단 자료 12개 국면의 재검증을 통과했습니다. 수정 전 빌드의 소스 목록은 [이전 빌드 기록](performance60/before-build-manifest.json)에 보존했습니다.

## 재현

`47c0cd0`의 release `eval-benchmark` 실행 파일을 별도로 보관한 다음 현재 버전을 빌드합니다. 원본 프로젝트의 파일을 되돌릴 필요 없이 별도 checkout에서 이전 실행 파일을 빌드해도 됩니다.

```powershell
npm run maze:build
node scripts/profile-evaluation.mjs <이전-eval-benchmark.exe-경로> reports/performance60/new-run.json
```

출력 경로는 새 파일을 사용합니다. 환경변수의 연결도 범위와 가중치는 스크립트가 고정합니다. 전체 점수 비교와 실행 파일 해시를 함께 기록합니다.

## 남은 추천 우선순위

1. 전체 탐색의 정렬·경로 계산 비용 측정과 중복 제거. 이번 개선은 정적 평가 구간에 한정됩니다.
2. 패배 국면의 강제 수 누락을 분석하고 탐색 깊이·위협 후보 범위 개선.
3. 후보를 미사용 validation·holdout 및 외부 엔진으로 검증하고 통과 시 기본 엔진에 반영.
4. 검증된 엔진을 활용한 지도 자료 생성과 GPU 학습 재검토.
