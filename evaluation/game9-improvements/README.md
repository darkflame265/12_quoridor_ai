# 기보 9 개선 적용과 대안 검증

## 반영한 변경

정확 고정 미로 결과에서는 같은 승패와 같은 남은 수를 가진 후보만 비교한다. 목표 거리, 최근 방문 횟수, 결정적인 수 번호 순으로 선택한다. 결과와 남은 수는 변경하지 않는다. JS/WASM 고정 미로도 같은 거리 조건에서 목표에 가까운 수를 우선한다.

최신 네이티브의 일반 탐색에서는 승패 수순 점수 영역에서 같은 점수인 후보에만 말 이동·목표 거리·최근 방문 기준을 적용한다. 일반 평가 점수의 단순 동점까지 확대하지 않았다. 특히 영창/감소 깊이 탐색이 반환한 경계값이 현재 최선과 같다고 해서 곧바로 동점으로 교체하지 않는다. 교체하고 싶은 후보는 원래 깊이·전체 창으로 다시 계산한 뒤 비교한다. 시간 안에 확인하지 못하면 해당 반복의 미확인 결과를 게시하지 않는다. 선택적 탐색의 수순 점수 자체가 전체 게임 증명으로 바뀌는 것은 아니다.

원본5.3 네이티브 소스는 보존했다. 최신 실험 엔진의 생성 패치와 정확 결과의 출력 선택에만 연결했다. 새로운 전략 가산점·기보 정답 하드코딩은 없다.

## 결과와 한계

- 59수: a5 역주행 → a7 전진. 패배 예상6수 유지.
- 61수: a4 역주행 → a6 전진. 패배 예상4수 유지.
- 57수: a6 전진 유지. 패배 예상8수 유지.
- 53수: 새 계산은 a6을 선택하며 같은 패배 점수를 유지한다. 다만 같은 새 프로세스 조건에서는 이전 바이너리도 a6을 골랐다. 실제 기보의 a5 세로벽은 캐시·작업 처리 순서가 있는 동점 선택 차이였으므로, 이 수가 반드시 변경 전후에 달라진다고 주장하지 않는다. 새 기준은 같은 점수로 확인된 말 이동이 있으면 벽을 보존하도록 명시한다.

같은 입력을 작업1개와4개로 각각 비교해 score와 exact outcome이 유지됨을 확인했다. ties.json, ties-4.json에 기록했다. Rust 검사3개는 패배 수순 길이 보존·벽 보존 선택·최단 승리 보존을 확인한다. JS 검사3개는 정확 종반 동점과 검증용 제한벽 풀이를 확인한다.

## 전략 대안 검증

43·45·47·49수의 실제 이동, 다른 합법 말 이동, a8/b7 선점 세로벽, 상대 경로 방해벽을 각각 강제로 적용했다. 각 후보는 새 프로세스·작업1개·최대1800ms·완료 깊이5 조건으로 상대의 강한 응수를 탐색했다. 모든 기록 후보가 깊이5를 완료했다. 이는 전 후보를 완전히 푼 결과나 승리 증명이 아니다.

43수는 실제 a5가 비교 후보 중 높았다.45수는 b5가 a6보다9점 높았으나 차이가 작고 실제 승리 개선은 미확인이다.47수는 b6/a7,49수는 c6/b7이 같은 점수였다.

49수 c6 뒤 상대 b7 가로벽, 대안 b7 뒤 상대 b7 세로벽을 별도로 정확하게 풀었다. 두 경우 모두 이후 상대 벽0·사용자 벽2이며, 벽 사용 시점을 포함하는 유한 상태 역산에서 사용자 패배였다. 단순히 마지막 가로벽만 피하면 이긴다는 근거는 나오지 않았다. 제한벽 검증기는 실시간 선택에 연결하지 않았다.

따라서 전략 가중치를 추가로 변경하지 않았다. 검증된 패배 회피 대안 확보는 여전히 미해결이며, 이는 기존에 합의한 대안 검증 범위다. 이번 변경으로 이 기보를 이기게 됐거나 전체 승률이 높아졌다고 주장하지 않는다.
