# 빠른 진행 복원과 복잡한 벽 배치 추적

2026-10-29. 빠르게 여러 수가 진행된 상황과 벽이 많은 배치에서 발생하는 오류를 분리해 처리하도록 변경했습니다. 엔진·모델·승격 상태는 변경하지 않았습니다.

## 사용법

- 기존과 같이 화면 연결 → 자동 격자 → 초기 배치·차례 확인 → 적용 → **자동 감시 시작**을 사용합니다.
- 한두 수를 넘어 놓쳤을 때 **최대 6수** 범위에서 유일한 최단 합법 진행을 찾습니다. 성공하면 기보·차례·벽 수와 내 차례 추천을 갱신합니다.
- **현재 화면 재동기화**는 공유를 유지한 채 감시를 멈추고 최신 프레임을 가져옵니다. 말·벽·차례·잔여 수를 확인해 적용한 뒤 감시를 다시 시작하세요. 현재 차례는 직접 확인해야 합니다.
- 복원하지 못한 진행을 새 기준으로 적용하면 **중간 기보 누락**이라고 표시합니다. 이전에 확정한 기보 구간은 최대 8개를 세션과 저장 JSON의 `screenSegments`에 보관합니다. 현재 기보 목록은 새 기준 이후 수만 표시합니다. 과거 구간의 별도 재생 UI는 아직 없습니다.
- **인식 진단 저장**은 최근 최대 40개 오류·복원 사건, 마지막 정상 배치, 인식한 말·벽·원시 벽 후보 수·색별 벽 수, 최근 중간 배치를 JSON으로 저장합니다. 원본 이미지·영상은 포함하지 않으며 서버로 전송하지 않습니다. 같은 오류와 판독 결과의 반복 기록은 합칩니다.

## 변경 내용

### 격자와 배치 검증 분리

기존에는 보드 후보를 고르는 단계에서 벽·자원·경로 검사까지 통과해야 했습니다. 이 때문에 벽 과다 검출이 격자 재탐지 실패로 표시될 수 있었습니다. 이제 칸 배열과 말 후보로 격자를 고르고, 벽 충돌·과다 검출·불가능한 진행을 별도로 검증합니다.

전체 탐지가 실패해도 이전 격자의 칸 모서리 색상 증거가 94% 이상 일치하고 영상 크기가 같으면 격자를 유지합니다. 말 중심·벽 틈을 피한 324개 지점을 비교하며, 새 배치와 합법 수 검증은 계속 수행합니다. 전체 화면 이동·크기 변경·증거 부족에서는 무조건 유지하지 않습니다. 잘못된 격자를 계속 적용하는 방식이 아닙니다.

### 연결된 벽 중복 후보 정리

같은 색 벽이 끝에서 이어지면 중간에 한 칸 밀린 가짜 벽이 추가로 검출될 수 있습니다. 동일 후보를 제거하고 서로 겹치거나 교차하는 후보 묶음마다 충돌 없이 가장 많은 실제 구간을 설명하는 조합을 찾습니다. 기존에 확정한 벽이 후보에 있으면 그 위치를 보호합니다.

최적 조합이 여러 개이거나 탐색 한도를 넘으면 **벽 후보 충돌**로 보류합니다. 색별 10개 초과도 별도 오류로 표시하며 잔여 수를 0으로 억지 보정하지 않습니다. 겹침·목표 경로·자원 보존 검사는 계속 적용합니다. 화면에서 사라진 기존 벽을 무조건 복사해 채우지도 않습니다.

### 중간 배치와 제한된 진행 복원

2회 연속 확인한 유효 배치를 최근 6초·최대 24개 보관합니다. 3회 연속 확인한 최종 배치를 반영할 때 이 중간 배치들로 한두 수씩 연결할 수 있으면 사용합니다. 연결되지 않으면 최종 배치까지 3~6수의 합법 진행을 탐색합니다.

복원은 **최단 진행이 유일한 경우**만 허용하며, 최대 12,000개 방문·80ms 계산 예산을 둡니다. 여러 진행, 벽 삭제·색 변경, 시간/작업 한도 초과는 마지막 정상 배치를 유지하고 이유를 표시합니다. 새 배치가 불확실한 동안 예전 분석을 취소합니다. 확정한 구간 이후 새 프레임만 사용하도록 반영·격자 이동·일시정지에서 버퍼를 초기화합니다.

## 검증

- 전체 Node 테스트 **124개**, 웹 빌드 통과.
- 3~6수 연속 진행 복원, 여러 진행이 가능한 경우 거부, 중간 배치로 진행 구분, 벽 설치 포함 복원, 계산 한도, 벽 삭제·자원 불일치 차단을 검사했습니다.
- 연결 부위를 채운 **벽 20개** 비트맵에서 20개를 모두 읽고 양쪽 잔여 수 0개를 확인했습니다. 원시 후보가 20개를 초과해도 중간 가짜 벽을 제거합니다. 모호한 두 후보는 임의로 선택하지 않습니다.
- 독립 headless Chrome **27개 시나리오**에서 실제 영상 픽셀 인식→6수 복원→추천 갱신, 모호한 진행 보류·진단 다운로드, 현재 화면 재동기화·누락 표시·이전 기보 보관과 새로고침 복원, 벽 20개 판독, 전체 칸 탐지가 실패해도 모서리 증거로 격자 유지하는 흐름을 확인했습니다.
- 공유 영상은 자체 캔버스 합성 MediaStream이며, 실제 Wallz 대국을 검증한 결과는 아닙니다. 사용자 첨부 이미지의 정확한 실패 원인을 실제 프레임으로 재현한 것도 아닙니다.

## 현재 제한과 남은 추천 우선순위

화면만으로는 보이지 않은 왕복 이동이나 모든 실제 기보를 알아낼 수 없습니다. 같은 최종 배치에 더 긴 진행이 있었는지도 단정할 수 없습니다. 차례·잔여 벽 숫자·우측 기보 OCR은 이번에 구현하지 않았습니다. 따라서 검증 없이 현재 차례를 추측해 자동 기준 배치로 바꾸지 않고 사용자의 확인을 받습니다. 실제 벽과 같은 색의 오래 유지되는 미리보기 구분 제한도 남습니다.

1. **원본 차례·잔여 벽·기보 독립 판독**: 실제 표시와 추적 결과를 대조해 모호한 진행을 해결하고 현재 배치 자동 재연결의 근거를 확보합니다.
2. **실제 실패 프레임 회귀 검증**: 빠른 착수·복잡한 미로·브라우저 확대별 오인식률과 복구 지연을 측정합니다. 진단 JSON으로 오류 종류와 벽 후보를 구분합니다.
3. **복원 범위와 자동 복구 확대**: 기보·수 번호를 활용해 6수 초과, 되돌리기·새 게임을 판별합니다.
4. **이전 기보 구간 재생·진단 표시 개선**: 보관 구간의 조회와 벽 검사 위치 시각화를 제공합니다.
5. **비용·지연 최적화**: 격자·인식 처리 분리와 프레임 처리 비용을 계측합니다.
