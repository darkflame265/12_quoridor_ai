# 기보 8 후반 경주 검증

기존 우선순위 1번(후반 경주 집중 검증)을 수행했다. 게임의 평가 가중치·추천 선택·사전 계산 설정은 변경하지 않았다. 이번 변경은 재현 가능한 검증기와 회귀 사례이며 패배 해결이나 승률 향상 적용이 아니다.

## 확인된 분기

사용자 벽이 0개인 후반을 두 가지 제한 게임으로 정확하게 풀었다.

- 상대가 지금 한 번 행동한 뒤 벽을 더 사용하지 않는 경우: 모든 합법 말 이동·점프·벽 설치를 열거하고 고정 미로를 역산했다.
- 상대가 앞으로 원하는 시점에 벽을 최대 한 번 설치하는 경우: 벽 사용 전의 모든 말 배치·차례를 역산하고, 벽 사용 후는 고정 미로의 정확 결과에 연결했다. 설치 시점을 지금으로 제한하지 않는다.

실제 상대는 벽이 6개였다. 한 개만 사용하는 상대에게도 패배하는 수라면 실제 게임에서도 상대가 그 전략을 선택해 승리할 수 있다. 반대로 한 개 조건에서 승리해도 6개를 쓰는 상대를 이긴다고 주장할 수 없다.

41수 실제 e4 후퇴는 즉시 벽 하나만 검사하면 패배가 드러나지 않았다. 하지만 설치 시점을 자유롭게 허용하면 상대 벽 한 개만으로도 사용자 패배가 강제된다. d5 전진과 c4는 한 개 제한 게임에서는 사용자 승리다. 따라서 41수의 회피는 구체적인 취약 분기로 재현된다. 이 위치가 실제 전체 게임의 최초 패착인지는 아직 확정하지 않았다.

51수에서는 즉시 벽 하나만 검사했을 때 b5가 유일하게 패배 반례가 없었다. 설치를 늦추는 공격도 허용하자 b5를 포함한 모든 합법 이동이 패배였다. 그러므로 51수 왕복만 바꾸면 해결된다는 설명은 맞지 않는다. 47·49수 역시 한 개 제한 게임에서 모든 이동이 패배한다. 39수와 마지막 벽 사용 직후인 37수는 한 개 제한 게임에서 생존 가능했다.

## 사전 계산 대조

41·49수를 각각 새 프로세스와 ScreenPonder로 캐시를 준비한 프로세스에서 비교했다. 전경은 작업1개·완료 깊이4·최대2500ms로 동일했다. 추천과 점수는 각각 e4/+101, d5/−546으로 같았고 준비한 캐시에서 계산 시간이 줄었다. 이 두 실험에서는 실제 배치와 일치하는 첫 추천 캐시 적중이 없었다. 따라서 배경 탐색 캐시의 영향은 비교했지만, 캐시 추천 즉시 게시의 모든 경우나 전체 실력은 검증한 것이 아니다. 이 구간의 패배를 사전 계산 탓으로 돌릴 근거는 나오지 않았다.

## 검증과 재현

입력은 `evaluation/fixtures/game8-record.json`이다. 사용자 이름·화면·이전 대국은 포함하지 않았다.

```text
node scripts/verify-wall-free-race.mjs evaluation/fixtures/game8-record.json reports/game8-race-verification/race-certificates.json
node scripts/check-game8-ponder-pairs.mjs
node --test src/one-wall-race.test.js
```

검사는 벽이 없을 때 기존 고정 미로 풀이와 전체 말 배치·차례 결과 일치, 상대에게 벽을 추가해도 사용자 결과가 좋아지지 않는 성질, 좌우 진영 회전 대칭, 원본 상태 보존, 벽이 있는 사용자의 잘못된 입력 거부, 41수 분기를 포함한다. `results.json`은 상세 열거에서 변형 목록을 제외한 요약이다. 상세 목록은 명령으로 재생성할 수 있다.

이 제한 게임 검증기는 실시간 엔진에 연결하지 않았다. 제한 게임의 승리를 실제 잔여 벽 6개에 대한 승리로 오인해 추천을 강제하지 않기 위해서다. 새로운 가산점은 추가하지 않았다.

## 남은 기존 우선순위

1. 왕복 진단을 8~12차례의 경로로 확장
2. 연속 벽 소비를 묶어서 평가
3. 안내 오류 정리

기존 목록에 새 항목을 추가하지 않았다. 이번에 확인한 41수 분기는 다음 왕복·진척 진단의 회귀 사례로 사용한다.
