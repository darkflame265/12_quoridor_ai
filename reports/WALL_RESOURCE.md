# 벽 우선순위와 마지막 자원 소모 기준 조정

이 문서는 `a0be405`의 실제 후보·결과입니다. 이후 [벽 선분 기하에 따른 연결도 교정](WALL_GEOMETRY.md)에서 연결도 모드와 v4 보고서가 추가됐습니다. 과거 결과를 해시까지 재검증하려면 기록된 버전의 소스·바이너리가 필요합니다.

이전 수 정렬 후보는 새 holdout에서 7승 9패로 탈락했습니다. 이번에는 방어 우선순위와 마지막 벽 소모를 더 좁은 조건으로 판단하는 후보를 추가했습니다. 정적 평가 점수·게임 규칙·정확한 종반 계산은 유지하며, 수를 읽는 순서만 바꿉니다. 별도 Rust 후보 이름은 `Atlas 5.6 experiment`입니다.

## 먼저 확인한 자료

이전 validation 패배 기보에서 후보가 설치한 벽은 34개였습니다. 이 중 27개는 `상대 거리 증가 - 자기 거리 증가 - 벽 설치에 쓰는 한 차례`가 0 이하였습니다. 장기적인 통로·연결 벽 효과가 있을 수 있으므로 이 수들을 실수로 판정하지 않습니다.

27개 중 설치 전 자기 벽이 1개 남은 수는 2개, 2개 남은 수는 2개였습니다. 따라서 마지막 벽 소모만으로 모든 패배를 설명할 수는 없습니다. 두 가지 변경을 별도 모드로 비교합니다.

## 변경한 기준

| `--search` | 방어 판단과 연결 벽 | 남은 벽 보정 |
| --- | --- | --- |
| legacy | 기존 Atlas 탐색 | 기존 방식 |
| ordering | 이전 후보의 근접 방어·연결 벽 보너스 | 없음 |
| threat | 실제 한 수 패배 위협 확인, 중립 연결 벽의 추가 보너스 제거 | 없음 |
| resource | threat와 동일 | 마지막 1~2개 벽의 중립적 소모를 후순위로 |

`threat`와 `resource`는 상대의 합법적인 말 이동에 실제 즉시 승리가 있는지 확인합니다. 점프·대각선 이동도 포함합니다. 실제 위협이 있을 때 이를 막는 수는 먼저 읽고, 여전히 상대의 즉시 승리를 허용하는 수는 뒤에서 읽습니다. 자기 말이 즉시 승리하는 수는 기존의 가장 높은 우선순위를 유지합니다.

상대가 목표선에 가깝다는 이유만으로 방어 벽에 큰 보너스를 주지 않습니다. 연결 벽도 순수 거리 증가가 1인 경우의 추가 보너스를 없애고, 2 이상인 경우에만 작은 보너스를 줍니다. 벽 설치 한 차례를 빼면 이 두 조건은 각각 중립·양의 즉시 이득에 해당합니다.

`resource`는 설치 전 벽이 1개면 900, 2개면 450의 정렬 점수를 차감합니다. 조건은 상대 거리 증가에서 자기 손해를 뺀 값이 1 이하일 때입니다. 벽이 3개 이상이거나 즉시 순이득이 양수이면 이 차감은 없습니다. 실제 한 수 패배를 막는 수에는 차감하지 않습니다. 이 값은 정렬 단위이며 승률이나 정적 평가 점수의 변화가 아닙니다.

모든 합법 수를 검색에 남깁니다. 벽을 강제로 금지하거나 방문 후보 개수를 줄이는 변경이 아닙니다. 정렬이 불리해진 벽도 기존 축소 검색과 개선 시 전체 깊이 재탐색을 거칩니다. 마지막 벽 이후의 정확한 종반 판정과 증명된 승리 수 보존도 유지합니다.

## 자료 분리

새 `search56-v1` 배치군의 시드는 개발 569321, validation 349979, holdout 926347입니다. 기존 Native v3와 이전 `search55-v1` 전체 분리 배치, 새 개발·validation·holdout 사이의 중복을 제외합니다. 일반·미로 각각 50개씩의 합법적 시작 기보를 준비하며 자동 테스트로 재생·분리를 확인합니다.

새 배치는 이전 패배 자료와 분리된 평가에 사용합니다. 시드가 공개된 재현용 시험이며, 같은 배치를 다음 튜닝에서 다시 쓰면서 미사용이라고 부르지 않습니다.

## 실제 개발 비교와 validation

새 일반·미로 각 1배치에서 진영을 교환해 모드마다 4판씩 총 16판을 실행했습니다.

| 모드 | 일반 | 미로 | 합계 |
| --- | --- | --- | --- |
| legacy 대조군 | 2승 | 2승 | 4승 0패 |
| ordering 이전 후보 | 1승 1패 | 1승 1패 | 2승 2패 |
| threat | 1승 1패 | 1승 1패 | 2승 2패 |
| resource | 1승 1패 | 2승 | 3승 1패 |

새 후보 중 resource를 별도 validation 12판으로 검사했습니다. 개발 4판의 차이로 실제 우위가 증명된 것은 아니며, 대조군보다 낫다는 근거도 없는 탐색적 확인입니다.

| validation 배치 | resource 성적 |
| --- | --- |
| 일반 6판 | 2승 4패 |
| 미로 6판 | 4승 2패 |
| 합계 | 6승 6패 |

전술 16/16과 시간 기준은 통과했지만 전체 양의 승패 차와 일반 배치 비퇴행 기준을 통과하지 못했습니다. 후보를 채택하지 않고 새 holdout 대전은 실행하지 않았습니다. 실전 기본 엔진은 Atlas 5.3입니다. 개발·validation의 총 28판을 기보와 시간 집계까지 재검증했습니다.

## 다음에 먼저 확인할 연결도 문제

가중치 조정 외에 더 구체적인 재현 사례를 확보했습니다. 세로벽 `(5,3)`이 있을 때 가로벽 `(3,4)`을 놓는 합법 배치와 그 좌우 반전에서, 기존 JavaScript `wallConnections`는 각각 1과 0을 반환합니다. 두 물리적 벽 구간은 양쪽 모두 끝점 사이에 한 칸 간격이 있습니다.

Rust 연결도 함수도 같은 교차 앵커 오프셋 목록을 사용합니다. 다만 진단 스크립트에서 직접 측정한 값은 JS 함수이며, 이 자료만으로 Native 대전의 패인까지 입증하지 않습니다. 이전 정렬 후보는 기준 방향 정규화로 반전 결과를 맞췄지만, 연결도 정의 자체가 실제 벽 기하를 반영하는지는 별도 문제입니다. 다음 작업은 이 기본 계산을 독립적인 벽 구간 기하와 대조하는 것이 우선입니다.

- [합법 배치·반전·실제 반환값·물리 구간·소스 해시](search56/connection-geometry.json)

```powershell
node scripts/inspect-wall-geometry.mjs reports/search56/new-geometry-diagnostic.json
```

이번 진단은 기존 연결도 함수를 수정하지 않습니다. Rust 테스트 19개, 앱 테스트 68개와 빌드를 통과했고, 기존 Atlas 5.3의 승인 해시와 종반 진단도 유지됩니다.

## 실행

```powershell
npm run maze:build
npm run maze:compare-search -- reports/search56/my-comparison --searches legacy,ordering,threat,resource --cohort search56-v1
node scripts/verify-search.mjs reports/search56/my-comparison
```

네 모드는 같은 `cache4` 평가, 같은 일반·미로 시작 배치, 수당 500ms·4코어·최대 180수로 기존 Atlas 5.3과 대전합니다. 각 배치에서 진영을 교환합니다. 탐색 모드와 배치군을 보고서에 기록하고 다른 모드·배치군의 결과를 섞어 채택하지 않습니다.

```powershell
npm run maze:evaluate -- --out reports/search56/my-validation --mode cache4 --search resource --cohort search56-v1 --split validation --pairs 3
```

현재 평가 명령의 기본 배치군은 `search56-v1`입니다. 예전 결과는 기록된 소스·바이너리 해시의 역사적 자료입니다. 이전 v3 결과를 정확히 재검증하려면 해당 커밋의 소스를 사용해야 합니다.

## 남은 추천 우선순위

1. 연결도 계산을 실제 벽 구간·좌우 대칭과 대조하고 잘못된 교차 앵커 판정을 교정.
2. 기준 방향 변환·캐시 조회·깊이 보호 비용을 최적화.
3. 중립 벽의 장기 이득과 자원 소모를 새 자료로 검증하고 통과한 후보만 채택.
4. 위협 평가·경로·병렬 탐색 효율 추가 개선.
5. 강해진 엔진으로 지도 자료와 신경망 학습 재검토.
