# 연결 벽과 방어 벽 가치 평가 실험

신경망 학습 없이 Atlas 5.3의 평가 함수를 보강하는 별도 Rust 엔진을 만들었습니다. 기존 Native/WASM 코드와 바이너리는 보존하고 `experimental-engine`에 후보를 빌드합니다. 이번 후보의 이름은 `Atlas 5.4 experiment`입니다. 실전 채택에는 별도의 검증·holdout 통과가 필요합니다.

## 바꾼 판단

기존 평가는 목표선까지의 모든 최단 경로에서 벽 자리를 찾은 뒤 연결도를 크게 반영해 상위 4개만 실제 우회 거리로 평가합니다. 연결도가 낮아도 여러 최단 경로를 가로막는 벽이 이 표본에서 빠질 수 있습니다.

후보는 벽이 8개 이상 놓인 배치에서 다음을 바꿉니다.

1. 기존 상위 4개를 반드시 유지합니다. 이어 최단 경로 간선을 많이 가로막는 후보를 추가해 최대 8개를 평가합니다.
2. 벽마다 목표선에서 역방향 BFS로 만든 거리 지도를 캐시합니다. 말 위치가 바뀌어도 같은 벽 배치의 지도를 공유해 자기·상대 우회 거리와 경로가 막히는 불법 설치 여부를 계산합니다.
3. 상대가 도착까지 4칸 이내일 때 남은 방어 벽의 자원 가치를 최대 48점 더 높입니다. 마지막 벽을 소모하면 이 보너스도 사라집니다. 벽 설치에 쓰는 한 차례의 비용은 위협 이득에서 계속 차감합니다.

한 벽의 위협 표본을 넓힌 휴리스틱입니다. 모든 벽 조합을 완전 탐색하거나 두 벽 함정 전체를 해결한 것은 아닙니다. 벽 8개 미만의 평가, 합법 수, 검색 알고리즘, 병렬 처리, 정확한 종반 계산은 그대로 재사용합니다. 고정된 상위 후보만 실제 검색하는 변경도 아닙니다. 모든 합법 수는 기존 검색에 남습니다.

후보가 평가하는 단일 벽 위협은 기존 4개 표본보다 작아지지 않고, 모든 합법 벽을 검사한 상한을 넘지 않는지 재현 배치에서 확인했습니다. 위협을 키우는 것이 평가와 실제 실력을 항상 개선한다는 의미는 아닙니다.

## 분리된 빌드

```powershell
npm run maze:build
```

후보 crate는 기존 보드 규칙·검색·종반 소스를 포함해 사용하고, 빌드 단계에서 기존 정적 평가 함수에 다른 이름을 부여한 후 후보 평가를 연결합니다. 기반 소스의 예상 연결 지점이 달라지면 빌드를 실패시킵니다. 원본 파일을 수정하거나 복제된 검색 전체를 따로 유지하지 않습니다. Cargo 의존성은 lock 파일로 고정합니다.

출력은 `experimental-engine/target/release/`에 있으며 Git에는 포함하지 않습니다. 소스·기반 엔진·바이너리 해시는 빌드 manifest와 평가 보고서에 기록합니다. 실전 Atlas 5.3의 소스 해시와 기존 승인 기록은 유효하게 유지됩니다.

## 비교 실행

```powershell
npm run maze:evaluate -- --out reports/maze-candidate/my-development
node scripts/review-maze.mjs --out reports/maze-candidate/my-review
node scripts/verify-maze.mjs reports/maze-candidate/my-development --save
```

기본 대전은 수당 500ms·4코어, 일반·미로 각각 2배치의 진영 교환 8판입니다. 상대는 기존 Atlas 5.3 `candidate` 프로필이며, 더 오래된 Atlas 5 기준 엔진이 아닙니다. 서로 다른 바이너리·프로세스를 사용하며 게임마다 초기화합니다. 전술 16문제, 수별 시간·깊이·노드 수·전체 기보를 저장합니다. 3회 반복과 수 제한은 평가용 무승부입니다.

`--split validation --pairs 3`은 12판, `--split holdout --pairs 4`는 16판입니다. 기본 수 제한은 180수이며 실전 채택 기준도 이 이상을 요구합니다. 개발 대전만을 근거로 기본 엔진을 바꾸지 않습니다. 검증·holdout에서 모두 양의 승패 차, 일반·미로 각각 비퇴행, 전술 16/16, 시간 초과 비율 5% 미만 등의 기준을 확인합니다. 작은 표본의 운영 기준이며 인간 상대 강도나 통계적으로 결정적인 우위를 인증하지 않습니다.

검증 명령은 모델·소스·바이너리 해시, 기보의 합법성, 시작 배치, 차례·행동·수별 시간, 승패와 집계를 다시 확인합니다. 보고서를 읽는 것만으로 엔진을 자동 승격시키지 않습니다.

## 개발 결과와 재현 배치

일반·미로 각 2배치, 수 제한 120수의 개발 대전 8판에서 후보는 **5승 3패**였습니다. 일반은 3승 1패, 미로는 2승 2패였습니다. 전술 16/16을 통과했고 양쪽 모두 허용 시간 초과는 0개였습니다. 이 결과만으로 후보가 미로에서 더 강하다고 말할 수 없습니다.

기존에 선택 차이가 난 재현 배치 4개를 500ms로 다시 검사했습니다. 평균 완료 깊이는 기준 엔진 6.75, 후보 6.25였고 총 노드 수는 각각 533,307과 525,790이었습니다. 기존 3초 검색의 참고 수와 일치한 배치는 양쪽 모두 1개였습니다. 계산 비용으로 깊이가 낮아지는 단점도 확인됐습니다. 긴 검색의 수와 일치하도록 맞추는 것은 강도 검증을 대체하지 않습니다.

## 추가 검증과 채택 보류

개발 대전 뒤 별도 validation 배치 12판을 500ms·4코어·최대 180수로 실행했습니다.

| 배치 | 후보 성적 |
| --- | --- |
| 일반 6판 | 5승 1패 |
| 미로 6판 | 2승 4패 |
| 합계 | 7승 5패 |

전술 16/16을 통과했고 양쪽 시간 초과는 0개였습니다. 전체 승패는 양수지만 미로에서 퇴행했으므로 후보를 채택하지 않았습니다. holdout은 열지 않았으며 실전 기본 엔진은 Atlas 5.3입니다. 이 후보를 강해진 엔진이라고 주장하지 않습니다. 서로 다른 평가 자료에서 나온 5승 3패와 7승 5패를 독립적인 실력 인증처럼 합산하지 않습니다.

모든 20판의 기보·차례·승패·시간 집계를 독립 규칙으로 재검증했습니다. Rust 테스트 15개, 앱 테스트 67개, 빌드를 통과했고 이전 12개 약점 배치의 해시·종반 검증도 계속 통과합니다.

- [validation 재검증](maze-candidate/validation-v1/verification.json)

이번 결과는 위협 후보를 늘리는 것과 방어 벽 자원 보너스를 함께 바꾼 결과입니다. 두 변경 중 무엇이 효과·퇴행을 일으켰는지 분리해서 입증하지는 못했습니다. 다음에는 계산량과 평가 항목을 분리해 비교하고, 늘어난 위협 정보를 수 정렬·심화에 활용하는 방법부터 확인하는 것이 좋습니다.

## 남은 추천 우선순위

1. 평가 비용을 줄이면서 중요한 벽 위협을 보존하고, 위험한 벽 분기의 수 정렬·선택적 심화 개선.
2. 동일 시간의 검증·별도 미사용 배치 대전으로 실제 향상을 확인하고 통과한 후보만 채택.
3. 경로 계산·캐시·병렬 탐색 효율을 추가 개선.
4. 충분히 강해진 엔진으로 지도 자료를 만들고 신경망 학습 재검토.
