# 중반 경로 방어와 실제 응수 연결

기존 쿼리도 0.4는 현재 거리 이득과 제한된 두 벽 위험을 비교했지만, 유리하다고 가정한 방어가 실제 다음 수의 비교에서 빠지거나 긴 우회를 충분히 반영하지 못했다. 이번 변경은 후보마다 `내 행동 → 상대 공격 → 내 대응 → 상대 후속 수`를 함께 평가하고, 실제 진행이 예상과 맞으면 이전에 가정한 대응을 다시 비교한다. 해당 응수를 강제로 두거나 특정 기보의 정답을 지정하지 않는다.

## 구현

- 원본 기보의 현재 대국만 사용해 13·15·17수 직전 배치를 evaluation/fixtures/midgame-defense-game4.json에 보존했다. 진영·잔여 벽·실제 연속 설치 횟수도 포함한다. 최초의 필패점이라고 단정하지 않는다.
- 벽이 4개 이상 설치됐고 상대 벽이 남았으면 새 비교를 활성화한다. 그 이전과 상대 벽이 없는 경우는 기존 평가를 사용해 단순 배치의 추가 비용을 피한다.
- 모든 합법 말 이동, 우선 방어벽 최대 6개, 강한 공격벽 최대 2개, 위협 벽의 합법 교차 선점 후보를 비교한다. 방어 순위에는 연결 지점 차단, 현재 경로 길이와 전진 방향 수를 반영한다. 전진 방향 수는 독립 탈출 경로 개수의 증명이 아니다.
- 상대는 유망한 벽과 전진 수를 선택한다. 내 대응은 모든 합법 말 이동과 상위 방어벽 4개다. 후속 공격은 일반 벽 최대 3개와 첫 벽에 연결되는 벽 최대 3개를 합치며 합법 말 이동도 포함한다. 연결 후보가 일반 후보의 잘림 때문에 사라지지 않도록 합집합으로 유지한다.
- 상대는 피해를 크게, 나는 피해를 작게 하는 응수를 선택한다. 완성된 진행의 거리 차 변화에 양측 소비 턴을 보정한다. 위험은 최대 8의 휴리스틱 값이다. 벽 재고는 실제 make에서 차감하고 양쪽 경로가 남는 합법 후보만 사용한다.
- 위험 변화는 기존 거리 평가와 같은 120점 단위로 반영한다. 전진 방향 변화에는 12점을 사용하며 최종 추가 보정은 ±240점으로 제한한다. 기본 탐색의 전략 점수를 무조건 덮어쓰지 않는다.
- 새 비교가 완료되면 이전 연결 위험의 루트 보정을 중복 적용하지 않는다. 기존 벽 보존·약한 벽 소비 비용은 유지한다. 시간 초과·취소로 완료하지 못하면 새 비교의 부분 보정은 전부 버리고 이전 평가로 복귀한다.
- 추가 시간은 남은 예산의 20% 이내, 일반적으로 최대 80ms다. 남은 예산이 1.5초보다 길면 최대 120ms다. 배치별 거리 지도 재사용을 유지한다.
- 위험이 크거나 피해를 줄이는 검토 후보는 루트의 늦은 수 감소를 면제한다. 내부 모든 분기를 완전 탐색하는 것은 아니다. 메이트 점수와 기존 완전 승리 전략 처리는 변경하지 않는다.

## 실제 대응과 연결

화면·수동·관전의 다음 분석에서 최근 실제 두 수와 이전 추천의 예상 공격을 대조한다. 내 실제 수와 상대 실제 수가 모두 맞고, 지금도 합법인 대응만 추가 후보로 전달한다. 상대가 다르게 두거나 엔진이 달라지면 전달하지 않는다. Native 진입점은 입력을 별도로 검증하고 매 요청 선호 후보를 초기화한다.

이전 대응은 가산점으로 강요하지 않는다. 검토 후보에 넣고 루트 깊이 감소를 면제하며, 검토 여부를 기록한다. 더 좋은 대응으로 바꾸거나 이전 가정을 버릴 수 있다. 재동기화로 이전 실제 두 수를 알 수 없으면 추측하지 않는다.

## 표시와 기보

threatDefense에 선택 수의 잔여 위험, 예상 경로 증가, 상대 공격·내 대응·상대 후속 수, 이전 가정의 검토 여부와 계산 시간을 기록한다. 선택 수가 검토 밖이거나 계산이 미완료면 '지금 착수 가능' 안내를 하지 않는다. 새 비교가 유효하면 이전 연결 위험 문단 대신 실제 응수선을 표시한다. 위험이 남으면 추천 안정도와 별도로 경로 취약 가능성을 알린다.

## 제한적 확인 결과

Rust 릴리스·웹 빌드, 실제 서비스 빌드 일치를 확인한다. 사용자의 기존 요청에 따라 전체 테스트·긴 대전·브라우저 시각 검증은 실행하지 않았다. 별도 새 프로세스에서 동일한 4코어·0.5초와 2초로 확인했으며 대국의 누적 탐색 이력은 재현하지 않았다.

|위치|기존 0.5초|변경 후 0.5초|변경 후 2초|
|---|---|---|---|
|13수|e4 이동|e4 이동|e4 이동|
|15수|h6 가로벽|e3 이동|h6 가로벽|
|17수|f6 가로벽|f6 가로벽|f6 가로벽|

- 세 위치 모두 검토가 완료됐고 선택 수도 검토 목록에 있었다. 추가 비교는 관측 약 36~45ms, 후보 13~14개였다. 0.5초 검색은 세 위치 모두 깊이 4, 2초는 깊이 5까지 완료했다. 전체 엔진 속도의 향상을 주장하지 않는다.
- 13수의 예상 공격 c5 세로벽과 후속 c3 세로벽을 함께 포착했다. 현재 모델은 그 사이 대응으로 e3 이동을 가정한다. 실제 공격이 c5 세로벽이었을 때 다음 분석으로 해당 대응이 전달되고 재검토됐다. 상대 수·엔진이 바뀐 대조에서는 전달되지 않았다.
- 15수의 c3 가로벽은 제한 비교에서 잔여 위험 2, 기존 h6 가로벽은 4였다. c3 가로벽은 후보에 포함됐지만 기본 탐색과 합친 최종 추천에는 선택되지 않았다. 순수 위험 최소화와 장기 탐색 평가 사이의 충돌이 남는다. 낮은 위험 추정이 실제로 더 좋은 수라는 증명도 없다.
- 보조로 7·11수도 확인했으며 추천은 유지됐다. 7수는 추가 비교 비활성, 11수는 활성이다. 더 이른 원인까지 해결됐다는 근거는 없다.
- 실제 가변 흐름의 첫 표시는 약 0.513초였다. 위험이 남은 경우 대기 권장 상태를 유지했으며 1.2초에서 수동 취소한 흐름에 오류가 없었다.

이 변경으로 이번 패배가 해결됐거나 실전 승률이 높아졌다고 결론 내리지 않는다. 선택적 공격·방어 생략은 위험의 과소/과대평가를 만들 수 있고, 완전 게임의 최선 수 또는 승패 증명이 아니다. 중반 전체 전략을 근본적으로 해결한 것도 아니다.

자료: comparison.json은 전후 검색, candidate-review.json은 후보별 응수 비교, flow.json은 가변 흐름, handoff-guards.json은 실제 수 일치 조건, upstream-context.json은 앞선 배치 관측이다. 다음 우선순위는 낮은 위험으로 추정한 방어안과 기본 탐색의 평가가 충돌하는 이유를 더 긴 대응선으로 검증하는 것이다.
