# 실제 벽 기하에 따른 연결도 교정

기존 연결도 계산은 좌우 반전한 합법 배치에서 1과 0을 반환했습니다. 이번에는 벽을 실제 선분으로 나타내고 접촉 관계를 계산하는 별도 Native 후보를 구현했습니다. 기존 Atlas 5.3과 WASM·JavaScript 엔진은 비교 기준으로 보존합니다. 후보 이름은 `Atlas 5.7 experiment`입니다.

## 무엇을 연결로 세는가

가로벽 `(x,y)`는 격자 경계 좌표에서 `(x,y+1)`부터 `(x+2,y+1)`까지, 세로벽은 `(x+1,y)`부터 `(x+1,y+2)`까지의 선분입니다. 연결도는 접촉하는 기존 벽의 개수를 뜻합니다.

- 같은 방향의 끝점 연결, 서로 다른 방향의 L자·T자 접촉을 셉니다.
- 간격이 있는 벽, 겹친 선분, 두 선분의 내부 교차는 연결로 세지 않습니다.
- 후보 벽 자신은 세지 않습니다. 보드 외곽선은 벽 개수에 포함하지 않습니다.
- 한 기존 벽은 한 번만 셉니다. 같은 접점에 여러 벽이 있으면 각 기존 벽을 셉니다.

128개 벽 자리의 접촉 관계를 컴파일 시점의 비트 마스크로 만듭니다. 실행 중에는 설치된 벽 비트와 교집합을 구해 개수를 셉니다. 벽마다 모든 기존 벽을 순회하는 추가 계산을 넣지 않습니다. 이것만으로 전체 탐색이 빨라졌다고 주장하지는 않습니다.

## 독립적인 전수 대조

실제로 컴파일한 Rust 함수의 반환값을, 오프셋 목록을 사용하지 않는 JavaScript 선분·끝점 계산과 대조했습니다.

| 검사 | 결과 |
| --- | ---: |
| 전체 순서 있는 벽 쌍 | 16,384개 일치 |
| 그중 합법적인 두 벽 조합 | 15,904개 |
| 기존 계산과 새 정의가 다른 전체 쌍 | 1,036개 |
| 합법 조합 중 달라진 쌍 | 908개 |
| 기존 계산의 좌우 반전 불일치 | 376개 |
| 새 계산의 좌우 반전 불일치 | 0개 |
| 기존 JS·Rust 구현 사이 불일치 | 0개 |

기존에 발견한 가로벽 `(3,4)`와 세로벽 `(5,3)`의 예는 끝점 사이에 한 칸의 틈이 있습니다. 기존 값은 반전 전후 1·0이었지만, 새 값은 Rust 실제 호출에서도 0·0입니다. 모든 쌍에서 순서 교환, 좌우 반전, 90도 회전 성질을 검사했습니다. 쌍별 결과를 비트 합으로 세므로 임의의 벽 집합에서도 같은 접촉 정의를 적용합니다.

- [독립 계산·실제 Rust 호출·바이너리 해시 검증](geometry57/contact-proof-checked.json)

## 엔진 연결과 대전 조건

`--geometry legacy`는 기존 연결도, `--geometry physical`은 교정한 연결도를 사용합니다. 임시 진단 함수에만 적용한 것이 아니라 정적 평가의 위협 후보 순위, 수 정렬, 기존 연결 벽 깊이 보호가 호출하는 실제 `Position::connections`에 연결했습니다. 빌드 시 원본 규칙 파일을 복사한 출력에서 기존 함수만 이름을 바꾸고 새 함수를 연결합니다. 원본 엔진 파일은 수정하지 않습니다.

대전에서는 평가 모드 `cache4`, 탐색 모드 `legacy`를 고정합니다. 이전에 탈락한 방어·자원 보정이나 추가 깊이 보호를 함께 적용하지 않습니다. 같은 바이너리에서 연결도만 바꾼 대조군과 후보를 각각 고정된 기존 Atlas 5.3과 비교합니다.

새 `search57-v1`의 개발·validation·holdout 시드는 713821, 468793, 182537입니다. 이전 Native v3, search55·search56 및 새 분리 사이의 중복을 제외합니다. 평가 자료는 사용 후 다음 튜닝에서 미사용으로 재사용하지 않습니다.

## 실제 대전 결과와 채택 보류

새 개발 배치의 일반·미로 각 1개에서 진영을 교환한 4판씩의 결과는 기존 연결도 2승 2패, 교정 연결도 1승 3패였습니다. 표본이 작아 개발 비교만으로 결론 내리지 않고 교정 후보를 별도 validation 12판으로 검사했습니다.

| validation 배치 | 교정 후보 성적 |
| --- | --- |
| 일반 6판 | 3승 3패 |
| 미로 6판 | 3승 3패 |
| 합계 | 6승 6패 |

전술 16/16과 시간 기준을 통과했고 배치별 승패 차는 음수가 아니었지만, 사전에 정한 전체 양의 승패 차 기준을 통과하지 못했습니다. 실전 채택을 보류하고 새 holdout 대전은 실행하지 않았습니다. 실전 기본값은 Atlas 5.3입니다.

기하 정의의 교정은 실험 엔진의 실제 평가·탐색 경로에 적용됐지만, 더 강한 게임 엔진으로 배포한 것은 아닙니다. 기존 연결도에 맞춰진 평가 가중치·위협 후보 선택까지 동일하게 최적이라는 의미는 아니므로 다음에는 정렬에만 쓰는 경우와 평가까지 쓰는 경우를 분리해야 합니다.

- [개발 8판 비교](geometry57/comparison.json)
- [개발 기보·시간 재검증](geometry57/verification.json)
- [validation 12판](geometry57/physical-validation/report.json)
- [validation 재검증](geometry57/physical-validation/verification.json)
- [채택 보류·holdout 보존 기록](geometry57/decision.json)

Rust 테스트 21개를 기존·교정 연결도 모드에서 모두 통과했습니다. 앱 테스트 69개, 빌드, 20판 기보·시간 검증과 기존 Atlas 5.3의 종반 진단도 통과했습니다. 좌우 반전 불일치는 실제 컴파일한 기존 Rust 함수에서도 확인했으며, 새 함수가 독립 선분 계산과 일치하는 것을 대전 강도와 구분해 기록했습니다.

## 실행

```powershell
npm run maze:build
npm run maze:check-geometry -- reports/geometry57/my-contact-proof.json
npm run maze:compare-geometry -- reports/geometry57/my-comparison
node scripts/verify-geometry.mjs reports/geometry57/my-comparison
```

새 출력 경로를 지정합니다. 전수 대조는 실제 Rust 실행 파일을 호출하며, 그림만으로 접촉을 추정하지 않습니다. 대전은 500ms·4코어·최대 180수로 일반·미로 각 한 배치의 진영을 교환합니다.

```powershell
npm run maze:evaluate -- --out reports/geometry57/my-validation --mode cache4 --search legacy --geometry physical --cohort search57-v1 --split validation --pairs 3
```

현재 대전 보고서는 연결도 모드를 명시한 v4입니다. validation과 holdout의 연결도 모드가 다르면 채택 기준을 통과하지 못합니다. 과거 v1~v3 결과는 당시 소스·바이너리 해시의 기록으로 보존합니다.

## 남은 추천 우선순위

1. 교정 연결도를 수 정렬에만 쓰는 경우와 평가·위협 후보 선택까지 쓰는 경우를 분리 검증.
2. 새 연결도에 맞는 가중치·위협 후보 순위와 계산 비용 조정.
3. 정렬·캐시·깊이 보호 최적화 후 새 미사용 배치에서 통과한 후보만 채택.
4. 경로·병렬 탐색 개선과 외부 강도 검증.
5. 강해진 엔진으로 신경망 지도 자료·학습 재검토.
