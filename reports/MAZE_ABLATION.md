# 벽 평가 항목 분리와 비용 측정

이 문서는 `0ffb2b7` 시점의 실제 v2 결과입니다. 이후 [수 정렬·깊이 보호 실험](SEARCH_ORDERING.md)에서 탐색 모드와 새 배치군을 명시한 v3 보고서가 추가됐습니다. 아래 과거 결과의 해시 재검증에는 당시 소스를 사용하며, 현재 명령은 새 v3 결과를 생성·검증합니다.

이전 후보는 벽 위협 확대와 방어 벽 보너스를 함께 바꿔 미로에서 2승 4패로 퇴행했습니다. 이번에는 두 항목을 분리하고, 기존 점수를 유지하는 계산 최적화를 별도로 비교합니다. 실전 기본 엔진은 Atlas 5.3입니다.

## 실행 모드

| 모드 | 위협 후보 | 방어 벽 보너스 | 용도 |
| --- | ---: | --- | --- |
| baseline | 기존 4개, 기존 계산 | 없음 | 평가 함수 비용 기준 |
| cache4 | 기존 4개, 캐시 계산 | 없음 | 점수 유지 최적화 후보 |
| reserve | 기존 4개, 캐시 계산 | 있음 | 방어 보너스 효과 분리 |
| coverage8 | 확대 8개, 캐시 계산 | 없음 | 후보 확대 효과 분리 |
| combined8 | 확대 8개, 캐시 계산 | 있음 | 두 평가 변경 결합 |
| reference8 | 이전 정렬 구현의 8개 | 있음 | 이전 복합 평가와 점수·비용 대조 |

실험 엔진의 기본값은 `cache4`입니다. `--mode`로 지정한 값은 해당 평가 프로세스의 환경에만 전달하며 기존 Atlas 5.3 바이너리는 이 값을 사용하지 않습니다. 같은 바이너리라도 모드가 다른 validation과 holdout을 섞으면 채택 기준을 통과하지 못합니다. 게임 화면에는 별도 모드를 추가하지 않았습니다.

## 계산 변경과 정확성

캐시 경로는 벽 배치별 역방향 거리 지도를 재사용합니다. 경로 탐색 큐를 고정 크기 배열로 바꾸고 같은 벽의 연결도를 한 번만 계산합니다. 후보 수가 작다는 점을 이용해 전체 정렬 대신 제한된 개수의 후보를 선형 선택합니다. 기존 순위와 동률 처리 순서를 유지합니다.

패배 6판을 합법적으로 재생해 얻은 167개 상태에서 다음을 확인했습니다.

- `cache4` 점수와 기존 평가 점수가 모두 일치합니다.
- `combined8` 점수와 이전 복합 평가 `reference8` 점수가 모두 일치합니다.
- Rust 테스트에서도 배치별 말 이동을 이어가며 점수 일치, 보드·해시 복원, 확대 표본의 하한·상한을 확인합니다.

이는 검사한 상태에서의 동등성 확인입니다. 시간 제한 검색의 첫 수와 승패까지 같아진다는 의미는 아닙니다. 계산 속도가 달라지면 완료 깊이·병렬 처리 순서와 선택이 달라질 수 있습니다.

## 미세 측정

각 모드에서 동일한 167개 상태를 처음 평가하고, 캐시를 재사용하며 50회 반복했습니다. 이를 3번 측정했습니다. 아래는 반복 평가 시간의 중앙값이며 각 행은 총 8,350회 평가입니다.

| 모드 | 반복 평가 시간 |
| --- | ---: |
| baseline | 98.016ms |
| cache4 | 60.741ms |
| reserve | 57.332ms |
| coverage8 | 83.496ms |
| combined8 | 80.417ms |
| reference8 | 69.207ms |

`cache4`의 반복 평가 시간은 약 38.0% 감소했습니다. 반면 새 8개 선형 선택 경로는 이전 정렬 구현보다 약 16.2% 느렸습니다. 정렬을 없앴다는 사실만으로 빨라졌다고 결론 내리지 않습니다. 8개 확장은 평가 품질뿐 아니라 구현 비용도 재검토해야 합니다.

반복 상태로 캐시가 잘 재사용되는 측정이며 실행 순서는 고정됐고 표본은 3회입니다. 표의 작은 차이를 모드 간의 확정적 속도 우위로 해석하지 않습니다. 전체 게임이나 0.5초 검색이 38% 빨라졌다는 뜻도 아닙니다. 실제 대전은 별도로 측정합니다.

## 항목별 실제 대전

동일한 일반·미로 개발 배치 각 1개에서 진영을 교환해 모드마다 4판씩, 총 16판을 500ms·4코어·최대 180수로 실행했습니다. 상대는 고정된 기존 Atlas 5.3입니다.

| 모드 | 일반 2판 | 미로 2판 | 합계 |
| --- | --- | --- | --- |
| cache4 | 2승 | 1승 1패 | 3승 1패 |
| reserve | 1승 1패 | 1승 1패 | 2승 2패 |
| coverage8 | 1승 1패 | 1승 1패 | 2승 2패 |
| combined8 | 1승 1패 | 1승 1패 | 2승 2패 |

각 모드는 전술 문제 16/16을 통과했습니다. 표본이 작고 같은 시작 배치를 반복했으므로 방어 보너스나 위협 확대의 일반적인 유불리를 단정하지 않습니다. 캐시만 바꾸면 기존 복합 후보와 비교해 무엇을 제거했는지가 명확해졌고, 추가 평가 항목이 이 작은 시험에서 우위를 더하지 않았다는 결과를 남깁니다.

- [전체 분리 비교와 측정 원자료](maze-ablation/v2/report.json)
- [167개 점수·16판 기보 재검증](maze-ablation/v2/verification.json)

## 캐시 단독 후보의 추가 검증

평가 점수가 유지되고 비용이 감소한 `cache4`를 별도 validation 12판으로 검사했습니다. 동일한 500ms·4코어·최대 180수에서 일반 4승 2패, 미로 3승 3패, 합계 7승 5패였습니다. 전술 16/16을 통과했고 미로 퇴행은 없었습니다. 단순히 개발 4판에서 가장 많이 이겼다는 이유로 선택한 것이 아니라, 점수 동등성과 비용 감소가 확인된 경로를 다음 검사 대상으로 삼았습니다.

- [캐시 단독 validation 12판](maze-ablation/cache4-validation/report.json)
- [validation 재검증](maze-ablation/cache4-validation/verification.json)

이후 별도로 보관했던 v3 holdout 16판을 같은 조건으로 실행했습니다. 일반 4승 4패, 미로 4승 4패, 합계 **8승 8패**였습니다. validation과 holdout 모두 전술 16/16, 시간 초과 비율 기준을 통과했습니다. 하지만 사전에 정한 holdout 양의 승패 차 기준을 통과하지 못해 실전 반영을 보류했습니다. 기준을 사후에 무승부 허용으로 바꾸지 않았습니다. 이 holdout은 이제 해당 후보의 평가에 사용된 자료이므로 다음 튜닝에서 새로운 미사용 시드가 필요합니다.

- [별도 배치 16판과 수별 시간](maze-ablation/cache4-holdout/report.json)
- [별도 배치 재검증](maze-ablation/cache4-holdout/verification.json)
- [두 보고서에 연결된 최종 채택 보류 기록](maze-ablation/cache4-decision.json)

같은 재현 배치 4개를 500ms로 다시 검사했을 때 기준과 후보의 평균 완료 깊이는 모두 6이었고, 총 검색 노드는 각각 387,917개와 398,869개였습니다. 캐시 후보의 노드 수가 약 2.8% 많았지만 작은 고정 배치의 측정이며 일반적인 속도·실력 향상을 입증하지 않습니다. [재현 배치 검색 기록](maze-ablation/cache4-review/report.json)에 원자료를 보관했습니다.

실전 기본값은 Atlas 5.3입니다. 이번 작업은 평가 항목을 분리하고 비용을 줄이는 경로를 확보한 결과이며, 더 강한 실전 엔진을 배포한 결과가 아닙니다. 개발 16판·validation 12판·holdout 16판의 총 44판을 기보와 시간 집계까지 검증했습니다. Rust 테스트 16개, 앱 테스트 67개와 빌드를 통과했습니다.

## 재실행과 검증

```powershell
npm run maze:build
npm run maze:ablate -- --out reports/maze-ablation/my-run --pairs 1 --ms 500
node scripts/verify-ablation.mjs reports/maze-ablation/my-run
```

마지막 명령은 완료된 측정 3회, 모드별 점수·체크섬 일치, 입력·코드·바이너리 해시, 대전 보고서와 기보·시간 집계를 다시 확인합니다. 새 출력 폴더를 사용합니다. `--resume`은 완료된 단계를 이어가며, 일부만 저장된 대전이 있다면 이를 보존하고 새 출력 폴더에서 시작합니다.

개별 모드를 실행할 수도 있습니다.

```powershell
npm run maze:evaluate -- --out reports/maze-candidate/cache-only --mode cache4 --split development --pairs 2
```

validation과 holdout을 모두 실행한 뒤에는 다음 명령으로 두 보고서를 재검증하고 채택 여부를 기록합니다. 마지막 인자는 새 파일이어야 합니다. 이 명령 자체가 실전 엔진을 교체하지는 않습니다.

```powershell
npm run maze:assess -- reports/maze-ablation/cache4-validation reports/maze-ablation/cache4-holdout reports/maze-ablation/new-decision.json
```

이전 v1 결과는 당시 소스와 바이너리를 기록한 역사적 자료입니다. 현재 검증기는 모드를 명시한 v2 결과를 요구하며, v1 재검증에는 `414a47a` 시점의 소스를 사용해야 합니다.

## 남은 추천 우선순위

1. 위험한 벽 분기의 수 정렬·선택적 심화로 중요한 수를 먼저 깊게 탐색.
2. 8개 평가의 추가 비용을 줄이고 탐색 순서에 위협 정보를 활용하는 방식 비교.
3. 새로운 미사용 배치에서 후보를 재검증하고 통과한 변경만 실전 채택.
4. 충분히 강해진 엔진으로 지도 자료 품질과 신경망 학습 재검토.
