# 화면 가져오기: 연결·영역 지정·배치 검토

2026-10-29. **오른쪽 게임 화면 또는 이미지에서 말·벽을 읽고, 검토한 배치를 왼쪽 보드에 적용하는 첫 단계를 구현했습니다.** 적용 후 기존 ‘최선 수 분석’ 버튼으로 추천을 볼 수 있습니다. 이번 단계는 수동 프레임 가져오기이며 실시간 자동 동기화·자동 차례 판독·자동 착수는 포함하지 않습니다.

## 사용 순서

1. 실행 중인 앱을 새로고침하고 **모드 → 화면 가져오기 · 수동 확인**을 선택합니다.
2. **오른쪽 게임 화면 연결**에서 게임 탭/창을 고르거나, **이미지 가져오기**로 PNG·JPG·WebP를 엽니다. 공유는 연결 버튼을 눌렀을 때만 요청합니다. 브라우저의 공유 대상 선택은 사용자가 직접 해야 합니다.
3. 실제 말·벽만 보이도록 원본 보드에서 마우스를 빼고 **현재 프레임 고정**을 누릅니다. 공유를 유지한 채 나중에 다시 고정할 수 있습니다.
4. 숫자·글자·바깥 테두리를 제외하고, 첫 칸의 왼쪽 위에서 마지막 칸의 오른쪽 아래까지 드래그합니다. 격자선이 9×9 칸과 맞는지 보고 필요하면 **칸 사이 간격**을 조절합니다.
5. **선택 영역 인식**을 누릅니다. 오른쪽 검토 보드의 두 말과 모든 벽을 원본과 비교합니다. 클릭 보정 도구로 말 위치·벽 색과 방향을 고치거나 벽 목록에서 삭제할 수 있습니다.
6. **원본 아래쪽 출발 진영**, **현재 차례**, **잔여 벽 수**를 확인합니다. 잔여 수의 초기 값은 읽은 설치 벽 색으로 추정한 값이며 원본 숫자를 OCR로 읽은 것이 아닙니다.
7. **확인한 배치를 왼쪽에 적용**합니다. 그 후 **최선 수 분석**을 누르면 현재 차례의 추천 이동/벽과 예상 진행을 표시합니다.

말이 없거나 같은 칸에 겹침, 벽 겹침·교차·목표 경로 차단, 소유자별 벽 수 불일치가 있으면 적용 버튼을 막습니다. 유효한 배치라는 검사와 원본 화면을 정확히 읽었다는 보장은 다르므로 적용 전에 직접 비교해야 합니다.

브라우저 화면 공유는 사용자 동작과 대상 선택을 요구합니다. 연결 허용을 앱이 영구 저장해 자동 시작하지 않습니다. [MDN 화면 캡처 문서](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)를 참고하세요.

## 현재 지원 범위

- 어두운 보드의 **청록·분홍 말과 벽**을 색상·형태로 판독합니다. 단색 말과 색 테두리의 링 형태를 검사했습니다.
- 작은 이동 점과 말은 크기·영역으로 구분합니다. 중립 회색 미리보기는 설치 벽으로 확정하지 않습니다. 색이 있는 설치 전 미리보기는 한 프레임만으로 실제 벽과 구분하지 못할 수 있으므로 커서를 보드 밖으로 옮기세요.
- 벽의 두 칸 구간과 가운데 연결 부분을 함께 확인합니다. 인접한 서로 다른 벽 두 개를 중간의 가짜 벽 하나로 합치지 않도록 했습니다.
- 원본 프레임과 선택 격자 그림을 별도 캔버스에 둡니다. 보정용 격자선이 판독 픽셀에 섞이지 않습니다.
- 원본 아래에 청록 또는 분홍이 시작하는 경우를 내부 좌표로 변환합니다. 적용할 때 왼쪽 보드의 시점을 원본 방향에 맞추며, 출발 진영 설정은 저장·복원합니다.
- 차례는 직접 선택합니다. 벽 소유 색상으로 잔여 수를 추정하되 직접 숫자를 고칠 수 있습니다. 숫자와 설치 벽 수가 다르면 다시 벽을 검토해야 합니다.
- 스크린샷을 대상으로 한 축 정렬 사각 보정입니다. 원근이 있는 카메라 사진·다른 테마·가려진 벽·아바타의 복잡한 색상에 대한 자동 인식 정확도는 보장하지 않습니다.
- 파일은 32MB 이하 PNG/JPG/WebP를 받습니다. 프레임은 긴 변 최대 2048픽셀로 처리하고, 인식 영역은 최소 180×180픽셀로 선택합니다.

화면 모드의 왼쪽 보드는 읽기 전용이며 AI가 자동 착수하지 않습니다. 아직 배치를 확인하지 않았으면 분석도 막습니다. 새 프레임·보정 내용을 가져오면 기존 분석을 취소하고 추천을 지웁니다. 실제 오른쪽 게임의 입력을 대신 보내지 않습니다.

## 저장·불러오기

중간 배치를 처음부터 둔 기보처럼 위조하지 않습니다. 확인한 상태를 `baseState`로 저장하고 그 이후의 수만 별도 기록하는 **세션 형식 3**을 추가했습니다. 기존 형식 1/2의 초기 배치부터 진행하는 기록도 계속 읽습니다.

- 새로고침·JSON 저장/불러오기에 확인한 배치와 출발 방향이 유지됩니다.
- 원본 화면 이미지·화면 공유 권한은 저장하지 않습니다. 화면 공유는 다시 직접 연결해야 합니다.
- 양쪽 직접 조작 등으로 전환해 시뮬레이션하면 그 이후 수를 저장·복원하고 무를 수 있습니다. 기보 색상은 가져온 배치의 실제 선행 차례를 따릅니다.
- 가져오기 전의 실제 대국 기록은 알 수 없으므로 과거 수나 반복 이력을 만들지 않습니다.
- 다른 모드에서 수동으로 진행한 뒤 화면 모드로 돌아오면 ‘수동 진행 상태’라고 표시합니다. 원본과 맞추려면 새 프레임을 확인해 적용하세요.

이미지는 브라우저에서 처리하며 인식용 클라우드나 외부 AI 서비스에 보내지 않습니다. 분석 엔진에는 말·벽·차례 등 보드 상태를 전달합니다. 공유 중지·모드 이탈·페이지 종료에서는 캡처 트랙을 정리합니다. 늦게 도착한 공유 허용 결과도 이미 취소된 요청이면 즉시 닫습니다.

## 검증

- Node 테스트 **108개** 통과, 웹 빌드 통과.
- 독립 비트맵 픽스처로 단색/링 말·이동 점·인접 벽·회색 미리보기를 두 배율에서 확인했습니다.
- 스냅샷의 양쪽 경로, 벽 수, 겹침·교차, 승리 상태, 기존 기보 호환성과 가져온 배치 이후 수의 복원을 검사했습니다.
- 별도 임시 프로필의 headless Chrome에서 **7개 브라우저 시나리오**를 통과했습니다. 이미지 가져오기·드래그 보정·수동 오류 수정·적용 차단·추천 표시·읽기 전용 보드·저장 파일 내용·파일 불러오기·새로고침·무르기·진영 방향 복원·캡처 트랙 정리를 확인했습니다. 처리되지 않은 페이지 오류는 0개였습니다.
- 화면 공유 API 흐름은 자체 캔버스의 **합성 MediaStream**으로 검사했습니다. 실제 Wallz 탭에서 사용자 공유 선택을 거쳐 실전 영상 전체를 검증한 결과는 아닙니다. 그 검증은 다음 단계에 남습니다.

[브라우저 검증 기록](screen-import/browser-qa.json), [인식·보정 화면](screen-import/recognition-review.png), [적용 후 분석 화면](screen-import/applied-board.png)을 참고하세요. 저장된 예시는 사용자 화면이 아닌 자체 합성 테스트 이미지입니다. 브라우저 QA의 분석은 Atlas 3으로 실행했고 실제 앱의 기본 엔진과 선택 설정은 유지했습니다. AI 엔진 알고리즘·모델·승격 상태는 바꾸지 않았습니다.

```powershell
npm test
# 앱을 빌드하고 별도 headless Chrome/Edge에서 검증
npm run screen:qa
```

브라우저 QA는 현재 Node 24 환경에서 검증했습니다. 내장 WebSocket과 로컬 Chrome/Edge가 필요하며 다른 설치 경로는 `SCREEN_QA_CHROME`으로 지정할 수 있습니다. 실제 사용자의 브라우저 프로필에 접속하지 않습니다.

## 남은 추천 우선순위

1. **실시간 프레임 안정화**: 연속 프레임에서 확정된 말·벽만 채택하고 커서 미리보기·애니메이션을 배제합니다.
2. **착수 감지·합법 상태 자동 동기화**: 내 수/상대 수·점프·벽 설치를 추적하고 빠르게 두 수가 지나간 경우도 복원합니다.
3. **차례·잔여 벽 자동 판독과 대조**: 화면 표시와 추적 결과가 일치하는지 확인하고 불확실하면 멈춥니다.
4. **내 차례 자동 분석·추천 갱신**: 확정된 새 상태에서 계산하고 이전 상태의 추천은 취소합니다.
5. **복구·실전 검증**: 재시작·무르기·창 크기/확대·연결 끊김을 처리하고 실제 게임 화면의 다양한 배치로 정확도와 지연을 확인합니다.
