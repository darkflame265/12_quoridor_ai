# 미로 후보 분리와 전술 탐색 보호

이전 5.1 후보는 미사용 미로에서 3승 5패여서 승격하지 않았습니다. 이번에는 정밀 평가의 영향과 탐색 축소 보호의 영향을 분리했습니다. 기존 보고서·기보는 그대로 보존했습니다.

## 분리 비교

이전 미사용 미로는 이제 **개발 자료**로 사용했습니다. 150ms·4코어, 동일한 2개 미로에서 진영을 교환해 각각 4판을 진행했습니다. 보고서의 `split: holdout`, `cohort: v1`은 원래 자료의 이름이며 이번 비교가 새 미사용 검증이라는 뜻은 아닙니다.

| 프로필 | 내용 | 개발 미로 결과 |
|---|---|---:|
| strategy | 미로에서 한 수 벽 위협의 정밀 평가만 사용 | 1승 3패 |
| combined | 정밀 평가와 전술 보호를 함께 사용 | 2승 2패 |
| candidate | 기존의 빠른 평가를 유지하고 전술 보호만 사용 | 3승 1패 |

원자료: [평가만 변경](native52/ablation-strategy/report.json), [둘 다 변경](native52/ablation-combined/report.json), [전술 보호만 변경](native52/ablation-candidate/report.json). 4판씩의 짧은 개발 비교이므로 원인이나 우월성을 확정하지 않습니다. 새 후보 선택을 위한 신호로만 사용했습니다.

## 최종 후보

Atlas 5.2 후보는 **기존 Atlas 5의 정적 평가를 유지**합니다. 정밀 벽 평가는 비교용 프로필에 보관하며 실전 후보의 모든 말단에 추가하지 않습니다. 급한 목표선 방어, 순수 우회 이득이 큰 벽, 마지막 벽을 사용하는 방어 수가 후순위라는 이유로 얕게 읽히지 않도록 합니다. 앞서 만든 공유 캐시와 취소·재탐색도 유지합니다.

기존 규칙·WASM·말 이동 UI·진영 방향은 바꾸지 않습니다. 신경망이나 GPU 학습을 새로 활성화하지 않습니다.

검증과 미사용 배치는 `v2`로 분리했습니다. 시드는 개발 457139, 검증 816713, 미사용 193651입니다. 새 미사용 일반 배치에서는 표준 시작을 제외했고, 이전 미사용 배치 및 새 검증 배치와 겹치지 않는지 테스트합니다. `v1` 배치를 재현하는 기능도 보존했습니다. 서로 다른 세대의 검증·미사용 결과를 섞어 승격하지 못하도록 검사합니다.

조건은 기존과 같은 **500ms·4코어**, 검증 12판·미사용 16판입니다. 일반·미로 각각 비퇴행, 미사용 전체 승수 우세, 전술 16개 통과, 시간 초과 비율 5% 미만과 전체 기보 검사를 요구합니다. 기준을 완화하지 않았습니다.

## 완료 결과와 기본 엔진

| 구분 | 일반 배치 | 벽 미로 | 전체 |
|---|---:|---:|---:|
| 검증 | 4승 2패 | 3승 3패 | 7승 5패 |
| 미사용 배치 | 5승 3패 | 3승 5패 | 8승 8패 |

[검증 원자료](native52/validation/report.json), [미사용 배치 원자료](native52/holdout/report.json). 양쪽 모두 전술 16개를 통과했으며 정한 응답 시간 초과는 없었습니다. 소스 해시가 평가 종료 후에도 일치하고, 모든 대국이 완료됐음을 확인했습니다. Usage 중단 뒤에도 대국 프로세스는 결과를 끝까지 저장했지만 커밋·푸시는 별도로 마무리했습니다.

**후보는 승격하지 않았습니다.** 미사용 전체의 승수 우세와 미로 비퇴행 조건을 통과하지 못했으므로 이 시도의 기본 엔진은 기존 Atlas 5입니다. 개발 비교의 3승 1패가 새 배치의 성능 향상으로 이어지지 않았습니다. [당시 승격 보류 기록](native52/release.json).

Node 테스트 61개·네이티브 Rust 테스트 10개·프로덕션 빌드를 확인했습니다. 이번 변경은 원인 분리, 프로필 비교와 새 평가 배치의 재현 기능을 적용한 것이며 실전 엔진이 강해졌다고 주장하지 않습니다.

## 남은 추천 순서

1. 마지막 벽 설치 이후의 정확한 종반 승패를 탐색 내부에서도 활용하고, 미로 패배 국면의 방어 타이밍을 개선합니다. 이번 미사용 배치는 이후 개발 자료로 취급하고 다음 판단에는 새 배치를 사용합니다.
2. 여러 대국의 신경망 추론을 묶는 GPU 배치 자가대국을 구축합니다.
3. 보드 구조를 반영한 정책·가치 신경망과 MCTS를 충분히 학습합니다.
4. 과거 모델·기존 엔진과의 리그 및 검증된 모델의 자동 승격을 연결합니다.
5. 독립 엔진·숙련자와 대전해 실제 수준을 검증합니다.

## 재현

```powershell
npm run native:verify -- --apply
```

이 명령은 새 `v2` 배치를 사용해 빌드·대국·기보 검사·조건부 승격을 진행합니다. 개별 비교에서는 다음 옵션을 사용할 수 있습니다. 이미 결과가 있는 폴더는 새 이름으로 지정해야 합니다.

```powershell
npm run native:evaluate -- --profile strategy --suite maze --split development --cohort v2 --pairs 2 --ms 150 --out reports/new-strategy-review
npm run native:evaluate -- --profile combined --suite maze --split development --cohort v2 --pairs 2 --ms 150 --out reports/new-combined-review
npm run native:evaluate -- --profile candidate --suite maze --split development --cohort v2 --pairs 2 --ms 150 --out reports/new-tactical-review
```

부분 비교나 150ms 개발 대국은 정식 승격 기준을 통과할 수 없습니다. `native:promote`의 기본 입력은 최신 `reports/native52/validation/report.json`과 `reports/native52/holdout/report.json`입니다.
