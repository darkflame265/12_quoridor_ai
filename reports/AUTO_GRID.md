# 보드·격자 자동 인식과 재탐지

**업데이트:** 빠른 진행의 최대 6수 복원, 연결된 벽 중복 후보 정리, 확인된 격자 유지, 진단 저장·현재 화면 재동기화를 추가했습니다. 최신 검증과 남은 우선순위는 [진행 복구](SCREEN_RECOVERY.md)를 참고하세요.

2026-10-29. 화면 연결·프레임 고정·이미지 가져오기 때 보드와 칸 간격을 자동으로 찾도록 변경했습니다. 최초 드래그와 간격 숫자 입력을 생략할 수 있습니다. AI 엔진과 모델·승격 상태는 변경하지 않았습니다.

## 사용법

1. 앱을 새로고침하고 **화면 연동 · 자동 감시**에서 게임 탭/창을 연결합니다. 전체 9×9 보드가 보이게 해 주세요.
2. 보드 위치·가로 간격·세로 간격을 자동 계산하고 격자·말·벽을 표시합니다. 별도의 ‘선택 영역 인식’을 누르지 않아도 최초 판독 결과가 나옵니다.
3. **내 진영**, **원본 아래쪽 출발 진영**, **현재 차례**, **말·벽·잔여 수**를 확인하고 **확인한 배치를 왼쪽에 적용**합니다. 초기 차례·벽 숫자를 OCR로 읽는 기능은 아직 아닙니다.
4. 메인 화면에서 **자동 감시 시작**을 누릅니다. 이후 합법적인 한두 수 변화와 내 차례 추천을 자동 반영합니다.
5. 보드가 여러 개 보이면 **보드 1/2…** 후보 버튼에서 게임 보드를 선택합니다. 추적 중에는 이전 위치·크기로 선택 대상을 유지하고, 대상을 구분하지 못하면 반영을 보류합니다.
6. 자동 탐지가 실패하면 전체 보드가 보이는지 확인하고 **보드 자동 찾기**를 누르거나 드래그로 보정합니다. 드래그 또는 간격 수동 입력은 수동 격자로 전환합니다. 자동 재탐지로 돌아가려면 **보드 자동 찾기 → 배치 확인·적용**을 진행하세요.

자동 격자에서는 감시 중 약 1초마다 격자를 다시 찾습니다. 보드 이동·확대·공유 영상 해상도 변경을 따라가고, 격자가 바뀌면 기존 추천을 취소한 뒤 안정된 배치를 확인합니다. 수동 격자에서는 영상 해상도 변경 시 영역을 다시 지정해야 합니다. 브라우저의 백그라운드 제한에 따라 실제 주기는 늦어질 수 있습니다.

## 구현과 가로벽 누락 대응

- 어두운 테마의 평평한 색 영역에서 칸 후보를 찾고, 비슷한 크기의 칸들이 가로·세로 **9개씩 규칙적으로 배열**되는지 검사합니다. 고정된 화면 좌표나 초기 말 위치에 의존하지 않습니다.
- 축마다 간격과 칸 크기를 따로 추정합니다. 81칸 중 최소 65칸의 정렬과 양쪽 말 후보, 유효한 벽·경로·자원 상태를 확인해야 자동 후보로 제시합니다. 여러 후보가 있으면 임의로 첫 보드를 선택하지 않습니다.
- 바깥 선택 사각형뿐 아니라 실제 칸 배열로 보정하므로 잘못 드래그한 경계와 가로·세로 간격 오차를 줄입니다.
- 벽 판독은 기존의 작은 사각 샘플 대신 틈 중심 주변의 좁은 띠를 검사합니다. **같은 픽셀 행/열에서 두 칸 구간과 가운데 연결부가 모두 같은 색**일 때 벽으로 읽습니다. 축소·픽셀 반올림 오차를 허용하면서 인접한 별개 벽을 합치지 않도록 합니다.
- 가로벽 2개·세로벽 3개 배치에서 벽 5개와 잔여 수 **청록 8·분홍 7**을 검증했습니다. 90도 회전에서도 가로·세로 벽 검출이 대응하는지 확인했습니다.

사용자 화면의 누락 원인이 드래그 오차 하나였다고 확정한 것은 아닙니다. 이번 변경은 자동 격자와 벽 검출 오차 허용을 함께 보강한 것이며, 첨부 화면과 동일한 실제 게임 환경의 성공 여부는 추가 확인이 필요합니다.

## 검증과 한계

- 전체 Node 테스트 **118개**, 웹 빌드 통과.
- 격자 이동·축소·독립 축 비율 변화, 회전, 여러 보드, 전체 보드가 잘린 경우, 빈 이미지, 벽 5개 회귀 배치를 검사했습니다.
- 독립 headless Chrome의 **21개 시나리오**에서 자동 초기 판독, 기존 수동 보정, 자동 감시, 영상 안에서 보드 이동·비율 변경, 영상 해상도 변경, 후보 선택 후 추적, 보드 누락 시 적용 차단을 확인했습니다. 보드 전체가 한 칸만큼 움직여도 두 말의 착수로 잘못 기록하지 않는지도 검사했습니다. 처리되지 않은 페이지 오류는 0개입니다.
- 화면 공유는 자체 합성 MediaStream으로 검증했습니다. 실제 Wallz 공유·여러 브라우저 확대 배율의 장기 정확도는 아직 측정하지 않았습니다. 사용자의 브라우저 프로필·실제 대국에는 접근하지 않았습니다.
- 축이 정렬된 어두운 청록·분홍 테마를 우선 지원합니다. 보드 전체가 잘렸거나 가려짐, 작은 미리보기, 다른 테마·복잡한 아바타, 원근 사진에서는 자동 탐지가 실패할 수 있습니다. 현재 최소 보드 크기는 처리 프레임에서 180×180픽셀입니다.
- 실제 벽과 똑같이 보이는 컬러 미리보기를 영상만으로 확실히 구분하지 못할 수 있습니다. 착수 후 커서를 보드 밖으로 옮겨 주세요. 초기 차례 오류·되돌리기·새 게임·세 수 이상 놓친 진행은 재확인·적용이 필요합니다.

## 남은 추천 우선순위

1. **실제 게임 화면 회귀 검증**: 다양한 화면 크기·확대·벽 배치에서 자동 격자와 가로벽 누락 여부를 측정하고 실패 프레임을 테스트로 추가합니다.
2. **차례·잔여 벽 독립 판독**: 원본 숫자·차례 표시를 추적 상태와 대조해 미리보기나 초기 설정 오류를 검출합니다.
3. **되돌리기·새 게임·여러 수 누락 복구**: 최근 정상 배치와 실제 기보로 재동기화합니다.
4. **인식 진단·테마 지원 확대**: 벽별 검사 위치·실패 사유를 표시하고 다른 말/보드 테마에 대응합니다.
5. **처리 비용·지연 개선**: 선택 영역 중심 검사와 재탐지 비용을 계측·최적화합니다.
