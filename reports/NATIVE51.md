# 벽 미로 평가·전술 보호·승격 자동화

## 패배 원인과 변경

이전 Atlas 5 대국의 패배 기보에서 69개 국면을 조사했습니다. 기존 4개 후보 표본이 놓친 한 수 벽 위협은 9개 국면이었습니다. 예를 들어 `maze-holdout-0`의 10번째 진행 국면은 순수 우회 손해를 0으로 보았지만, 전수 확인에서는 3이었습니다. 이는 위협 평가의 누락이며 그 수가 패배의 유일한 원인이라는 증명은 아닙니다. [조사 원자료](native51/loss-review.json).

네이티브 후보는 다음을 적용합니다.

- 벽이 8개 이상인 미로에서는 모든 최단 경로 가지를 따라 한 수로 길을 늘릴 수 있는 벽을 검사합니다. 상대 경로 증가에서 자기 경로 증가와 벽 설치에 쓰는 한 차례를 빼며, 어느 말이든 길이 사라지는 불법 벽은 제외합니다. 4개 표본으로 자르지 않습니다.
- 벽 배치별로 양쪽 목표선에서 역산한 거리 지도를 공유·재사용합니다. 보드 좌표와 벽만으로 결정되는 거리 지도는 말 위치가 달라져도 재사용합니다. 캐시는 크기를 제한합니다.
- 말 간 점프를 제외한 기하학적 거리 기준의 **최대 한 수 순수 우회 손해**를 전수 검사와 대조했습니다. 점프·차례·여러 벽의 장기 조합까지 완전히 푼다는 뜻은 아닙니다.
- 상대가 곧 도착할 때의 말 이동과 실제 경로를 늦추는 방어 벽, 순수 우회 이득이 2 이상인 벽, 마지막 벽으로 상대를 늦추는 수는 후순위 탐색 축소에서 보호합니다. 먼 곳의 무관한 벽을 모두 보호하지는 않습니다.
- 개방된 초반에는 기존의 빠른 평가를 유지합니다. 마지막 방어 벽의 비선형 자원 가치도 보존합니다. 기존 즉시 승리·점프·목표선 위협 대응을 유지합니다.

12개 패배 국면을 개발용 회귀 배치로 보관했습니다. 이를 새 미사용 평가 배치에 섞지 않았습니다. [개발 회귀 배치](../evaluation/fixtures/native-maze-regressions.json).

## 후보 선택과 평가

같은 네이티브 바이너리에 이전 평가·탐색의 `baseline`, 평가만 바꾼 `strategy`, 평가와 전술 보호를 합친 `candidate`를 보관합니다. 프로필별 프로세스·캐시는 분리해 비교하며, 한 대국이 끝나면 프로세스를 종료합니다. 실제 앱은 승격 기준을 통과한 후보만 선택하고 그 외에는 baseline을 사용합니다.

정밀 평가를 모든 국면에 적용한 첫 후보는 검증 12판에서 **5승 7패**였습니다. 벽 미로는 4승 2패였으나 일반 배치가 1승 5패여서 채택하지 않았습니다. 이 결과를 보고 미로에 정밀 평가를 집중하고 불필요한 전술 보호를 줄였습니다. [첫 후보 결과](native51/validation/report.json), [당시 탐색 소스](native51/attempt1-source/search.rs.txt), [당시 평가 소스](native51/attempt1-source/strategy.rs.txt). 이 시도는 미사용 배치 평가에 진입하지 않았습니다.

최종 후보는 500ms·4코어, 일반/미로 두 종류에서 진영을 교환해 검증 12판과 별도 미사용 배치 16판을 평가합니다. 미사용 일반 배치에서는 표준 시작 보드를 제외해 검증의 표준 시작과 겹치지 않도록 했습니다. 엔진 소스·바이너리 해시, 시드, 모든 수의 깊이·점수·실제 시간·예상 진행, 전체 기보를 저장합니다. 반복 3회와 180수 제한은 평가용 무승부입니다.

조정한 후보의 검증 결과는 **8승 4패**이며 일반 배치 5승 1패, 미로 3승 3패입니다. [최종 후보 검증 기록](native51/validation-focused/report.json). 검증 배치는 비용 조정에 사용했으므로 최종 판단은 별도 미사용 배치 결과와 함께 해야 합니다.

미사용 배치 결과는 **9승 7패**이며 일반 배치 6승 2패, 미로 3승 5패입니다. [미사용 배치 원자료·전체 기보](native51/holdout/report.json). 미로의 비퇴행 조건을 통과하지 못했으므로 **후보를 승격하지 않고 기존 Atlas 5를 기본으로 유지**했습니다. 검증 283수와 미사용 368수에서 정한 시간 초과 기준을 넘긴 수는 없었습니다. 후보 응답 p95는 각각 약 500.6ms였고 최댓값은 검증 509.4ms, 미사용 505.3ms였습니다. 즉, 평가 누락을 고친 것이 실전 미로 승률 향상으로 곧바로 이어지지는 않았습니다.

승격 조건은 다음과 같습니다.

1. 검증 12판·미사용 16판 이상이 모두 완료되고 각 배치의 양쪽 진영 대국이 존재해야 합니다.
2. 동일한 소스, 500ms·4코어, baseline 상대여야 합니다.
3. 전술 16개를 모두 통과하고, 검증 전체 및 각 평가의 일반/미로에서 승수가 패수보다 적지 않아야 합니다. 미사용 배치 전체는 승수가 더 많아야 합니다.
4. 후보의 시간 초과 비율은 5% 미만이어야 합니다. 초과는 실제 응답이 예산의 1.2배+5ms보다 긴 경우입니다.
5. 각 기보를 독립 JS 규칙으로 처음부터 재생하고 시작 배치·진영·승자를 재검사합니다.

작은 진영 교환 표본을 이용한 배포 기준입니다. 게임끼리 상관이 있고 통계적으로 결정적인 우월성이나 인간 상대 실력을 증명하지 않습니다. 보고서의 Wilson 구간도 참고값입니다. 무승부를 승리로 세지 않습니다.

소스나 평가 보고서가 변경되거나 빌드 출처가 맞지 않으면 서비스는 baseline으로 복귀합니다. 승격 여부는 [배포 결정](../evaluation/native-release.json)에 기록합니다. 네이티브 서비스를 재시작해야 새 결정이 반영됩니다.

## 재현

```powershell
npm run native:review
npm run native:verify -- --apply
```

`native:verify`는 빌드 → 검증 → 미사용 배치 → 기보 확인 → 조건부 승격 순서로 실행합니다. 매번 새 결과 폴더를 만들며 평가가 실패하면 종료 코드 1을 반환합니다. 개별 실행은 다음과 같습니다. 이미 결과가 있는 폴더는 새 이름으로 지정해야 합니다.

```powershell
npm run native:evaluate -- --split validation --pairs 3 --out reports/my-validation
npm run native:evaluate -- --split holdout --pairs 4 --out reports/my-holdout
npm run native:promote -- --validation reports/my-validation/report.json --holdout reports/my-holdout/report.json --apply
```

이번 작업은 GPU 신경망 학습이나 실전 신경망 활성화를 추가하지 않습니다. GPU 환경은 이전 검증 상태를 유지합니다.

## 검증과 다음 순서

Node 테스트 60개, 네이티브 Rust 테스트 10개, Vite 빌드를 통과했습니다. 한 수 벽 위협의 전수 대조·불법 봉쇄 제외·거리 지도 재사용·반사 대칭·급한 방어와 무관한 벽 구분·취소 및 재탐색·기보 및 승격 조건을 확인했습니다. 원래 WASM 소스와 산출물은 바꾸지 않았습니다.

1. **미로 후보의 실전 성능 개선**: 이번 미사용 배치의 미로 패배 기보는 이제 개발 자료로 전환합니다. 정밀 평가와 전술 보호를 분리해 어떤 변경이 패배를 만드는지 대조하고, 두 벽 연속 함정·방어 타이밍·시간 배분을 개선합니다. 다음 최종 판단에는 새 시드의 미사용 배치를 사용해야 합니다.
2. **GPU 배치 자가대국**: 여러 게임의 정책/가치 추론을 묶어 데이터 생성 속도를 높입니다.
3. **보드 구조를 반영한 신경망과 MCTS 학습**: 정책·가치 모델을 충분히 학습하고 기존 엔진에 대조합니다.
4. **자가대국 리그와 자동 승격**: 과거 모델·기존 엔진을 상대해 강해진 모델만 채택합니다.
5. **외부 실력 검증**: 독립 엔진·숙련자와 대전해 실제 수준을 확인합니다.
