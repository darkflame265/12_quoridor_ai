# 100판 미로 패배의 평가·선택적 탐색 분리 진단

속도 후보의 100판 중 미로 26패를 재생하고, 벽이 2개 이상 남은 상태에서 서로 다른 패배 기보를 포함한 12개 국면을 결정적으로 추출했습니다. 사용한 기보는 이제 개발용으로 노출된 자료입니다. 새로운 승률 검증 표본으로 재사용하지 않습니다.

별도 `diagnostic-engine`은 기존 5.3 speed의 평가·규칙을 유지하고 **LMR(뒤쪽 수의 깊이 축소)만 비활성화**할 수 있게 했습니다. 기본 동작은 LMR 활성입니다. 일반 모드의 깊이 3 점수·PV·노드 수가 5.3 speed와 일치하는지 매 국면 확인했습니다. 원본·속도 후보·실제 게임의 기본 엔진은 변경하지 않았습니다.

## 같은 국면의 비교

각 검색은 새 프로세스를 사용했습니다.

- 단일 코어·깊이 3과 4: LMR 활성 / 비활성. 각각 최대 15초 예산을 주고 완료 여부를 구분합니다.
- 깊이 3: 1코어 / 4코어, LMR 활성.
- 4코어: 500ms / 3,000ms.
- 정적 평가의 상위 4개 위협 추정과 전체 합법 벽 검사 비교. Native 전체 후보 결과는 별도 JS 규칙에서 벽 128개를 전부 확인한 최대 이득과 대조했습니다.

고정 깊이의 비축소 탐색도 같은 휴리스틱 평가와 기존 즉시 승리 대응 확장을 사용합니다. 게임 전체의 최적 수·승패 증명은 아닙니다. 코어 수나 생각 시간에 따른 선택 차이만으로 오류라고 판정하지 않습니다.

## 실제 결과

| 관측 | 결과 |
| --- | ---: |
| 깊이 3에서 LMR 활성/비활성 점수 차이 | 2 / 12 |
| 깊이 4에서 LMR 활성/비활성 점수 차이 | 3 / 12 |
| 두 깊이 중 하나라도 점수가 달라진 국면 | 4 / 12 |
| 깊이 3에서 1코어/4코어 점수 차이 | 0 / 12 |
| 500ms/3,000ms에서 첫 수 변경 | 3 / 12 |
| 위협 추정이 전체 합법 벽 최대 이득보다 작음 | 9 / 24 진영 관측 |

예를 들어 maze-2는 깊이 3에서 기존 선택적 탐색이 말 이동을 선택하며 -378점, 비축소 탐색은 가로 벽을 선택하며 -272점이었습니다. 두 검색 모두 깊이 3을 완료했고 평가 함수도 같습니다. 이 사례를 [고정 검증 자료](../evaluation/fixtures/diagnostic66-lmr-gap.json)와 실제 실행 파일을 재실행하는 테스트로 보존했습니다.

maze-7에서는 깊이 4의 점수가 -528 대 -681로 반대 방향의 차이도 있었습니다. 선택적 탐색이 항상 보수적으로 낮은 점수를 내는 것은 아닙니다. 점수 차이가 난 네 국면은 현재 위치의 정적 위협 누락이 없었습니다. 따라서 이번 자료에서 선택적 탐색 차이를 단순한 현재 위치의 위협 누락만으로 설명할 수는 없습니다. 이후 도달하는 평가 위치의 정확성이나 실제 패배 원인은 추가 분석이 필요합니다.

LMR을 전부 끄는 것을 강화 해법으로 채택하지 않습니다. 예를 들어 maze-1의 깊이 4 탐색 노드는 18,973개에서 47,879개로 증가했습니다. 정확한 고정 깊이 기준을 얻는 것과 제한 시간의 좋은 수를 얻는 것은 다릅니다. 깊이 3의 코어 비교 결과로 다중 코어가 언제나 동등하다고 일반화할 수도 없습니다.

## 재현과 게임에서 사례 보기

```powershell
node scripts/build-diagnostic.mjs
node scripts/diagnose-speed-losses.mjs reports/diagnostic66/new-run
node scripts/verify-speed-diagnostics.mjs reports/diagnostic66/new-run
```

새 출력 디렉터리를 사용합니다. 검색 결과·상태·합법 PV·깊이·노드·시간·입력 및 바이너리 해시를 [분석 원본](diagnostic66/report.json)에 저장했습니다. 검증 도구는 원본 기보 해시와 상태·PV·분류를 다시 확인하고 게임에서 불러올 수 있는 [국면 기보](diagnostic66/cases/maze-2.json)를 만듭니다. 게임의 **기보 → 불러오기**에서 선택하면 양쪽 직접 조작 모드로 해당 위치를 볼 수 있습니다.

과거 보고서의 해시 검증은 당시 커밋에서 수행합니다. 진단은 기본 엔진을 교체하거나 승률 향상을 주장하는 작업이 아닙니다.

## 남은 추천 우선순위

진단용 Rust 13개·전체 Node 77개 테스트와 웹 빌드를 통과했습니다. 12개 상태·PV·기보와 빌드 소스·실행 파일 해시도 다시 검증했습니다.

1. 확보한 고정 사례를 기준으로 얕은 깊이·루트 수의 LMR 조건을 좁힌 후보 구현. 비축소 기준과의 차이 및 비용을 함께 검사.
2. 위협 평가 누락은 별도 후보로 개선해 탐색 변경 효과와 섞이지 않도록 비교.
3. 새 국면의 동일 조건 대전과 별도 holdout을 통과한 후보만 기본 엔진에 반영.
4. 캐시 조회·함수별 시간 계측과 외부 엔진·숙련자 검증.
