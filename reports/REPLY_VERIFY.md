# 선별된 실패 분기만 원래 깊이로 재탐색

2026-10-29. **수 순서는 유지하고, 경로 선별에 포함된 일부 축소 실패 분기만 원래 깊이로 다시 읽는 후보를 구현했습니다.** 정적 개선을 기준으로 삼은 pressure 후보는 안쪽 봉쇄의 추가 재탐색을 12회에서 3회로 줄이며 깊이 4의 선택 개선을 유지했습니다.

5만 노드 기준은 여전히 미달입니다. 추가 0.5초·4코어 진단에서는 깊이 4 참조보다 낮은 값의 선택이 원본 6/15회, 후보 1/15회였지만 공개 배치의 반복 결과입니다. 승률·인간 상대 강함의 증거로 취급하지 않으며 **기본 엔진은 원본 Atlas 5.3을 유지**합니다.

## 기존 탐색과 변경 범위

원본은 뒷순위 수를 LMR로 얕게 읽고, 그 점수가 현재 알파를 넘을 때 원래 깊이로 다시 읽습니다. 이번에는 알파를 넘지 못한 fail-low 중에서도 경로 특징이 있는 대응을 추가 확인합니다.

- 기존 경로 선별기의 exit 규칙을 사용합니다. 양쪽 말의 최단 경로 초입을 건드리는 뒷순위 벽을 최대 8개 고릅니다. 고정 좌표·기보 ID·색상은 조건으로 쓰지 않습니다.
- 적용 범위는 `depth=3, ply=1`입니다. 원래 상위 8개·TT 수·연결 벽 등 이미 축소하지 않는 수는 추가 확인 대상이 아닙니다. 원래 `reduce` 조건이 참일 때만 새 조건을 검사합니다.
- 전체 목록을 재정렬하거나 수를 삭제하지 않습니다. 원래 알파를 넘은 수의 정상 재탐색 규칙도 그대로입니다.
- 평가 함수에 새 점수를 더하지 않습니다. 추가 확인이 필요하면 원래 깊이의 영창(null-window) 탐색으로 값을 다시 얻고, 기존 PVS의 후속 조건을 따릅니다.
- 여기서 fail-low는 얕은 검색의 결과입니다. 더 깊은 값까지 보증하는 증거가 아니므로 추가 확인 조건은 실험적 휴리스틱입니다.

## 비교한 네 후보

|후보|선별된 축소 fail-low의 추가 확인 조건|
|---|---|
|near|현재 알파와의 차이가 64 이내|
|all|선별된 fail-low 모두|
|gain|한 수 뒤 정적 평가가 해당 수를 두기 전보다 좋아짐|
|pressure|그 정적 개선 폭이 64 이상|

64는 기존 벽 위협 항목의 한 단위에서 가져온 값입니다. 최적의 임계값을 증명한 것이 아닙니다. gain·pressure는 부모 노드의 정적 평가를 한 번 구하고, 실제 선별 fail-low가 발생한 경우에만 자식 평가를 요청합니다. 자식 점수의 부호를 바꿔 부모 시점으로 비교합니다. 정적 개선은 재탐색의 계기일 뿐 최종 검색 점수로 대입하지 않습니다.

near·all을 먼저 비교한 뒤, near가 필요한 분기를 놓치고 all은 추가 계산이 큰 것을 확인해 gain·pressure를 개발했습니다. 모두 공개 개발 국면을 보고 만든 후보입니다. 같은 기하학의 잔여 벽 변형 3개를 독립 표본으로 세거나 이 결과를 미사용 검증 결과로 주장하지 않습니다.

## 고정 깊이·고정 노드 결과

기존 안쪽 봉쇄의 잔여 벽 조건 3개와 3×3 공격·장문 각 1개를 사용했습니다.

|후보|깊이 4 선택 개선/악화|5만 노드 선택 개선/악화|5만 노드 완료 깊이 감소|
|---|---:|---:|---:|
|near|0 / 0|0 / 0|0|
|all|3 / 0|0 / 0|3|
|gain|3 / 0|0 / 0|3|
|pressure|3 / 0|0 / 0|3|

균등 벽의 안쪽 봉쇄 한 배치에서 관측한 비용입니다. 원본은 깊이 4에 48,508개 노드가 필요했고 선택한 수의 비축소 참조 값 차이는 8이었습니다.

|후보|깊이 4 노드|선별 fail-low 수|추가 원래 깊이 탐색 시도|선택 수의 참조 값 차이|
|---|---:|---:|---:|---:|
|near|48,508|6|0|8|
|all|52,343|12|12|0|
|gain|51,907|12|8|0|
|pressure|51,359|12|3|0|

pressure는 이 배치에서 부모 평가 요청 99회·자식 미리 평가 요청 12회·목표 거리 맵 계산 198회를 사용했습니다. 이전 exit 재정렬 후보는 추가 평가 요청 828회였습니다. 실행 경로도 달라지므로 이 요청 수 차이를 곧바로 전체 CPU 시간 감소율로 환산하지 않습니다. 캐시 적중도 포함한 요청 수이며, 일부 비용은 노드 수에 포함되지 않습니다.

5만 노드에서 near를 제외한 세 후보는 안쪽 봉쇄 세 조건 모두 깊이 3으로 끝났습니다. 사전에 정한 고정 노드 개발 기준을 통과했다고 표시하지 않았고 보고서의 `eligibleForTimedTrial`도 false 그대로입니다. 장문에서는 pressure가 루트 선택을 바꾸지 않으면서 노드가 22,575개에서 42,877개로 늘었습니다. 따라서 추가 재탐색 비용 문제가 해결됐다고 볼 수 없습니다.

## 0.5초·4코어 추가 진단

노드 수가 동일 CPU 비용은 아니므로, 실패한 개발 기준을 보존한 상태에서 pressure만 **보충 시간 진단**했습니다. 이 진단은 기준 면제·개발 대전 진입·엔진 승격에 사용하지 않았습니다.

원본 실제 바이너리와 pressure 후보를 5개 배치에서 3회씩 실행했습니다. 매번 새 프로세스를 사용하고, 라운드별 배치 순서와 역할 순서를 번갈아 배치했습니다. 시간 측정 중 에이전트의 다른 테스트·빌드는 병행하지 않았습니다. 사용자 컴퓨터의 OS 부하·클럭을 통제한 연구 실험은 아닙니다.

|항목|원본|pressure|
|---|---:|---:|
|검색 수|15|15|
|깊이 4 이상 완료|15|15|
|깊이 4 참조보다 낮은 값을 고른 검색|6|1|
|평균 완료 깊이|4.13|4.00|
|평균 방문 노드|59,148|58,784|
|엔진 계산 시간이 605ms 초과|0|0|

원본은 장문에서 두 번 깊이 5까지 완료했고 후보는 모두 깊이 4였습니다. 다른 깊이의 선택은 합법적으로 다를 수 있으며, 표의 참조 값은 완전한 승패가 아닙니다. 실제 낮은 참조 값 선택은 이 실행에서 안쪽 봉쇄에 집중됐고 두 엔진 모두 해당 검색을 깊이 4로 완료했습니다. 압도적 실력·통계적으로 확정된 개선·대전 승률 향상으로 해석하지 않습니다.

프로세스 시작 방식은 원본의 NativeProcess/health와 후보의 단일 입력 CLI가 다릅니다. 기록의 `wallMs`는 시작 비용까지 포함해 제품 응답 시간 비교에 그대로 사용하지 않습니다. 표의 시간 제한은 양쪽 엔진 내부에 같은 500ms를 전달한 것입니다. GUI의 지속 프로세스·캐시 재사용 조건은 별도 검증이 필요합니다.

- Node 테스트 95개와 웹 빌드 통과.

- off와 원본 깊이 3 점수·PV·노드 일치: 두 구현의 각 5개 국면.
- 네 후보의 5만 노드 반복: 20쌍. 선택·점수·노드·추가 작업 수 일치.
- 재검증: 후보 검색 40개 재계산, LMR을 전부 끈 깊이 4 점수 일치 20개, 독립 분기 집합 10개.
- 시간 기록: 30개 검색의 조건·합법 PV·요약을 확인하고 비축소 분기 5개 집합을 재계산했습니다. 시간 결과를 똑같이 재현했다는 뜻은 아닙니다.

## 남은 추천 우선순위

1. **다른 국면·깊이·계산 예산에서 독립 검증**: pressure의 시간 진단 신호가 일반·미로의 다른 기하학에서도 유지되는지 확인합니다. 후보를 더 조정하기 전에 여러 노드 예산과 실제 0.5초 조건의 판정 기준을 정하고, 기존 5만 노드 미달 결과는 보존합니다.
2. **거리 맵·부모 평가의 안전한 재사용**: 반복되는 선별 비용을 줄이고 CPU 시간을 계측합니다. 캐시가 시간을 줄여도 방문 노드 수가 반드시 줄어드는 것은 아닙니다.
3. **불필요한 재탐색 억제와 적용 깊이 검증**: 장문에서 선택 개선 없이 비용이 늘어난 경우를 분리하고, 현재 depth 3·ply 1 밖의 적용은 별도 시험합니다.
4. **실제 대전·미사용 검증 세트 후 승격**: 독립 개발 기준을 넘은 후보만 지속 프로세스 조건의 일반/미로 대전과 미사용 검증 세트로 평가하고 기본 엔진에 반영합니다.
5. **외부 실력 검증과 병목 계측**: 외부 엔진과 대전하고 추가 평가·BFS·캐시·코어 대기 비용을 분리합니다.
