# 위험한 벽 수 정렬과 선택적 깊이 보호

이 문서는 `1114a8b` 시점의 후보와 실제 결과를 기록합니다. 이후 [벽 우선순위·자원 소모 조정](WALL_RESOURCE.md)에서 추가 탐색 모드와 `search56-v1` 배치군이 생겼습니다. 과거 결과의 소스·바이너리 해시 재검증에는 당시 소스가 필요합니다.

Atlas 5.3의 규칙·평가 점수·정확한 종반 계산을 유지하면서 탐색 순서와 깊이 축소 예외를 바꾸는 후보를 구현했습니다. 별도 Rust 바이너리는 `Atlas 5.5 experiment`이며 기존 실전 Atlas 5.3은 보존합니다.

## 탐색 모드

정적 평가는 모두 기존 점수와 일치하는 `cache4`로 고정해 평가 함수를 함께 튜닝하지 않습니다.

| `--search` | 수 정렬 | 후순위 수의 깊이 축소 |
| --- | --- | --- |
| legacy | 기존 탐색 | 기존 방식 |
| ordering | 방어 벽·이득 있는 연결 벽 우선 | 기존 방식 |
| protected | ordering과 동일 | 중요한 수에 축소 예외 |

`ordering`은 상대가 목표선에 가까운 경우 경로를 늘리는 방어 벽에 우선순위를 더합니다. 연결된 벽이 자기 경로 손해를 뺀 상대 경로 증가를 1 이상 만드는 경우에도 먼저 읽도록 합니다. 계산에 필요한 연결도·경로 길이는 기존 합법 수 생성 과정에서 구한 값을 재사용합니다.

`protected`는 같은 정렬에 더해 급한 방어 수와 이득이 큰 벽의 탐색 깊이를 덜 줄입니다. 급한 방어가 아닌 경우 생성하는 보호 메타데이터를 정렬 점수 상위 최대 4개로 제한합니다. 캐시 축출로 메타데이터를 잃으면 기존 보수적 정책처럼 깊이 축소를 피하므로 실제 예외가 더 많아질 수 있습니다. 기존 검색이 이미 수행하던 루트 연결 벽 보호도 유지합니다.

두 모드 모두 모든 합법 수를 생성하고 검색에 남깁니다. 후순위 수의 축소 검색에서 alpha를 개선하면 기존의 전체 깊이 재탐색을 계속 수행합니다. 명목 탐색 깊이보다 추가로 한 수를 연장하는 기능이 아니라, 중요한 수를 얕게 줄이지 않는 예외입니다. 일반 국면의 완전한 최적 수를 증명하지 않습니다.

## 좌우 반전과 검증

연결 벽 점수를 차가운 캐시에서 따로 계산하면 좌우 반전 배치의 정렬 점수가 달라질 수 있음을 새 테스트에서 확인했습니다. 새 정렬은 정규화한 기준 방향에서 계산해 원래 방향으로 되돌립니다. 깊이 보호 메타데이터도 같은 좌표 변환을 사용합니다. 이 정리와 정렬 보너스가 ordering 모드에 함께 포함되므로 둘의 개별 대전 효과를 분리해 입증한 결과는 아닙니다.

Rust 테스트는 기존 검색과 합법 수 집합 일치, 보드·해시 복원, 좌우 반전 점수와 보호 대상 일치, 비긴급 보호 개수 제한, 직접적인 목표선 방어 벽 우선 및 깊이 보호를 검사합니다. 기존 취소·캐시·정확한 종반 테스트도 계속 사용합니다.

## 새 배치군

이전 v3 배치와 튜닝에 사용한 배치를 반복해서 미사용 자료라고 부르지 않도록 `search55-v1`을 추가했습니다. 개발·validation·holdout 시드는 각각 881931, 443159, 755627입니다. 일반·미로별로 이전 v3 배치와 새 분리 사이의 중복을 제외하고 50개씩 준비합니다. 전체 합법 기보 재생과 분리·중복 제거를 자동 테스트합니다.

시드는 공개된 재현용 값입니다. 보안상 숨겨진 시험이 아니라 이번 후보의 대전 평가를 분리하기 위한 자료입니다. 이전 holdout은 이미 사용된 자료로 취급합니다. 새 holdout 대전은 validation 통과 이후에만 진행합니다.

## 개발 대전

수당 500ms·4코어·최대 180수, 새 일반·미로 각 한 배치의 진영 교환으로 모드마다 4판을 두었습니다. 상대는 고정한 기존 Atlas 5.3이며 모든 모드가 같은 시작 배치를 사용합니다.

| 탐색 모드 | 성적 |
| --- | --- |
| legacy 대조군 | 3승 1패 |
| ordering | 4승 0패 |
| protected | 2승 2패 |

각 모드는 전술 16/16을 통과했습니다. 4판씩의 작은 개발 비교로 통계적인 우위나 인과 효과를 확정하지 않습니다. 깊이 보호를 추가한 후보가 더 강하다는 근거는 나오지 않았고, 수 정렬 후보를 다음 validation 대상으로 선택했습니다.

## validation·holdout 결과와 채택 보류

개발 비교 뒤 ordering 후보만 별도 배치로 검사했습니다. 모두 500ms·4코어·최대 180수입니다.

| 평가 | 일반 | 미로 | 합계 |
| --- | --- | --- | --- |
| 새 validation 12판 | 3승 3패 | 4승 2패 | 7승 5패 |
| 새 holdout 16판 | 3승 5패 | 4승 4패 | 7승 9패 |

전술 문제는 모두 16/16을 통과했고 시간 기준도 통과했습니다. 하지만 holdout의 전체 승패와 일반 배치 비퇴행 기준을 통과하지 못해 실전 채택을 보류했습니다. 기존 Atlas 5.3을 유지하며 이번 후보를 더 강한 실전 엔진이라고 부르지 않습니다. 사용한 새 holdout은 이제 노출된 자료이므로 다음 튜닝에서는 새 미사용 배치가 필요합니다.

## 재현 배치와 다음 진단

기존에 확보한 개발용 미로 4개를 각각 500ms로 다시 비교했습니다.

| 비교 | 기준 평균 깊이 / 노드 합계 | 후보 평균 깊이 / 노드 합계 |
| --- | --- | --- |
| ordering | 6.75 / 563,851 | 6.75 / 490,880 |
| protected | 6.75 / 542,859 | 6.50 / 443,316 |

두 비교는 별도로 실행했고 기준 수치도 달랐습니다. 노드 수가 작아진 이유는 수 정렬에 따른 가지치기와 처리 비용 등이 섞여 있어 속도 향상이나 퇴행의 원인으로 단정할 수 없습니다. 보호를 늘렸을 때 명목 완료 깊이가 낮아질 수 있다는 점도 확인했습니다.

- [정렬 모드 재현 비교](search55/ordering-review/report.json)
- [보호 모드 재현 비교](search55/protected-review/report.json)

노출된 validation 패배 기보에서 후보가 둔 벽 34개 중 27개는 즉시 거리 이득에서 한 차례의 비용을 빼면 0 이하였습니다. 연결 벽의 장기 효과가 있을 수 있으므로 이를 실수로 판정하지 않습니다. 이 자료에서 상대가 목표선에 가깝지만 즉시 승리 수는 없는 상황의 벽 선택은 0개여서, 근접 방어 보너스가 패인이라는 근거도 얻지 못했습니다. [벽 설치 진단 자료](search55/validation-wall-review.json)는 다음 우선순위 선별과 자원 소모 분석을 위한 개발 자료입니다.

Rust 테스트 18개와 전체 앱 테스트 68개, 빌드 및 총 40판 기보·시간 집계 검증을 통과했습니다. 기존 원본 엔진·WASM·학습 모델은 변경하지 않았습니다.

## 실행

```powershell
npm run maze:build
npm run maze:compare-search -- reports/search55/my-comparison
```

비교 명령은 완료된 대국을 재검증하고 없는 모드의 대전만 실행합니다. 비교 출력 자체는 새 경로를 지정합니다. 일부만 실행된 대국은 보존하고 새 경로에서 시작합니다.

```powershell
npm run maze:evaluate -- --out reports/search55/my-validation --mode cache4 --search ordering --cohort search55-v1 --split validation --pairs 3
node scripts/verify-maze.mjs reports/search55/my-validation --save
```

완료된 모드 비교는 `node scripts/verify-search.mjs reports/search55`로 다시 검증할 수 있습니다. validation과 holdout의 최종 판정은 `npm run maze:assess -- <validation 폴더> <holdout 폴더> <새 판정 파일>`로 기록합니다.

`--search` 기본값은 `legacy`이고 `--cohort` 기본값은 `search55-v1`입니다. 이전 배치를 다시 실행하려면 `--cohort native53-v3`를 명시합니다. 후보의 평가 모드·탐색 모드·배치군이 다른 validation과 holdout을 섞으면 채택하지 않습니다. 현재 보고서 형식은 v3이며 이전 v1·v2 자료는 기록된 커밋의 소스로 재검증해야 합니다.

## 남은 추천 우선순위

1. 패배 기보의 벽 설치·자원 소모·장기 이득을 분석해 우선순위 보너스와 중요 수 선별을 재조정.
2. 기준 방향 변환·캐시 조회·깊이 보호의 비용을 따로 측정하고 보호 범위 최적화.
3. 새 미사용 배치에서 실제 우위를 확인한 변경만 실전 채택.
4. 8개 위협 평가 비용과 경로·병렬 탐색 최적화.
5. 충분히 강해진 탐색 엔진으로 지도 자료·신경망 학습 재검토.
