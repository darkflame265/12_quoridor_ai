# 아래 시작 진영과 현재 차례 자동 판독

2026-10-29. 화면 연동에서 ‘나는 항상 아래에서 출발한다’를 적용했습니다. 아래 출발 줄 색으로 내 진영을 정하고, 원본 차례 문구·활성 카드와 수 추적을 대조합니다. AI 엔진·모델·기본 승격 상태는 변경하지 않았습니다.

## 사용법

1. 앱을 새로고침하고 **화면 연동 · 자동 감시 → 화면 연결**을 사용합니다. 9×9 보드와 오른쪽 플레이어 카드·차례 문구가 포함된 게임 탭/창을 공유하세요.
2. 자동 격자 아래에 **내 진영: 청록/분홍 · 아래 시작 · 자동**, **내/상대 차례 · 원본 문구/활성 카드 판독**이 표시됩니다. 진영·차례를 직접 선택할 필요가 없습니다.
3. 말·벽과 결과를 확인해 적용하고 **자동 감시 시작**을 누릅니다. 원본 차례·수 번호와 실제 합법 진행이 일치할 때만 반영하며 내 차례에 추천합니다.
4. 차례 문구·카드를 읽지 못하면 적용·추천을 보류합니다. 확대·공유 범위를 확인하거나 **원본 차례 표시 자동 판독**을 끄고 **판독 실패 시 진영·차례 수동 보정**을 열어 직접 선택하세요. 수동 모드임을 표시합니다.
5. 새 게임에서 아래 출발 줄 색이 바뀌면 기존 대국 추적을 보류합니다. **현재 화면 재동기화**에서 새 결과를 적용하면 내 색과 왼쪽 아래 시작 시점이 함께 바뀝니다.

화면 모드의 메인 ‘내 진영’과 ‘내 시작 위치’는 판독 결과를 따르도록 잠급니다. 다른 대전·직접 조작·관전 모드에서는 기존 설정을 사용할 수 있습니다. 저장한 화면 배치를 다시 열 때도 `sourceBottom`에 맞춰 내 진영과 아래 시작을 복원합니다. 말·벽의 실제 색과 소유자를 뒤집지 않습니다.

## 판독 근거

- 위·아래 출발 줄의 칸 모서리 36개씩을 검사합니다. 아래 색을 내 진영으로 쓰되 위줄이 반대 색인지 확인합니다. 말이 현재 어디에 있는지는 진영 판정 근거로 쓰지 않습니다.
- 원본 보드 오른쪽 영역의 `YOUR TURN`, `OPPONENT’S TURN` 문구를 로컬 글자 형태 템플릿으로 판독합니다. 공백과 작은 아포스트로피의 영향을 줄이고 영문 대문자 형태를 비교합니다.
- 문구가 작거나 보이지 않으면 **닫힌 활성 카드 테두리와 카드 안의 YOU/OPPONENT 표기**를 함께 검사합니다. 카드 위치나 시계 색만으로 임의 판정하지 않습니다. 문구와 카드가 서로 다른 차례를 가리키면 보류합니다.
- `MOVES` 헤더 옆의 1~3자리 수 번호를 확신할 수 있을 때 읽습니다. 직전 번호와의 차이가 합법 진행 길이·차례 교대와 일치하는지 검사합니다. 숫자가 불명확하면 강제로 채우지 않습니다. 선공 색의 가정으로 현재 차례를 정하지 않습니다.
- 배치와 관측 차례가 3회 연속 일치해야 확정합니다. 기존 차례를 원본 문구 하나로 덮어쓰지 않고, 실제 가능한 수와 함께 검증합니다. 충돌·미판독 때 이전 추천을 취소합니다.
- 최초 차례 판독 실패도 진단에 남깁니다. **인식 진단 저장**에는 문구·카드 근거, 글자 행 수, 테두리 검사 결과, MOVES 후보와 숫자 점수가 들어갑니다. 영상·픽셀 이미지는 저장하거나 업로드하지 않습니다.

## 사용자가 보고한 실제 판독 실패 대응

작업 도중 사용자가 공유한 화면에서는 **진영 자동 판독은 성공했고 차례 판독은 실패**했습니다. 카드와 YOUR TURN 문구가 화면에 보였으므로 ‘공유가 부족하다’고 단정할 수 없었습니다.

초기 구현은 직선·밝은 테두리 합성 화면에 치우쳐 있었습니다. 실제처럼 둥글고 얇은 테두리는 대각선 픽셀 연결이나 약한 색 때문에 놓칠 수 있어 다음을 보강했습니다.

- 대각선과 작은 픽셀 단절을 포함한 카드 테두리 연결 검사.
- 말의 밝은 색상 검사와 별도로 희미한 청록·분홍 테두리 범위 지원.
- 7~8px를 포함한 글자 템플릿과 여러 로컬 글꼴, 붙은 카드 제목의 단어 단위 검사.
- ‘카드 포함 공유·확대·수동 보정’ 안내와 최초 판독 실패 진단.

실제 첨부 원본 프레임의 픽셀을 다시 실행한 검증은 하지 못했습니다. 사용자 브라우저·실제 게임에는 접근하지 않았습니다. 따라서 아래 합성 검증이 실제 환경에서의 성공을 보장하는 것은 아니며, 동일 화면은 새로고침·재연결 후 다시 확인해야 합니다.

## 검증

- 전체 Node 테스트 **130개 통과**, 웹 빌드 통과.
- 청록·분홍 아래줄, 말 위치와 무관한 진영 판정, 가림·반대 줄 불일치, 원본 차례를 포함한 안정화, 수 번호·차례와 6수 복원 제약을 검사했습니다.
- 별도 headless Chrome **36개 시나리오 통과**, 처리되지 않은 페이지 오류 0개. 합성 화면의 양 진영·양 차례·여러 글꼴, 작은/큰 문구, 문구 없이 희미한 1px 둥근 카드와 8px 제목만 있는 경우를 검사했습니다.
- 수동 선택 없이 분홍 아래 진영과 차례를 읽어 적용하고, 내 수→상대 수의 픽셀 영상으로 원본 차례·MOVES·기보·추천을 동기화했습니다. 충돌한 차례·활성 카드와 새 게임 색 변경에서는 잘못 반영하지 않았습니다.
- 최초 미판독 시 적용 차단·진단 기록·명시적 수동 보정도 확인했습니다. 공유 영상은 자체 합성 MediaStream이고 QA 분석 엔진은 Atlas 3입니다.

## 남은 추천 우선순위

1. **실제 실패 화면 회귀 검증**: 진단 JSON으로 작은 글씨·카드 위치·배율별 실패를 구분하고 실제 프레임 정확도·지연을 측정합니다.
2. **원본 기보 착수 표기·잔여 벽 숫자 판독**: MOVES 수 번호 외의 독립 근거를 늘려 벽 미리보기·누락 진행을 검증합니다.
3. **6수 초과·되돌리기·새 게임 복구**: 기보와 수 번호로 현재 기준 배치까지 재연결합니다.
4. **판독 영역·언어·테마 확대**: 카드 위치가 다른 화면과 영문 외 표시를 지원하고 시계 변화도 보조 근거로 검증합니다.
5. **처리 비용 최적화**: 템플릿·격자·메타데이터 판독을 분리해 프레임 처리 지연을 줄입니다.
