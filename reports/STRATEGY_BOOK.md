# 기본 기술 자료를 이용한 전략 진단

2026-10-28. 이번 적용은 **전략 사례·반례와 재현 도구 구축**입니다. 게임의 평가 함수·기본 엔진을 강화하거나 교체한 단계는 아닙니다. 기본은 승인된 원본 Atlas 5.3입니다. 실력 향상을 입증한 새 대전 결과는 없습니다.

## 자료와 범위

원문 [기본 기술 1](https://greena0216.tistory.com/137), [기본 기술 2](https://greena0216.tistory.com/138), [기본 기술 3](https://greena0216.tistory.com/141)의 그림에서 다음 5개 배치를 직접 옮겼습니다.

|배치|출처의 기술|비교 내용|
|---|---|---|
|inside-edge|1편: 가장자리 안쪽 봉쇄|안쪽 설치와 가장자리 설치|
|chamber-horizontal|2편: 3×3 구역|가로 공격 벽|
|chamber-vertical|2편: 3×3 구역|세로 공격 벽|
|long-net|3편: 장문|가까운 벽과 먼 준비 벽|
|backdoor|3편: 뒷문 예외|공격 전 배치와 대응 벽의 합법성|

3편의 뒷문 그림은 파란 공격 벽과 빨간 대응 벽을 제외한 배치입니다. 2편의 두 배치는 서로 다른 시점의 예시입니다. 하나의 연속 기보라고 가정하지 않았습니다. 원문 이미지 자체는 저장소에 배포하지 않았으며 URL·그림 순번·검토한 파일의 SHA-256은 [출처 기록](book70/sources.json)에 남겼습니다. 아직 공역 전체, 벽 소모전, 마지막 벽 대기 등 모든 기술을 옮긴 것은 아닙니다.

## 확정된 정보와 가정

- 그림의 말 위치와 갈색 벽은 직접 전사했습니다. a~i는 x=0~8, 9~1행은 y=0~8입니다. 백은 0번이며 위쪽이 목표입니다.
- 그림만으로 확정할 수 없는 차례는 공격자 차례로 가정했습니다. 원래 벽의 소유자와 남은 개수는 원문 게임의 사실이라고 주장하지 않습니다.
- 벽을 비슷하게 사용한 경우, 공격자가 더 사용한 경우, 수비자가 더 사용한 경우를 만들었습니다. 소유자별 설치 수+잔여 벽=10을 유지합니다. 이 세 경우는 가능한 잔여 벽 조합 전부를 대표하지 않습니다.
- 각 배치를 180도 회전하고 색상을 바꿔 총 **30개**를 만들었습니다. 기하학 효과는 회전 대칭이어야 하지만 제한 시간 탐색의 수 선택은 정렬·작업 배정 때문에 달라질 수 있습니다.
- 모든 배치는 초기 상태부터 합법적으로 도달하는 기보를 생성했습니다. 이는 **재현용 합성 기보**이며 원문의 실제 대국 기록이 아닙니다.
- 글의 예시는 비교할 후보이며 유일 최선 수나 필승 정답이 아닙니다. 원문의 일반적인 설명을 무조건적인 평가 가산점으로 바꾸지 않았습니다.

## 측정 결과

엔진 프로세스를 매번 새로 시작해 기존 탐색 기록의 영향을 줄였습니다. 30개 모두 원본 5.3으로 0.5초·4코어, 벽 수가 비슷한 10개는 추가로 2초·4코어를 측정했습니다. 다른 PC의 줄바꿈 형식에도 검증할 수 있도록 도구 해시를 정규화한 뒤 같은 측정을 한 번 더 했습니다. 두 실행의 엔진 소스·바이너리는 같습니다. 각 선택의 전체 PV는 JS 규칙으로 검사했습니다. 모든 합법 벽의 즉시 순이득도 BFS로 계산했습니다.

|비교|첫 측정|반복 측정|
|---|---:|---:|
|0.5초 선택이 깊이 3 비교 후보 중 낮은 값인 경우|5 / 30|3 / 30|
|2초 선택이 깊이 3 비교 후보 중 낮은 값인 경우|1 / 10|4 / 10|
|0.5초와 2초의 첫 수가 달라진 경우|3 / 10|4 / 10|
|0.5초가 깊이 4를 완료한 경우|24 / 30|15 / 30|
|그중 같은 깊이 4 비축소 분기 비교에서 낮은 값인 경우|3 / 24|0 / 15|

위 수치는 전체 합법 수를 평가한 순위가 아닙니다. **글의 비교 수 + 0.5초 선택 + 가능한 2초 선택**의 집합만 비교했습니다. 분기 값은 기존 수작업 평가 함수를 사용하는 LMR 없는 참조입니다. 루트의 반복 이력과 ply를 유지한 같은 깊이 비교이며, 끝까지 풀어 구한 승패가 아닙니다. 서로 다른 깊이의 결과가 다르다는 것만으로 탐색 오류라고 판정하지 않았습니다. 시간 제한 결과는 다시 실행하면 달라질 수 있습니다.

### 다음 수정에 사용할 구체적 국면

첫 측정에서 깊이 4까지 완료했지만 같은 깊이 비축소 비교에서 낮은 수를 고른 것은 `inside-edge`의 회전된 세 가지 잔여 벽 조건입니다. 반복 측정에서는 이 세 배치 모두 깊이 3에서 끝났습니다. 따라서 매번 발생하는 선택 오류라고 단정하지 않습니다. 첫 선택의 비축소 분기 점수 자체는 다시 계산해 동일함을 확인했습니다.

|가정|선택한 수의 비교 값 차이|해석|
|---|---:|---|
|balanced/rotated|64|비축소 비교 후보에 더 높은 값 존재|
|attacker-poor/rotated|8|작은 차이, 강제 승패 차이로 취급 금지|
|defender-poor/rotated|8|작은 차이, 강제 승패 차이로 취급 금지|

이는 엔진이 모든 원문 기술을 모른다는 증거가 아닙니다. 예를 들어 첫 측정의 3×3 가로·세로 공격은 기본 방향·균등 벽 조건에서 그림의 공격 벽을 골랐지만, 반복 측정의 같은 조건에서는 깊이 3에서 끝나며 말 이동을 골랐습니다. 완료 깊이와 시간 제한의 변동을 먼저 계측해야 합니다. 장문의 먼 벽은 즉시 거리 순이득이 -1이고 가까운 벽은 +1입니다. 안쪽 준비 벽도 즉시 순이득 -1입니다. **즉시 거리 이득만 최대화하면 준비 수를 누락할 수 있다는 점**은 확인되지만, 먼 벽을 항상 더 좋게 평가해야 한다는 결론은 아닙니다. 2초의 수가 더 얕은 참조와 달라도 더 약하다는 뜻은 아닙니다.

## 남은 추천 우선순위

1. **완료 깊이 변동과 안쪽 봉쇄 국면의 탐색 개선**: 동일 조건 반복·고정 노드 예산으로 시간/작업 배정 변동을 분리하고, 첫 측정의 3개 차이에서 루트 순서·LMR·내부 분기 원인을 구분합니다. 준비 벽을 놓치는 분기만 보강하고 전역 깊이 보호를 반복하지 않습니다.
2. **준비 벽과 상대 복구 대응의 2단계 비교**: 장문·뒷문·3×3 예시의 수비 최선 대응을 포함한 분기 기준을 추가합니다. 즉시 이득이 낮다는 이유로 후보에서 밀리는지부터 확인합니다.
3. **공역·벽 소모전·마지막 벽 사례와 반례 확장**: 차례·잔여 벽 조건별로 검증한 뒤 필요한 항목만 수작업 평가에 넣습니다. 거리·남은 벽과 중복 계산하지 않습니다.
4. **새 후보의 대전 검증**: 이 사례는 회귀 검사로 쓰고, 별도 일반·미로 대전과 미사용 검증 세트에서 원본을 넘는 후보만 승격합니다.
5. **외부 엔진 검증과 병목 계측**: 내부 대전 승률과 인간 상대 절대 강함을 구분하고 탐색량·응답 시간을 함께 확인합니다.
