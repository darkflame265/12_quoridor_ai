# 마지막 1~3개 벽의 방어 가치

Atlas 0.4의 보완 빌드다. 엔진 선택은 0.4·5.3을 유지하며 서비스에 별도 빌드 해시와 보완 내용을 표시한다. 5.3 원본 평가·소스는 변경하지 않는다.

## 동작

- 내 벽 1~3개, 상대 벽 1개 이상일 때 루트에서 적용한다. 골인 직전으로 제한하지 않는다.
- 상대가 합법적으로 벽 하나를 놓았을 때의 `내 거리 증가 - 상대 거리 증가 - 설치 1턴`을 계산한다. 양쪽 경로가 존재하는 경우만 후보로 인정한다.
- 양의 이득을 주는 위협 중 최대 6개를 보존한다. 각 내 벽 설치 후 해당 공격의 잔여 위험을 다시 계산한다. 위험을 없애는 벽에는 추가 보존 비용을 주지 않는다.
- 비용은 `12 × (4-내 벽 수) × (최대 4의 잔여 위험 + 최대 2의 상대 벽 우위)`다. 마지막 벽일수록 높고 최대 216점이다. 기존 평가의 거리 단위는 약 120점이지만 이 비용은 승률로 해석할 수 없다.
- 행동을 금지하지 않는다. 기존 탐색 점수와 함께 비교한다. 기존 pressure_adjust의 메이트 점수 보호와 완전 탐색 승리 전략 처리를 유지한다.
- 추가 작업은 남은 시간의 12%와 45ms 중 작은 값 이내다. 취소·시간 초과 시 부분 비용은 전부 버리고 기존 평가를 사용한다. 복제 배치에서 후보를 계산하여 원본을 보존한다.
- 화면 및 JSON reserveDefense에 적용 여부·완료 여부·위협·보유 벽·벌점 적용 행동 수·선택 행동의 비용을 기록한다. 모든 후보 목록을 매번 직렬화하지 않아 기록 용량을 줄인다.

## 한계와 확인 결과

미래 이동 위치의 위협이나 여러 벽의 연결 공격은 계산하지 않는다. 위협 6개 제한도 있으므로 안전 또는 승패 증명이 아니다. 과도한 벽 보존으로 공격 기회를 놓칠 위험이 있어 승률 개선을 주장하지 않는다.

최근 기보의 19·21·23수 직전 세 위치를 500ms·4코어 새 프로세스로 확인했다. 모두 합법 수를 반환했지만 추천은 기존과 동일했다. 19·21수는 현 위치의 수익성 있는 단일 벽 공격을 찾지 못했다. 23수는 위험 3, 벌점 적용 87개였지만 d7 세로벽은 그 위협을 차단해 면제됐다. 따라서 이 패배가 해결됐다는 근거는 없다. diagnostics.json에 해당 배치와 결과를 보존한다.

Rust 릴리스 빌드·웹 빌드 및 실행 서비스 버전·빌드 일치를 확인한다. 긴 테스트 대전과 전체 테스트는 사용자의 기존 요청에 따라 생략한다.
