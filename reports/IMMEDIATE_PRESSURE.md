# 상대의 가까운 길목을 막는 즉시 압박 후보

2026-10-29. 상대의 먼 도착 지점에 벽을 쌓는 추천을 진단하고, 앞 1~3구간에서 효과가 생기는 벽을 우대하는 독립 Native 후보를 추가했습니다. 기존 Atlas 5.3 소스·기본 승격 상태와 신경망 모델은 변경하지 않았습니다.

## 사용법

1. 실행 중인 쿼리도 앱을 종료하고 다시 실행합니다. 기존 서버는 새 `/api/pressure` 경로를 모르므로 페이지 새로고침만으로 서비스가 추가되지는 않습니다. 바탕화면 실행기는 새 엔진을 필요할 때 자동 빌드합니다.
2. **사용 엔진 → Atlas 즉시 압박 0.1 · 실험 (미승격)**을 선택합니다. 0.5초·4코어가 이번 개발 대전 조건입니다. AI 대전·화면 연동의 추천·AI 관전에서 사용할 수 있습니다. 관전에서는 진영별 엔진을 고릅니다.
3. 사용 엔진 표시에서 **Atlas 즉시 압박 / 0.1 실험 / 5.3 + 가까운 길목 평가**와 빌드 ID를 확인합니다. 사용할 수 없으면 명시적으로 오류를 표시하며 다른 엔진으로 몰래 대체하지 않습니다.
4. 추천 아래의 설명을 확인합니다. 예: **상대 최단 경로 1번째 구간 차단 · 상대 경로 +1칸 · 내 경로 0칸 · 설치 1턴**. 설명은 기존 엔진의 추천에도 표시됩니다.

기본값은 기존 안정 엔진입니다. 개발 8국만으로 새 후보가 더 강하다고 확정하거나 모든 추천을 가까운 벽으로 바꾸지 않았습니다. [실제 서비스·화면 검증](immediate-pressure/browser.json), [화면](screen-import/pressure-engine.png), [별도 실행기 검증](immediate-pressure/launch.json).

## 현재 추천의 계측

안정 5.3의 기본 평가는 경로 거리 차이와 잔여 벽·진행 선택지를 중심으로 합니다. 연결 벽은 기본 탐색 순서에서 접촉 수 ×180을 더 받습니다. 루트에서 ‘상대가 몇 번째 구간에서 이 벽을 만나느냐’는 별도 우대 기준이 없었습니다. 현재 제공한 벽 구조가 단순히 가산점 하나 때문에 생겼다고 확정한 것은 아닙니다.

다음 값들을 원본과 독립 후보에서 기록했습니다.

- 상대·내 경로 거리 증가, 설치에 쓰는 1턴, 거리 기준 순이득.
- 상대의 **모든 최단 경로 분기** 중 벽으로 사라지는 구간과 가장 이른 접촉 위치. 경로는 말이 서 있는 칸을 무시한 벽 그래프 기준으로 세며, 점프를 포함한 실제 턴 수와 같다고 주장하지 않습니다.
- 상대의 합법 말 이동 선택지 전후 개수와, 가능한 한 수 이후에 남는 거리 증가의 최솟값. 이 최솟값은 보수적인 하한이며 상대의 실제 최선 응수나 강제 승리 증명이 아닙니다. 벽 응수를 포함한 후속 판단은 기존 탐색이 맡습니다.
- 연결 벽 개수와 기본 정렬 식 점수. 이 정적 식 점수는 즉시 승리·전이표·히스토리 같은 탐색 보너스를 제외한 설명용 값입니다.

### 첨부 배치를 좌표로 옮긴 예

직전 사용자가 제공한 보드를 손으로 옮긴 상태를 `provided-board-transcribed`로 저장했습니다. 그 이전 착수 순서는 만들어 넣지 않았으며 이미지에서 자동 추출한 원본 데이터라고 주장하지 않습니다.

| 벽 후보의 원본 좌표(x,y,방향) | 상대 경로 증가 | 내 경로 증가 | 효과 시작 구간 | 한 수 이후 증가 최솟값 | 압박 보정 |
|---|---:|---:|---:|---:|---:|
| (4,6,h): 두 엔진의 다음 추천 | +2 | 0 | 11번째 | 2 | 0 |
| (1,3,h): 가까운 후보 | +2 | 0 | 2번째 | 0 | +12 |

이 단일 0.5초 스냅샷에서 새 후보도 먼 벽을 선택했습니다. 가까운 후보의 보정만으로 기존 탐색의 선택을 넘지 못한 사례입니다. 이는 먼 벽의 이론적 최선성을 입증한 것이 아니며, 축소 탐색·깊이·가중치 영향을 더 구분해야 합니다. [전체 후보·탐색 결과](immediate-pressure/check.json).

## 후보의 적용 범위

- `pressure-engine`은 검증된 Native 규칙·탐색을 별도 크레이트에서 포함하고, 빌드 시 루트 선택 부분에만 패치를 적용합니다. 원본 파일을 덮어쓰지 않습니다. 기준 프로필은 기존 안정 `candidate`(5.3)입니다.
- 상대의 앞 3구간을 막고 **상대 거리 증가 − 내 거리 증가 − 설치 1턴 ≥ 0**인 벽에 최대 **24점**의 루트 보정을 줍니다. 기존 경로 한 칸의 평가 단위는 120점입니다. 먼 벽을 무조건 금지하거나 위치만 가까운 벽에 점수를 주지 않습니다.
- 내부 정적 평가와 연결 벽 가산점은 유지해 이번 변경의 효과를 분리했습니다. 이 후보는 루트 수준 수작업 평가 보강이며 신경망 학습이나 새로운 기본 모델이 아닙니다.
- 액션별 보정을 적용한 만큼 루트의 좁은 탐색 창 기준도 이동시킵니다. 즉시 승패 점수에는 보정을 더하지 않습니다. 기존 마지막 벽·무벽 종반 처리를 유지합니다.
- 압박 계산도 생각 시간에 포함하고 취소를 확인합니다. 다 계산하지 못하면 부분적으로 계산한 보정 배열을 쓰지 않고 0으로 되돌립니다. 현재 진입 수를 우대하는 기능이며 상대 차례마다 전체 공격 스타일을 강제하는 별도 목적 함수는 아닙니다.

## 개발 대전 결과

원본 안정 5.3과 동일한 **최대 0.5초·4코어**, 일반/미로 각 2개 시작 배치에서 진영을 교대해 총 8국을 진행했습니다. 이 대전 동안 다른 무거운 검증을 함께 실행하지 않았습니다.

| 구분 | 후보 승 | 후보 패 | 무승부 |
|---|---:|---:|---:|
| 일반 | 2 | 1 | 1 |
| 미로 | 2 | 2 | 0 |
| 합계 | **4** | **3** | **1** |

| 벽 사용 계측 | 즉시 압박 후보 | 기존 안정 |
|---|---:|---:|
| 설치 벽 | 57 | 55 |
| 상대 앞 3구간을 막은 벽 | 21 / 36.8% | 14 / 25.5% |
| 직후 거리 기준 순이득이 음수인 벽 | 14 | 14 |
| 설치 직후 상대 거리 증가 합계 | 107 | 101 |

각 엔진 222수의 실제 응답 시간에서 `예산×1.2+5ms` 초과는 0회였습니다. 모든 수가 항상 500ms를 사용한 것은 아니며, 일찍 끝난 전술·종반 계산도 포함합니다. 기보 8개·총 512착수를 독립 규칙으로 재생하고 계측과 승패를 다시 검증했습니다.

이 수치는 **작은 개발 표본에서 스타일이 조금 바뀐 관찰**입니다. 승률 향상·사람보다 강함·통계적 유의성을 입증하지 않습니다. 별도 홀드아웃과 충분한 검증 표본이 없으므로 기본 엔진을 승격하지 않았습니다. [대전](immediate-pressure/development/report.json), [기보·계측 재검증](immediate-pressure/development/verification.json).

## 검증과 재현

- Rust 테스트 **15개**, 전체 Node 테스트 **144개**, 웹 빌드 통과.
- 압박을 끈 독립 엔진과 원본을 새 프로세스·1코어·고정 깊이로 비교해 6개 배치의 점수·PV·깊이·노드 수가 일치했습니다.
- Native의 743개 액션 계측을 독립 JS 규칙·BFS 계산과 대조했습니다. 전술 16개, 취소 후 재사용을 통과했습니다.
- headless Chrome **44개 시나리오**에서 기존 화면 연동과 새 Native 선택·실제 계산·관전 한 수·AI 응수·추천 설명을 확인했습니다. 캡처 입력은 합성 영상이며 실제 사용자의 브라우저나 대국에 접근하지 않았습니다.
- 실제 앱 실행기도 별도 상태 디렉터리·브라우저 열기 없이 띄워 새 프록시와 압박 엔진의 합법 응답을 확인하고 종료했습니다.
- 원본 Native 소스 해시는 `be6af5d57cc5068c54d8c7eb8e3ef5d18d2e906617ecc6b947f3df60751a52e4`, 기본 프로필은 그대로 `candidate`입니다.

```powershell
npm run pressure:build
npm run pressure:check
npm run pressure:evaluate -- --out reports/immediate-pressure/new-development --pairs 2 --ms 500 --cores 4
npm run pressure:verify -- reports/immediate-pressure/new-development
```

대전 출력 폴더는 새 경로를 지정해야 합니다. 기존 증거를 덮어쓰지 않습니다. 빌드 산출물은 Git에서 제외하고 소스·잠금 파일·빌드 신원·대전 기보를 저장합니다. 다른 컴퓨터의 바이너리 해시는 재빌드 환경에 따라 달라질 수 있습니다.

## 남은 추천 우선순위

1. **가까운 벽 후보의 탐색 누락 진단**: 첨부 배치의 가까운/먼 벽을 같은 깊이와 충분한 분기로 읽어 가중치 문제와 루트 축소 영향을 분리합니다.
2. **효과 지속 평가 개선**: 보수적인 한 수 하한과 상대의 최선 이동·벽 응수 후 이득을 구분해, 쉽게 무력화되는 압박을 줄입니다.
3. **가중치 비교와 독립 대전 확대**: 가까운 차단 비율·낭비·시간·승패를 함께 비교하고 별도 검증/홀드아웃을 통과한 후보만 기본 승격을 검토합니다.
4. **독립 엔진·실제 대국 검증**: 기존 엔진과의 자가 비교를 넘어 실전 방해 효과와 취약점을 확인합니다.
5. **압박 계산 비용 계측·최적화**: 짧은 시간에서 깊이가 줄어드는 국면과 효과 없는 루트 계산을 줄입니다.
