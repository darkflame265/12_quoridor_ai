# Atlas 5.3 약점 배치 수집과 탐색 비교

신경망 학습 대신 기존 Atlas 5.3의 판단을 개선하기 위한 진단 도구를 추가했습니다. 이번 단계는 약점 재현과 개선 지점 선정이며 실전 엔진의 평가 함수나 탐색은 변경하지 않았습니다.

## 실제 검사

기존 `reports/native53/validation`의 패배 6판을 독립 JavaScript 규칙으로 재생해 후보 상태 167개를 추출했습니다. 여기서 일반·미로, 양쪽 벽 소진 종반, 마지막 벽, 벽이 많은 중반을 포함하는 12개를 골랐습니다. 표본은 전체 약점을 대표하거나 모두 찾았다는 의미가 아닙니다. 기존 holdout은 열지 않았습니다.

각 상태에서 새 Native 프로세스로 다음을 실행했습니다. 모든 검색은 승인된 Atlas 5.3·4코어입니다.

1. 500ms 탐색과 같은 조건의 반복 탐색: 짧은 탐색의 선택 안정성 확인.
2. 3,000ms 탐색: 더 깊이 읽었을 때 선택이 달라지는지 확인.
3. 짧은 탐색과 긴 탐색의 후보 수를 각각 둔 뒤 1,500ms 재탐색: 같은 추가 예산에서 후보 수 비교. 상대 차례 점수는 원래 차례 관점으로 부호를 바꿉니다.
4. 양쪽 벽이 모두 0인 상태는 독립 JavaScript 역산으로 정확한 승패 확인. 마지막 벽 이후의 자식 상태도 해당하면 정확하게 확인합니다.

검색 시작 전 프로세스 준비 시간을 제외하고, 실제 검색 통신 시간을 별도로 기록했습니다. 루트 검색끼리는 캐시를 공유하지 않습니다. 짧은 검색을 먼저 수행해 긴 검색에 캐시 이득을 주는 방식이 아닙니다.

## 발견한 재검토 지점

12개 중 4개에서 선택이 달랐고 모두 미로였습니다. 짧은 탐색을 반복했을 때는 12개 모두 같은 첫 수를 골랐습니다. 4개 중 3개는 후보 수 이후 재탐색에서도 점수 차이가 50 이상이었습니다. 루트에서 독립적인 정확한 종반 계산이 가능한 2개를 포함해 이번 검사에서 증명된 승패 손실은 0개입니다.

| 배치 | 상황 | 500ms 선택과 3초 선택 차이 | 후속 탐색 점수 차이 |
| --- | --- | --- | ---: |
| loss-4 | 남은 벽 0 대 1 | 서로 다른 방향으로 이동 | 12 |
| loss-5 | 남은 벽 2 대 4 | 가로벽 설치 대신 전진 | 68 |
| loss-9 | 남은 벽 5 대 5 | 세로벽 위치 변경 | 130 |
| loss-11 | 남은 벽 3 대 3 | 가로벽 위치 변경 | 360 |

`loss-9`는 두 벽 모두 즉시 상대 최단 거리를 2 늘리고 자기 거리는 그대로지만 후속 평가가 다릅니다. `loss-11`은 두 벽 모두 즉시 최단 거리를 바꾸지 않는데도 후속 평가가 크게 다릅니다. 단순한 즉시 거리 증가만으로 벽을 판단하기 어려운 구체적 재현 사례입니다. 연결 벽과 향후 방어 가능성, 벽을 쓰는 시점의 가치부터 살펴볼 근거가 됐습니다.

긴 검색도 선택적 탐색이고 후속 검색의 깊이도 제한되어 있습니다. 점수 차이는 승률이나 확정 손실이 아닙니다. 긴 검색의 선택을 무조건 정답으로 고정하거나 그 수를 고르게만 만드는 수정은 하지 않습니다. 현 단계에서 확인한 것은 검색 시간에 민감한 배치이며, 인과적인 패인 확정에는 실제 후속 대전·추가 분석이 필요합니다.

- [전체 검색 결과·상태·PV·시간·해시](native-diagnostics/v1/report.json)
- [다음 개선에 사용할 재검토 배치](../evaluation/fixtures/native54-search-review.json)
- [loss-11을 짧은 탐색 수까지 재생하는 기보](native-diagnostics/v1/cases/loss-11.json)

`cases/*.json`을 게임의 불러오기로 열면 해당 배치까지의 기보와 500ms 엔진의 선택을 재생할 수 있습니다. 재검토 배치 파일에는 짧은 수와 긴 검색 참고 수를 함께 저장했으며, 최적 수를 강제하는 테스트 정답으로 사용하지 않습니다. 모든 추출 자료는 노출된 개발 자료입니다.

## 실행과 검증

```powershell
npm run native:diagnose -- --out reports/native-diagnostics/my-review
```

기본값은 12개 배치, 500ms/3,000ms, 후속 1,500ms, 4코어입니다. `--positions`, `--short-ms`, `--long-ms`, `--branch-ms`, `--cores`, `--source`를 지정할 수 있습니다. 입력은 완료된 validation 기보만 허용합니다. 새 출력 폴더를 사용하고, 중단되었다면 같은 인자에 `--resume`을 붙입니다.

```powershell
npm run native:diagnose -- --verify --out reports/native-diagnostics/v1
```

기본값과 다른 배치 수로 만들었다면 검증 시 같은 `--positions`를 지정합니다. 검증은 입력 기보·소스·Native 바이너리·승인 자료의 해시, 시작 상태 재현, 검색 PV의 합법성, 정확한 종반 결과, 진단 분류와 재생 기보 파일 해시를 확인합니다. 시간에 제한된 Native 검색 점수를 정확한 해답처럼 재증명하지는 않습니다.

전체 앱 테스트 66개와 빌드를 통과했습니다. 새 테스트는 손상된 기보·차례·승패 기록 거부, 중복 없는 배치 추출, 독립 종반 계산, 휴리스틱 점수 차이를 증명으로 오인하지 않는 분류를 확인합니다.

## 남은 추천 우선순위

1. 이번 미로 재현 배치에서 연결 벽·긴 우회로·공격과 방어 시점 평가 개선.
2. 위험한 벽 분기를 먼저 읽고 더 깊게 탐색하도록 수 정렬·선택적 심화 개선.
3. 경로 계산·캐시·병렬 탐색 효율을 개선해 0.5초 계산량 확대.
4. 기존 Atlas 5.3과 진영 교환·새 미사용 배치 대전으로 실제 향상을 확인한 변경만 채택.
5. 강해진 탐색 엔진으로 지도 자료 품질을 높인 뒤 신경망 학습 재검토.
