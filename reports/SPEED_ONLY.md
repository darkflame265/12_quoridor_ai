# Atlas 5.3 판단 유지 최적화와 전체 탐색 비교

원본 Atlas 5.3을 보존한 채 별도 `speed-engine` 실행 파일을 만들었습니다. 이전 실험의 평가 모드·연결도 교정·가중치·깊이 보호를 포함하지 않습니다. 원래 규칙, 평가 함수, 수 점수, LMR, 반복 판정과 종반 해법을 그대로 사용합니다.

유일한 탐색 변경은 수 정렬의 거리 계산입니다. 양쪽 말의 최단 경로 하나씩을 구하고, 벽 후보가 해당 경로를 끊지 않으면 기존 거리를 재사용합니다. 경로를 끊는 벽은 기존 BFS로 계산합니다. 버전 표시는 식별을 위해 `5.3 speed`로 구분합니다. 원본 Native 소스와 실행 파일은 교체하지 않습니다.

## 같은 깊이 결과와 전체 탐색 계측

기존 개발 기보와 초기 상태에서 벽이 2개 이상 남은 93개 상태를 사용했습니다. 시간 예산을 10초로 충분히 주고 단일 코어·최대 깊이 2에서 비교한 결과, 완료 깊이·평가 점수·PV·탐색 노드 수가 모두 같았습니다. 양쪽 실행 순서를 번갈아 새 프로세스로 측정했습니다.

| 항목 | 원본 5.3 | 5.3 speed |
| --- | ---: | ---: |
| 고정 깊이 93개 상태 합산 시간 | 873.28ms | 555.36ms |
| 별도 12개 상태·500ms·4코어 총 노드 | 1,262,501 | 1,748,700 |
| 동일 시간 측정 평균 완료 깊이 | 5.83 | 6.25 |

고정 깊이 전체 탐색은 약 1.57배 처리량이었고, 동일 시간의 노드 수는 약 38.5% 늘었습니다. 후자는 탐색하는 깊이와 가지가 달라진 측정이며 승률 향상이나 통계적으로 확정된 속도 배율을 뜻하지 않습니다. 노드 수에는 끝내지 못한 반복 심화의 탐색도 포함될 수 있습니다.

기록에는 수별 깊이·노드·실측 시간·공유 캐시 적중 수·종반 해법 적중 수를 보존합니다. 공유 캐시 적중 수는 여러 캐시의 합계이며 전이표의 적중률이 아닙니다. 캐시 조회 횟수와 함수별 내부 시간은 아직 계측하지 않았습니다. 정확한 종반 해법의 별도 시간 예산이 결과 비교에 섞이지 않도록 벽 0~1개 상태는 고정 깊이 검사에서 제외하며 기존 Rust 종반 테스트를 수행합니다.

원본은 [고정 깊이·동일 시간 측정](speed65/benchmark.json)에 입력·소스·실행 파일 해시와 함께 저장했습니다.

## 비교 대전과 채택 기준

새 search65-v1 시드: 개발 651719, validation 428317, holdout 963541. 기존 Native v3·앞선 search 배치 및 분리 사이 중복 국면을 제외합니다. 같은 국면에서 진영을 바꿔 500ms·4코어·최대 180수로 대전합니다. 기보와 시간·노드·완료 깊이·캐시 지표를 저장하고 합법 수로 재검증합니다.

채택 기준은 대전 결과 확인 전에 `evaluation/speed-release-policy.mjs`에 고정했습니다. validation 100판과 별도 holdout 16판, 양쪽 승수 우위, 일반·미로 각각 승수≥패수, 전술 16개 통과, 후보 시간 초과 5% 미만, 동일 빌드·조건, 고정 깊이 결과 일치와 속도 개선이 모두 필요합니다. 통과가 확정적 초인 실력이나 통계적 우위를 뜻하지는 않습니다.

```powershell
node scripts/build-speed.mjs
node scripts/benchmark-speed.mjs reports/speed65/new-benchmark.json
node scripts/evaluate-speed.mjs --out reports/speed65/new-validation --split validation --pairs 25 --ms 500 --cores 4
node scripts/verify-speed.mjs reports/speed65/new-validation --save
```

출력은 새 경로를 사용합니다. 고정 깊이 측정은 개발 자료이며 대전용 미사용 국면과 구분합니다. 과거 보고서 해시 검증은 기록 당시 커밋에서 수행합니다.

## 최종 결과와 적용 판단

별도 validation **100판**을 끝까지 진행했습니다.

| 배치 | 승 | 패 | 무 |
| --- | ---: | ---: | ---: |
| 일반 | 28 | 22 | 0 |
| 미로 | 24 | 26 | 0 |
| 합계 | 52 | 48 | 0 |

전술 16개는 모두 통과했습니다. 미로 승수가 패수보다 적어 사전에 정한 배치별 비퇴보 기준에 미달했습니다. **실제 기본 엔진은 원본 Atlas 5.3을 유지**합니다. holdout 16판은 열지 않았습니다. 별도 실행 파일과 재현 도구는 후속 비교를 위한 후보로 남겼으며 기본 엔진에 적용됐다고 표시하지 않습니다.

52승 48패만으로 강화가 확인됐다고 볼 수 없습니다. 승패 표본의 단순 Wilson 95% 구간은 약 42.3~61.5%이며, 이 구간도 진영 교환 대전 사이의 상관관계를 반영하지 않으므로 참고용입니다. 계산 속도·탐색량 증가를 확인한 것과 실제 승률 개선을 확인한 것을 구분합니다. 이번 결과로 특정 평가 오류가 패배 원인이라고 단정할 수도 없습니다.

추가로 최대 깊이 3·단일 코어의 12개 상태에서도 점수·PV·노드 수가 원본과 같았습니다. [심화 검사](speed65/deep-proof.json), [100판 기보](speed65/validation/report.json), [배치별 결과·계측 요약](speed65/summary.json), [채택 판단](speed65/decision.json)을 보존했습니다.

speed-engine의 Rust 13개 테스트, 전체 Node 75개 테스트와 웹 빌드를 통과했습니다. 모든 시간 제한 대전과 속도 측정이 끝난 다음 테스트를 실행했습니다.

## 남은 추천 우선순위

1. 이번 미로 패배에서 단일 코어·다중 코어와 깊이별 선택을 비교해 평가 오류와 선택적 탐색 누락을 분리. 좋은 수의 근거가 되는 고정 사례 확보.
2. 전이표·수 정렬·평가별 조회 횟수와 시간 계측. 전체 경로 일치 조건을 제거하기 전에 반복 판정 정확성을 유지하는 설계 검증.
3. 위협 평가와 깊이 보호 개선을 원본 또는 같은 속도 후보 위에서 하나씩 비교. 새 배치의 충분한 대전으로 검증한 변경만 기본 엔진 반영.
4. 외부 엔진·숙련자 검증과, 검증된 엔진을 활용한 학습 재검토.
