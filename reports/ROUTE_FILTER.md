# 뒷순위 대응을 포함하는 경로 기반 후보 선별

2026-10-29. **기존 순위가 낮아도 최단 경로 초입을 건드리는 벽을 골라내는 선별기를 구현했습니다.** 안쪽 봉쇄의 참조 대응을 초기 84위에서 5위로 올렸고, 깊이 4의 선택 문제 3개를 해결했습니다. 하지만 5만 노드에서는 완료 깊이가 감소해 기본 원본 Atlas 5.3은 유지합니다. 실전 승률 향상이나 새 엔진 승격을 주장하지 않습니다.

## 구현한 선별 규칙

이전 경계 후보는 기존 16위 또는 24위까지에서만 수를 골랐습니다. 이번 `route-filter-engine`은 원래 순서와 별개로 **전체 합법 벽**에서 경로 특징을 검사합니다. 고정 좌표·기보 ID·색상을 조건으로 사용하지 않습니다.

- 양쪽 말의 목표 거리 맵을 한 번씩 계산합니다. 현재 위치에서 목표 쪽으로 한 칸씩 가까워지는 경로의 초입을 살펴봅니다.
- **exit**는 첫 한 걸음, **dag**는 첫 두 걸음에서 경로 간선을 막을 수 있는 벽에 점수를 줍니다. 상대 초입 간선의 가중치는 128, 자신의 것은 32이며, 한 단계 뒤의 가중치는 절반입니다. 이는 후보 우선순위이며 게임 평가 점수에 넣지 않습니다.
- 기존 1~4위는 유지합니다. 5~8위 네 수에, 기존 9위 이후에서도 경로 점수가 높은 벽을 최대 8개 추가합니다.
- 이 최대 12개에만 기존 한 수 뒤 평가를 적용해 재정렬합니다. 선택되지 않은 수를 삭제하지 않고 뒤에 원래 상대 순서로 둡니다. 따라서 합법 수 집합은 같습니다.
- 적용 범위는 `depth=3, ply=1`입니다. 평가 함수·LMR 규칙·벽 유효성 검사·루트 순서는 변경하지 않습니다.

경로 특징은 말을 장애물로 고정하지 않는 기존 벽 그래프의 목표 거리 맵을 사용합니다. 점프까지 반영한 완전한 전술 판정이 아니며, 경로 초입에 없는 준비 벽은 놓칠 수 있습니다. 선택 후의 평가는 기존 엔진과 같습니다. 먼저 선별을 한 뒤 평가하므로 모든 벽에 비싼 기존 평가를 적용하지 않습니다.

## 개발 검증 결과

기존 공개 개발 배치 5개를 사용했습니다. 안쪽 봉쇄의 잔여 벽 변형 3개와 3×3 공격·장문 각 1개입니다. 세 잔여 벽 변형은 같은 기하학이므로 독립적인 실력 표본 3개가 아닙니다. 이 사례를 알고 설계한 선별기이므로 미사용 검증 세트의 성과로 취급하지 않습니다.

|후보|깊이 4 선택 개선/악화|5만 노드 선택 개선/악화|5만 노드 완료 깊이 감소|
|---|---:|---:|---:|
|exit: 첫 한 걸음|3 / 0|0 / 0|3|
|dag: 첫 두 걸음|3 / 0|0 / 0|3|

안쪽 봉쇄의 계산량입니다.

|잔여 벽 조건|원본 깊이 4 노드|exit|dag|
|---|---:|---:|---:|
|균등 벽|48,508|51,353|51,357|
|공격자 벽 적음|48,508|51,353|51,357|
|수비자 벽 적음|48,508|51,352|51,356|

같은 깊이에서 원본 선택의 비축소 분기 값 차이는 8이었고 두 후보는 0입니다. 이전 전체 static 정렬의 약 51,560~51,666개보다 노드는 조금 줄었지만, 5만 노드 안에는 끝내지 못했습니다. 세 경우 모두 원본은 깊이 4, 후보는 깊이 3으로 끝났습니다.

균등 벽 사례의 exit는 **99회 선별 호출·828회 추가 평가·198회 목표 거리 맵 계산**, dag는 **99회 호출·1,174회 추가 평가·198회 목표 거리 맵 계산**을 사용했습니다. 관측한 한 호출의 최대 후보 수는 exit 11개, dag 12개입니다. 구현 상한은 둘 다 12개이며 목표 거리 맵 계산은 호출당 두 번입니다.

노드 수는 이 추가 평가·목표 거리 맵 계산까지 같은 CPU 작업량으로 세지 않습니다. 후보 수 제한과 선택 복구는 확인했지만 실제 시간 단축은 확인하지 않았습니다. 사전에 정한 후속 시간 비교 기준은 고정 깊이와 5만 노드에서 모두 개선이 있고 선택 값·완료 깊이 악화가 없는 것입니다. 두 후보 모두 미달해 새 0.5초·4코어 시험·대전은 실행하지 않았고 기본 엔진도 교체하지 않았습니다.

## 후보군 누락이 해결됐는지 별도 감사

별도 `ranks` 감사는 루트 수를 놓은 뒤 깊이 3 비축소 탐색으로 한 참조 대응을 구합니다. 루트의 반복 이력과 ply를 유지한 값이 기존 독립 분기 감사와 같은지 확인하고, history·killer·TT를 빼고 초기 정렬의 위치를 비교합니다. 표는 1부터 센 순위입니다.

|배치와 루트 수|참조 대응|원래 초기 순위|exit / dag 순위|전체 static 순위|
|---|---|---:|---:|---:|
|안쪽 봉쇄, `h(0,0)`|`v(3,2)`|84|5 / 5|5|
|안쪽 봉쇄, `h(0,1)`|`h(0,6)`|1|1 / 1|1|
|장문, 기존 루트 수|참조 대응|76|10 / 10|10|

이전 경계 후보가 후보군에 넣지 못한 84위 대응을 이번 두 선별기는 실제 평가 후보에 포함했습니다. 좌표는 결과를 설명하기 위한 것이며 알고리즘의 조건이 아닙니다. 감사의 `included`는 추가 평가 후보군에 속하는지 표시합니다. 원래 상위 4위 안의 수는 추가 평가 후보군에 없더라도 앞부분에 그대로 유지됩니다.

이 표는 초기 순위이며 실제 탐색 중 항상 같은 순서라는 뜻은 아닙니다. 참조는 기존 수작업 평가를 쓰는 제한 깊이 값입니다. 한 참조 대응의 순위 복구가 게임 전체의 승리나 인간 상대 강함을 증명하지 않습니다.

## 재현과 테스트

[측정 결과](filter74/report.json), [재검증](filter74/verification.json), [후보 포함·순위 감사](filter74/rank-audit.json), [순위 감사 재검증](filter74/rank-verification.json)에 소스·바이너리·원본 기록의 해시를 저장했습니다. 게임 엔진 소스·바이너리는 변경하지 않았고 후보는 별도 identity로 구분합니다.

- off/원본 깊이 3 점수·PV·노드 일치: 5개.
- 두 모드의 5만 노드 반복: 10쌍. 추가 평가 작업 수도 일치.
- 재검증: 후보 탐색 20개, 비축소 깊이 4 점수 일치 10개, 독립 분기 집합 5개.
- 순위 감사 재계산: 두 모드의 분기 총 16개, 대응 수의 합법성 검사.
- Node 테스트 93개, Rust 14개를 exit·dag 각각 실행, 웹 빌드 통과.

```powershell
npm run search:filter-build
# 새 결과 폴더 지정
npm run search:filter-check -- reports/my-filter-run
npm run search:filter-verify -- reports/my-filter-run
npm run search:filter-ranks -- reports/my-filter-run
npm run search:filter-ranks -- reports/my-filter-run --verify
```

기존 기록 검증에는 `reports/filter74`를 사용합니다. 기존 원본 native와 root-guard 비축소 감사 빌드가 필요하며, 없으면 `node scripts/build-native.mjs`, `node scripts/build-root-guard.mjs`로 준비하세요. 다른 바이너리 해시로 재빌드한 경우 새 결과 폴더를 사용합니다. 측정 결과는 덮어쓰지 않습니다.

## 남은 추천 우선순위

1. **선별된 대응에 필요한 분기만 재탐색**: 매 내부 노드에서 순서를 모두 바꾸기보다, 선별 정보와 축소 탐색 결과가 충돌하는 분기에만 계산을 추가합니다. 5만 노드에서 깊이 감소 없이 선택 개선을 얻는 것이 다음 기준입니다.
2. **선별·평가 계산 재사용**: 같은 벽 배치의 거리 맵과 후보 평가를 안전하게 재사용하고 실제 시간을 계측합니다. 노드 감소와 CPU 시간 감소를 구분합니다.
3. **다른 기하학의 준비 벽·공역·벽 소모전 검증**: 초입에 없는 벽과 점프·선후공·잔여 벽 조건의 반례를 추가해 선별 누락과 과적합을 확인합니다.
4. **0.5초·4코어 및 별도 대전 후 승격**: 개발 기준을 먼저 넘긴 후보만 실제 시간 비교·일반/미로 대전·미사용 검증 세트로 진행합니다.
5. **외부 실력 검증과 병목 계측**: 외부 엔진과 대전하고 BFS·평가·캐시·코어 대기의 비용을 나누어 확인합니다.
