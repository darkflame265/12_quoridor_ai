# 미로 패배의 깊이 보호·위협 후보 누락 분석

앞선 forcing 후보의 validation 미로 4패를 모두 합법 수로 재생해 후보가 행동한 81개 상태를 추출했습니다. 이번 작업은 추천 1순위였던 원인 후보의 분리 분석과 독립 검증 도구를 적용한 것입니다. 승률을 높인 새 알고리즘을 채택한 작업은 아닙니다.

## 확인된 차이

| 항목 | 결과 |
| --- | ---: |
| 깊이 보호 대상이 있는 상태 | 15 / 81 |
| 보호 대상이 4개를 넘는 상태 | 2 / 81 |
| 한 상태의 최대 보호 대상 | 7 |
| 4개 후보 평가가 놓친 위협 | 37 / 162 |
| 8개 후보 평가가 놓친 위협 | 25 / 162 |
| 누락된 최대 순수 우회 이득 | 5칸 |

위협 관측 수 162개는 81개 상태의 양쪽 진영을 각각 평가한 값입니다. 기준은 모든 최단 경로에 걸리는 합법 벽을 검사한 결과이며, 완전한 게임 탐색의 최적 수 증명은 아닙니다. 깊이 보호가 많아서 패배했다고 단정할 근거도 없습니다.

4개 후보에서 놓친 37개 관측 중 공격자 벽이 1개 남은 경우가 17개, 2개가 15개, 3개가 3개, 4개가 2개였습니다. 벽이 적게 남은 중후반의 위협 후보 선정을 우선 검토할 근거가 생겼습니다. 같은 패배 자료에 맞춘 수치는 개발용이며 새로운 검증 표본으로 취급하지 않습니다.

## 독립 검증한 사례

한 국면에서 4개·8개 후보 평가는 모두 위협 이득을 0으로 계산했지만, 실제로 순수 이득이 5칸인 합법 벽이 있었습니다. 이 상태를 [고정 사례](../evaluation/fixtures/forcing63-threat-gap.json)로 저장했습니다. Rust의 전체 최단 경로 후보 검사 결과와 별개로, JS 규칙에서 가능한 벽 128개를 전부 검사해 해당 벽의 합법성과 최대 이득 5칸을 확인하는 테스트를 추가했습니다.

이는 위협 후보 제한이 놓치는 실제 사례를 확인한 것입니다. 그 벽을 고르면 반드시 이긴다거나 이 누락 때문에 대국을 졌다는 뜻은 아닙니다. 깊이 보호만 늘리거나 후보 수를 4개에서 8개로 늘리는 변경으로 모든 누락이 해결되지는 않습니다.

전체 입력 기보·상태·기존 행동·완료 깊이·노드 수·보호 대상·양쪽 위협 값은 [분석 원본](forcing63/analysis.json)에 해시와 함께 보존했습니다. 상태 복원도 확인했습니다. 기존 대전 자료는 당시 커밋에서 원래 검증을 수행해야 합니다.

## 재현

```powershell
npm run maze:build
node scripts/analyze-forcing-losses.mjs reports/forcing63/new-analysis.json
npm test
```

출력은 새 파일을 사용합니다. 분석 도구는 forcing62 validation의 미로 패배만 사용하고 각 기보 해시·합법 수·추적 기록·최종 결과를 확인합니다. 실행 파일과 분석 스크립트의 해시도 기록합니다.

실제 기본 엔진은 **Atlas 5.3을 유지**합니다. 새 대전·학습·기본 엔진 교체는 하지 않았습니다.

Rust 25개·Node 71개 테스트, 웹 빌드와 기본 엔진 진단 기록 재검증을 통과했습니다.

## 남은 추천 우선순위

1. 벽이 적게 남은 중후반의 위협 후보 선택 개선. 실제 우회 이득을 놓친 고정 사례를 해결하면서 계산 비용을 제한하는 방식 비교.
2. 깊이 보호 범위를 좁힌 후보와 위협 평가 개선 후보를 각각 대전해 효과 분리.
3. 미사용 validation·holdout, 외부 엔진 대전을 통과한 후보만 기본 엔진에 반영.
4. 검증된 엔진을 활용한 지도 자료 생성과 GPU 학습 재검토.
