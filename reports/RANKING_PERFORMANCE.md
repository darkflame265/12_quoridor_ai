# 수 정렬의 중복 경로 탐색 제거

실험 엔진에서 가상 벽 후보마다 수행하던 거리 BFS를 줄였습니다. 양쪽 말의 최단 경로를 하나씩 구한 뒤, 후보 벽이 그 경로를 끊지 않으면 기존 거리를 재사용합니다. 벽 추가로 거리는 짧아질 수 없고 기존 최단 경로가 남아 있으므로 결과는 정확히 같습니다. 경로를 끊는 벽은 기존 BFS로 다시 계산합니다.

경로와 벽의 교차 마스크는 수 정렬 호출마다 생성합니다. 벽을 둘 수 없는 차례에는 기존 거리 계산을 유지해 불필요한 경로 마스크 생성을 피합니다. 말의 점프를 반영하는 거리 계산에는 이 생략 규칙을 적용하지 않습니다. 기존 수 점수·순서·동점 처리와 탐색 깊이는 유지합니다.

## 검증 결과

- 기존 패배 기록 167개, 추가 미로 4개, 초기 국면 1개로 총 172개 국면을 확인했습니다.
- 연결도 적용 범위 5가지에서 각각 **수 8,729개의 정렬 결과가 기존 구현과 동일**했습니다.
- 각 범위에서 벽 배치 후 양쪽 거리 **17,240개**를 기존 BFS와 직접 비교했습니다. 이 중 **14,644개(약 85%)**의 BFS를 생략할 수 있었으며 결과는 모두 같았습니다. 배치 시 통로가 끊기는 후보도 거리 비교에 포함했습니다.
- 별도로 자동 생성한 합법 대국의 60개 상태에서 경로 거리와 벽 후보를 대조하고, 가상 수 취소 후 상태가 복원되는지 확인했습니다.

동일 실행 파일 안에 보존한 기존 정렬 구현과 최적화 구현을 비교했습니다. 매 측정마다 검색 캐시를 새로 만들고 실행 순서를 번갈아 7회 측정했습니다. 두 번의 독립 측정 결과는 다음과 같습니다.

| 연결도 범위 | 첫 측정 처리량 | 재측정 처리량 |
| --- | ---: | ---: |
| legacy | 3.04배 | 3.36배 |
| rank-only | 3.05배 | 3.21배 |
| eval-only | 3.28배 | 2.71배 |
| rank-eval | 3.26배 | 3.05배 |
| physical | 3.38배 | 3.43배 |

이는 **수 정렬 구간의 측정**이며 전체 탐색이나 승률이 같은 비율로 좋아졌다는 뜻은 아닙니다. 원본은 [첫 측정](ranking61/profile.json), [재측정](ranking61/confirmation.json)에 입력·소스·실행 파일 해시와 함께 저장했습니다.

Rust 24개·Node 70개 테스트, 웹 빌드와 기본 엔진 진단 자료 재검증을 통과했습니다. 실제 기본 엔진은 Atlas 5.3을 유지합니다. 이번 최적화는 별도 실험 엔진의 legacy 및 추가 정렬 모드에 적용됐습니다. 기존 실패 후보를 기본 엔진으로 바꾸지 않았습니다. 과거 대전 자료의 해시 검증은 당시 커밋에서 수행해야 합니다.

## 재현

```powershell
npm run maze:build
node scripts/profile-ranking.mjs reports/ranking61/new-run.json
```

새 출력 파일을 사용합니다. 원본 구현은 빌드 시 원래 Native 정렬 함수로부터 생성하므로 두 구현의 비교가 같은 컴파일 조건에서 이루어집니다. 측정 중 다른 대전·테스트는 실행하지 않습니다.

## 남은 추천 우선순위

1. 패배 국면에서 강제 수 누락을 분석하고 탐색 깊이·위협 후보 범위 개선.
2. 최적화 후보의 전체 탐색량·시간 준수와 500ms·4코어 대전 검증. 미사용 validation·holdout을 통과한 경우에만 기본 엔진 반영.
3. 외부 엔진·숙련자 대전으로 실제 강도 검증.
4. 검증된 엔진을 활용한 지도 자료 생성과 GPU 학습 재검토.
