# 연결도 정렬 계수와 위협 후보 가중치 분리 조정

교정 연결도의 적용 위치를 분리한 뒤, 이번에는 수 정렬 계수와 평가 내부의 위협 후보 선택 가중치를 독립적으로 바꿀 수 있게 했습니다. 원본 Atlas 5.3과 기존 WASM·JS 엔진은 보존하고 별도 후보 `Atlas 5.9 experiment`에서 비교합니다.

## 서로 다른 두 계수

- 정렬 계수는 벽을 읽는 순서에 사용하는 `연결도 × 계수` 항입니다. 기본값은 180입니다.
- 위협 가중치는 최단 경로 위의 벽 후보 중 실제 우회 거리를 검사할 후보 4개를 고르는 순위에 사용합니다. 기본값은 30입니다. 정적 평가의 최종 위협 점수 배율을 바꾸는 항은 아닙니다.

모든 비교는 `cache4`, `--search legacy`, `--geometry rank-eval`로 고정합니다. 깊이 보호나 벽 자원 보너스를 함께 튜닝하지 않습니다. 네 조합은 대전 전에 고정한 2×2 비교입니다.

| 이름 | 정렬 계수 | 위협 후보 가중치 | 확인할 효과 |
| --- | ---: | ---: | --- |
| default | 180 | 30 | 기존 계수 대조군 |
| order90 | 90 | 30 | 정렬 영향만 절반으로 |
| threat0 | 180 | 0 | 위협 후보 선택에서 연결도 편향 제거 |
| combined | 90 | 0 | 두 변경의 결합 |

0은 해당 연결도 항의 영향을 없애는 비교입니다. 위협 평가나 벽 검색 자체를 끄지 않습니다. 실제 우회 거리 계산과 모든 합법 수는 계속 사용합니다.

## 실제 함수 출력 검증

컴파일한 Rust 실행 파일을 각 계수로 실행해 노출된 합법 상태 167개와 합법 수 8,332개의 점수를 확인했습니다.

- 정렬 계수만 바꾸면 정적 평가 점수는 유지됩니다.
- 위협 가중치만 바꾸면 같은 상태의 수 정렬 점수는 유지됩니다.
- 정렬 점수 차이는 독립 선분 계산의 접촉 개수에 계수 차이를 곱한 값과 일치합니다.
- 기본 180·30의 정적 평가 점수는 이전 버전과 모두 같습니다.
- 위협 가중치 30을 0으로 바꾸면 167개 중 24개 상태의 캐시 평가 점수가 달라집니다.

동일 상태에서의 출력 분리 검사이며, 실제 대국의 검색 트리나 첫 수가 같다는 뜻은 아닙니다. Rust와 CLI에서 정수·허용 범위를 검증하고, validation과 holdout의 두 계수가 다르면 채택을 거부합니다.

- [점수·합법 수·입력·바이너리 검증](weights59/weight-proof.json)

## 새 배치와 실행

새 `search59-v1` 시드는 개발 517873, validation 962431, holdout 328619입니다. 이전 Native v3, search55~58, 새 분리 사이의 중복을 제외합니다. 이미 사용한 자료를 다시 미사용으로 취급하지 않습니다.

```powershell
npm run maze:build
npm run maze:check-weights -- reports/weights59/my-proof.json
npm run maze:compare-weights -- reports/weights59/my-comparison
node scripts/verify-weights.mjs reports/weights59/my-comparison
```

새 출력 경로를 사용합니다. 각 조합은 동일한 일반·미로 개발 배치에서 진영을 교환해 4판씩, 기존 Atlas 5.3과 수당 500ms·4코어·최대 180수로 대전합니다. 조합의 개수나 계수는 대전 도중에 바꾸지 않습니다.

```powershell
npm run maze:evaluate -- --out reports/weights59/my-validation --mode cache4 --search legacy --geometry rank-eval --order-weight 90 --threat-weight 0 --cohort search59-v1 --split validation --pairs 3
```

정렬 계수 허용 범위는 0~720, 위협 후보 가중치는 0~120의 정수입니다. 해당 범위는 실험 입력 검증용이며 그 안의 값이 모두 좋은 후보라는 뜻은 아닙니다. 프로세스마다 계수를 고정하고 캐시를 다른 계수와 공유하지 않습니다.

현재 보고서 형식은 계수를 명시한 v5입니다. 과거 결과의 해시 재검증에는 기록된 커밋의 소스·바이너리가 필요합니다. 새 계수의 결과를 이전 계수와 섞어 승격하지 않습니다.

## 실제 대전 결과와 적용 판단

모든 대전은 기존 Atlas 5.3을 상대로 500ms·4코어·최대 180수 조건에서 진행했습니다.

| 개발 조합 | 일반 | 미로 | 합계 |
| --- | --- | --- | --- |
| default | 1승 1패 | 0승 2패 | 1승 3패 |
| order90 | 1승 1패 | 1승 1패 | 2승 2패 |
| threat0 | 1승 1패 | 2승 0패 | 3승 1패 |
| combined | 1승 1패 | 1승 1패 | 2승 2패 |

개발 결과로 선택한 threat0(180·0)는 별도 validation 12판에서 **5승 7패**였습니다. 승수 우위 기준을 충족하지 못해 채택하지 않았습니다. holdout은 열지 않았으며 실제 기본 엔진은 Atlas 5.3을 유지합니다. 개발 4판의 우위가 독립 검증에서 재현되지 않았으므로 강화 성공으로 해석하지 않습니다.

Rust 테스트 23개, Node 테스트 70개와 웹 빌드, 대전 기록 재검증으로 구현을 확인합니다. 결과 원본은 [개발 비교](weights59/comparison.json), [별도 검증](weights59/threat0-validation/report.json), [채택 판단](weights59/decision.json)에 있습니다.

## 남은 추천 우선순위

1. 정렬·평가 비용을 프로파일링하고 캐시·중복 경로 계산을 최적화해 같은 시간의 탐색량 확대.
2. 패배 국면에서 실제 강제 수에 맞춘 깊이 보호와 위협 후보 선택 범위 검증.
3. 새 후보를 미사용 validation·holdout 및 외부 엔진으로 검증하고 통과할 때만 기본 엔진 교체.
4. 검증된 엔진으로 신경망 지도 자료 생성과 GPU 학습 재검토.
