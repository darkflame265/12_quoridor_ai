# 실행 버전 혼용 방지와 추천 이력

## 동작

- 실행기는 앱·서버·엔진 소스와 빌드 매니페스트의 지문을 비교한다. 현재 서버와 같으면 재사용하고, 다르거나 지문이 없는 이전 서버면 인증된 종료 경로로 닫고 새로 준비한다.
- 갱신할 때 같은 로컬 포트를 유지한다. 브라우저 localStorage의 기보는 같은 출처에 남는다. 현재 탭은 새로고침해야 하고 화면 공유는 다시 연결해야 한다.
- `npm run play -- --restart`로 명시적으로 재시작할 수도 있다. 개발 서버는 이미 실행 중인 안정 서비스 때문에 다른 실험 엔진 준비를 생략하지 않는다. 다른 프로세스가 점유한 개발 포트의 구버전 서비스는 종료하지 않고 오류로 알린다.
- 브라우저는 실제 서비스 ID, 버전, 빌드가 번들의 요구와 일치해야 추천을 받는다. 검증된 빌드 없이 만든 번들도 실패하도록 처리한다. 서비스는 요청의 빌드 요구가 다르면 검색 전에 409로 거절한다.
- 즉시압박 0.2와 벽 투자 0.3은 서로 다른 엔드포인트와 ID를 사용하며 다른 엔진으로 자동 대체하지 않는다. 기본 5.3은 유지한다.
- 추천에 현재 전체 수 번호·진영·계산 중/완료를 표시한다. 추천 수가 바뀌거나 완료 상태가 바뀐 이력은 보존한다. 실제 착수가 최신 추천과 달라도 앞선 중간 추천과 일치하는지 JSON에 남긴다. 이는 사용자가 그 추천을 보고 뒀다는 인과관계 증명은 아니다.

## 검증

- `check.json`: 격리된 구버전 서버 → 자동 갱신, 같은 출처 유지, 최신 서버 재사용, 강제 재시작 확인. 구버전 개발·사용자 프로세스를 테스트 대상으로 중단하지 않는다.
- Node 149개 및 Rust 18개 통과.
- 브라우저 48개 통과. 실제 Native 0.2·0.3 추천과 기보 빌드 저장, 구버전 0.1 서버 응답 시 추천 차단을 확인했다. 화면 인식 영상은 합성 공유 영상이다.
- `pressure-check.json`: 기본 압박 기능의 비활성 제어군 원본 일치 6건, 벽 지표 743건, 전술 16건, 취소 후 재사용 확인.

실제 사용 중 서버의 갱신 결과는 `live.json`으로 별도 확인한다. 사용자 서버의 인증 토큰은 보고서에 보관하지 않는다.
