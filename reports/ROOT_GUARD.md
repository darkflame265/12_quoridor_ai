# 루트 보호와 실제 전술 수 보호의 분리 비교

벽 개수에 따른 분기를 추가하지 않고 두 후보를 사전에 고정했습니다. 평가 함수·수 점수·반복 판정·종반 해법은 원본 5.3과 같고, 경로 계산 최적화는 5.3 speed와 같습니다.

- **root**: 루트에서만 깊이 3·4의 뒤쪽 수를 축소하지 않습니다. 내부 노드의 기존 LMR은 유지합니다.
- **tactical**: 루트에서 상대가 한 수로 승리할 수 있으면 이를 막는 모든 합법 수를 보호합니다. 그렇지 않으면 전체 최단 경로 위협 검사에서 순수 이득이 양수인 최우선 벽 하나만 보호합니다. 이 벽은 기하학적 이득 추정이며 강제 승리의 증명은 아닙니다. 내부 LMR은 유지합니다.

검증용 **off**는 기존 speed와 같아야 하며 **full**은 LMR을 끈 참조입니다. 두 검증 모드는 대전 후보로 허용하지 않습니다. 상대의 즉시 승리가 있는 위치에서는 생존 대응만 보호하고, 생존하지 못하는 공격 벽을 보호 대상으로 추가하지 않습니다.

## 고정 사례와 분기별 값

12개 기존 상태에서 off와 기존 선택적 탐색의 점수·PV·노드 일치 24회, full과 기존 비축소 참조 일치 24회를 확인했습니다. root는 깊이 3의 12개 결과를 모두 회복했습니다. 양쪽 색의 즉시 패배 위기에서 합법 수 262개를 별도 JS 이동 규칙과 대조해 tactical의 보호 집합이 생존 대응 집합과 정확히 일치하는지 확인했습니다.

이번에는 보고된 루트 점수만 비교하지 않고, 각 방식이 선택한 수를 직접 둔 뒤 같은 깊이의 비축소 탐색으로 해당 분기 값을 다시 계산했습니다. 실제 검색 경로에 원래 루트 위치를 포함하고 ply를 1부터 세므로, 단순히 자식 위치를 새 게임처럼 분석하는 방식과 구분됩니다.

| 참조보다 낮은 분기 값을 선택한 상태 | root | tactical |
| --- | ---: | ---: |
| 깊이 3 | 0 / 12 | 2 / 12 |
| 깊이 4 | 1 / 12 | 2 / 12 |

예를 들어 maze-7의 깊이 4에서 기존 선택적 탐색은 -528점으로 보고한 벽을 선택했지만, 그 분기의 비축소 값은 -852였습니다. 참조 최선은 말 이동의 -681이어서 같은 깊이 기준으로 171점의 선택 차이가 있었습니다. root 후보는 이 말 이동을 선택했습니다. 반면 maze-1의 98점 선택 차이는 두 후보 모두 남았습니다. 게임 승패의 증명이나 실제 승률 개선으로 해석하지 않습니다.

수당 500ms·4코어의 별도 측정에서 평균 완료 깊이는 speed 4.67, root 4.75, tactical 4.67이었습니다. 같은 작은 표본의 측정이며 노드 수·명목 깊이만으로 강함을 판단하지 않습니다. [원본 검증·분기 자료](root69/proof.json)를 보존했습니다.

## 개발 선택과 다음 단계 기준

새 search69-v1 시드: 개발 693271, validation 478139, holdout 927653. 기존 시작 국면과 분리 사이 중복을 제외합니다. root·tactical 각각 동일한 개발 시작 국면에서 진영을 바꿔 5.3 speed와 12판씩, 500ms·4코어·최대 180수로 비교합니다.

고정 검사·전술·시간·전체 승수 우위·일반/미로 각각 승수≥패수를 통과한 후보만 선택합니다. 복수 통과 시 승수−패수, 승수 순으로 비교하고 동률이면 root를 선택합니다. 개발 선택은 소표본의 탐색적 선택입니다. 통과 후보만 원본 5.3 상대 새 validation 100판으로 진행하고, 통과 시 별도 holdout 16판을 수행합니다. 두 분리의 전체 승수 우위·배치별 비퇴보·전술·시간·동일 후보 조건을 만족해야 기본 엔진 교체 대상입니다.

```powershell
node scripts/build-root-guard.mjs
node scripts/check-root-guard.mjs reports/root69/new-proof.json
node scripts/evaluate-root-guard.mjs --out reports/root69/new-root --mode root --split development --pairs 3 --baseline speed --ms 500 --cores 4
node scripts/evaluate-root-guard.mjs --out reports/root69/new-tactical --mode tactical --split development --pairs 3 --baseline speed --ms 500 --cores 4
node scripts/assess-root-guard.mjs reports/root69/new-root reports/root69/new-tactical reports/root69/new-proof.json reports/root69/new-selection.json
```

출력은 새 경로를 사용합니다. 기존 고정 사례는 개발 자료이며, 이전 보고서의 소스 해시는 당시 커밋에서 검증합니다.

## 실제 비교 결과와 채택 판단

| 단계·상대 | 일반 | 미로 | 합계 |
| --- | --- | --- | --- |
| root 개발 · 5.3 speed | 3승 3패 | 4승 2패 | 7승 5패 |
| tactical 개발 · 5.3 speed | 4승 2패 | 3승 3패 | 7승 5패 |
| 선택한 root의 별도 validation · 원본 5.3 | 23승 27패 | 22승 27패 1무 | 45승 54패 1무 |

두 후보의 개발 조건이 모두 통과했고 사전에 정한 동률 기준으로 root를 선택했습니다. 별도 100판에서는 전체 승수 우위와 배치별 비퇴보 기준에 미달했습니다. **실제 기본 엔진은 원본 Atlas 5.3을 유지**하며 holdout 16판은 사용하지 않았습니다. 개발과 validation은 상대·국면이 다르고 소표본 개발 선택에는 불확실성이 있으므로 개발 승률을 강화 증명으로 사용하지 않습니다.

validation 전술 16개는 모두 통과했고 시간 초과는 0회였습니다. 고정 깊이의 선택 차이를 줄이는 것과 시간 제한 대전의 승률을 높이는 것은 별개라는 결과로 기록합니다. 실패 원인이 반드시 평가 함수나 특정 가지치기 하나라고 단정하지 않습니다.

선택된 수의 점수 자체도 별도 확인했습니다. root 후보의 깊이 4에서 비축소 분기 값보다 높은 점수를 보고한 상태는 3개였고, 차이는 106·81·60점이었습니다. 세 상태 중 실제 선택이 참조보다 낮은 경우는 1개였습니다. [분기 값 요약과 상태](root69/branch-summary.json)에 보존했습니다. 다음에는 루트 보호 범위를 다시 넓히기보다 이 과대평가가 발생하는 내부 분기를 추적하는 것이 우선입니다.

원본은 [개발 선택](root69/selection.json), [100판 기보](root69/validation/report.json), [validation 요약](root69/validation-summary.json), [채택 판단](root69/release-decision.json)에 저장했습니다. 채택 판단의 통합 검사에는 미사용 holdout이 없어 거짓인 항목이 있으며, validation만의 조건은 `validationChecks`에 따로 기록합니다.

## 남은 추천 우선순위

Rust 14개·Node 85개 테스트, 웹 빌드와 개발 24판·validation 100판의 기보 재검증을 통과했습니다. 모든 시간 제한 비교와 대전이 끝난 후 테스트를 실행했습니다. 검사한 실행 파일의 식별자는 고정 검사·개발·validation 기록과 모두 일치합니다.

1. 남은 3개 과대평가 사례의 주요 변화(PV)와 상대 대응 분기를 추적해 필요한 재검증만 수행하는 후보 설계.
2. 수작업 평가의 위협 누락·벽 자원·우회로 취약성 보강을 탐색 변경과 분리 비교.
3. 캐시·평가 시간 계측으로 전술 확인 비용을 확보하고 새 국면·holdout·외부 상대 검증 후 채택.
