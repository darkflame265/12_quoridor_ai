# 얕은 깊이와 루트의 LMR 보완 후보

진단에서 확인한 깊이 3·4의 차이를 해결하기 위해 별도 `5.3 guard` 후보를 구현했습니다. 수 정렬의 경로 계산 최적화는 5.3 speed와 같고 평가 함수·벽 후보·수 점수·반복 판정·종반 해법도 유지합니다.

변경은 LMR 허용 깊이뿐입니다. 내부 노드는 기존 깊이 3부터 대신 **깊이 4부터**, 루트 수는 **깊이 5부터** 뒤쪽 수의 깊이를 축소합니다. 기존의 순서·연결 벽·보호 수·재탐색 예외 조건은 그대로 유지합니다. LMR을 모든 깊이에서 끄는 모드는 아닙니다.

## 고정 사례와 비용

기존 진단 12개 상태의 깊이 3·4, 총 24회 검사에서 점수·PV·노드 수가 비축소 참조와 모두 일치했습니다. 말 이동 대신 벽을 선택하며 -378 대신 -272점으로 평가하는 고정 사례도 해결했습니다. 이는 같은 평가 함수의 고정 깊이 참조와 일치한다는 뜻이며 게임 전체의 최적 수를 증명하지 않습니다.

별도로 같은 12개 상태에서 수당 500ms·4코어로 5.3 speed와 비교했습니다. 평균 완료 깊이는 speed 4.67, guard 4.42였습니다. 총 탐색 노드는 각각 1,301,303 / 1,504,689였습니다. 축소 규칙이 달라 같은 명목 깊이도 탐색 범위가 다르므로 노드 수 증가를 속도 증가로 해석하지 않습니다. 깊이를 줄이지 않는 만큼 실제 탐색 비용이 늘 수 있습니다.

[검증 원본](guard67/proof.json)에 입력·두 실행 파일 식별자·실제 검색 결과를 보존했습니다.

## 효과 분리와 단계별 검증

새 search67-v1 배치의 시드는 개발 672913, validation 539827, holdout 184963입니다. 기존 배치 및 분리 사이 중복 국면을 제외합니다. 첫 개발 비교는 **동일한 속도 최적화가 들어간 5.3 speed**를 상대하므로 LMR 변경의 효과를 분리합니다.

개발 12판에서 전체 승수 우위, 일반·미로 각각 승수≥패수, 전술 16개, 시간 초과 5% 미만, 동일 빌드·조건과 고정 참조 일치를 모두 만족할 때만 별도 validation으로 진행합니다. 실제 기본 엔진 교체에는 이후 원본 5.3 상대의 별도 100판 및 holdout 검증이 필요합니다. 개발 결과를 본 뒤 조건을 바꾸지 않습니다.

```powershell
node scripts/build-guard.mjs
node scripts/check-guard.mjs reports/guard67/new-proof.json
node scripts/evaluate-guard.mjs --out reports/guard67/new-development --split development --pairs 3 --baseline speed --ms 500 --cores 4
node scripts/verify-guard.mjs reports/guard67/new-development --save
```

각 출력은 새 파일·폴더를 사용합니다. 고정 사례는 이미 노출된 개발 자료이며 미사용 승률 검증 자료와 구분합니다. 과거 보고서는 해당 커밋에서 해시를 검증합니다.

## 대전 결과와 적용 판단

수당 500ms·4코어·최대 180수로 새 국면에서 진영을 교환해 **5.3 speed 상대 12판**을 진행했습니다.

| 배치 | 승 | 패 | 무 |
| --- | ---: | ---: | ---: |
| 일반 | 1 | 5 | 0 |
| 미로 | 4 | 2 | 0 |
| 합계 | 5 | 7 | 0 |

전체 승수 우위와 배치별 비퇴보 기준을 통과하지 못해 별도 validation·holdout은 사용하지 않았습니다. **실제 기본 엔진은 원본 Atlas 5.3을 유지**합니다. 고정 깊이의 정확한 참조 결과와 일치하도록 만든 후보지만, 현재 시간 제한에서 실제 강화가 확인된 것은 아닙니다. 미로의 4승 2패도 소표본이므로 우위 확정으로 해석하지 않습니다.

이 결과는 전 구간에서 보수적으로 축소하는 방식보다 미로·전술 상황으로 적용 범위를 좁히는 후속 후보를 비교할 근거입니다. 일반 패배가 반드시 초반 계산 비용 때문이라는 인과관계는 아직 확인하지 않았습니다. [개발 기보](guard67/development/report.json), [계측 요약](guard67/summary.json), [판단 기록](guard67/decision.json)을 보존했습니다.

## 남은 추천 우선순위

Rust 14개·Node 79개 테스트, 웹 빌드와 개발 12판 기보 재검증을 통과했습니다. 전술 16개와 시간 제한 검사도 통과했습니다.

1. 보호 범위를 벽이 많은 미로 또는 실제 전술 상황으로 제한한 후보를 별도로 비교. 일반 배치의 성적을 유지하는지 새 국면에서 확인.
2. 깊이 축소 때문에 달라진 수를 분기별로 재평가해 필요한 보호와 과도한 보호를 구분.
3. 위협 평가 개선을 따로 비교하고, 개발을 통과한 후보에만 원본 5.3 상대 100판·별도 holdout 수행.
4. 외부 엔진·숙련자 검증과 캐시·평가 비용 계측.
