# 벽이 적게 남은 미로의 위협 누락 보완

새 실험 평가 모드 `--mode late-full`을 추가했습니다. 미로 벽이 8개 이상이고 공격자에게 벽이 1~3개 남았다면, 기존 상위 4개 후보 제한 대신 모든 최단 경로에 걸리는 합법 벽의 우회 이득을 확인합니다. 그 외에는 기존 cache4 평가를 유지합니다. 벽 자원 점수·수 정렬·LMR 깊이 보호는 바꾸지 않았습니다.

공격자 벽 1~3개라는 범위는 앞선 개발 분석에서 누락 37개 중 35개가 발생한 범위입니다. 이는 개발 자료에 기반한 후보 설계이며, 같은 자료를 독립 성능 검증으로 사용하지 않습니다. 모든 합법 벽이나 게임 트리를 완전 탐색하는 모드는 아닙니다.

## 누락 해결과 비용

이전 미로 4패의 81개 상태·양쪽 진영 162개 관측을 다시 확인했습니다.

- 위협 누락: 37개 → 2개.
- 기존 4개·8개 후보가 놓쳤던 순수 이득 5칸 사례를 해결했습니다.
- 남은 두 누락은 범위 밖인 공격자 벽 4개 상태입니다. 최대 차이는 3칸입니다.
- Rust의 고정 사례 검사와 JS의 전체 합법 벽 검사를 유지했습니다.

81개 상태를 50회 평가한 한 번의 측정에서 cache4는 9,128µs, late-full은 12,201µs였습니다. 개별 평가 비용이 약 34% 늘어났습니다. 이는 캐시가 채워진 정적 평가 구간의 측정이며 전체 탐색 속도나 승률 수치는 아닙니다. 원본 점수·소스·입력·실행 파일 해시는 [검증 기록](late64/proof.json)에 있습니다.

## 재현

```powershell
npm run maze:build
node scripts/check-late-threats.mjs reports/late64/new-proof.json
npm run maze:evaluate -- --out reports/late64/new-development --mode late-full --search legacy --geometry legacy --order-weight 180 --threat-weight 30 --cohort search64-v1 --split development --pairs 1 --ms 500 --cores 4 --max-plies 180
```

새 출력 경로를 사용합니다. search64-v1은 개발 649183, validation 375821, holdout 918463 시드이며 앞선 Native v3와 search55~62 배치 및 분리 사이 중복 국면을 제외합니다. 평가 개선만 분리해서 확인하기 위해 search forcing은 사용하지 않습니다.

## 남은 추천 우선순위

1. 전체 위협 검사 구간의 후보 집합·거리 맵 재사용으로 비용 절감. 누락 해결과 탐색량을 함께 유지하는 방식 검증.
2. 비용을 줄인 위협 평가와 깊이 보호 범위를 각각 독립 비교.
3. 미사용 validation·holdout, 외부 엔진 대전을 통과한 후보만 기본 엔진 반영.
4. 검증된 엔진을 활용한 지도 자료 생성과 GPU 학습 재검토.

## 대전 결과와 적용 판단

새 개발 배치에서 기존 Atlas 5.3과 수당 500ms·4코어·최대 180수로 대전했습니다. 일반 1승 1패, 미로 0승 2패로 합계 **1승 3패**였습니다. 전술 16개는 통과했고 후보의 시간 초과는 0회였습니다.

위협 누락을 해결했지만 이번 소표본 대전에서는 개선 신호를 얻지 못했습니다. 비용 증가가 패배 원인이라는 인과관계까지 확인한 것은 아닙니다. 추가 validation·holdout은 사용하지 않고 **실제 기본 엔진은 Atlas 5.3을 유지**합니다. 후보는 후속 비용 개선과 비교를 위해 실험 모드로 남깁니다. [개발 기보](late64/development/report.json), [채택 판단](late64/decision.json)을 보존했습니다.

Rust 26개·Node 71개 테스트, 웹 빌드와 대전 기보 재검증으로 구현을 확인했습니다. 과거 대전 자료는 당시 커밋에서 해시를 검증해야 합니다.
