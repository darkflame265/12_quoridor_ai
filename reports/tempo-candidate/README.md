# 벽 투자 0.3 실험

## 변경

0.2의 즉시압박·보유 벽 실효성 보정을 유지하면서, 양쪽에 벽이 남은 초중반에 다음 조건을 만족하는 준비 벽에만 작은 루트 비용 16점을 추가한다.

- 즉시 상대·자기 최단거리 변화가 모두 0이고 가까운 최단 경로를 끊지 않는다.
- 내 벽이 최소 2개이며, 이어서 놓을 수 있는 합법 벽으로 설치 2턴의 비용을 회수할 가능성을 찾지 못했다.
- 설치 후 상대의 최대 즉시 공격 이득을 줄이지도 못했다.

후속 벽 검사는 상대가 멈춘 낙관적 조건이므로 전술 예측이나 강제 승패 판정이 아니다. 낙관적 조건에서도 투자 회수가 불가능할 때만 비용을 준다. 연결 준비가 가능한 벽, 방어 효과가 있는 벽, 직접 상대를 늦추는 벽은 이 비용을 받지 않는다. 강제 승패 점수는 변경하지 않는다.

루트 계산은 남은 시간의 15%, 최대 60ms를 사용한다. 검사를 완료하지 못하면 일부 벽만 불리하게 만들지 않고 전체 보정을 취소한다. 기존 0.2 서비스는 플래그를 명시적으로 꺼서 동작을 유지한다. 0.3은 별도 선택인 `atlas-tempo`, `/api/tempo`에서만 활성화한다. 기본 5.3을 승격·교체하지 않았다.

## 검증 결과

- 사용자 2번째 패배 기보 중 5개 위치를 개발 회귀 사례로 추가했다. 전체 기보·과거 경기·타임스탬프·상대 식별 정보는 추가하지 않았다.
- 첫 8경기는 0.2 대비 5승 3패: 일반 3승 1패, 미로 2승 2패. 이 단계 바이너리는 후보 플래그로 구분하고 출력 이름은 아직 0.2였다. 준비 벽 보정과 별도 서비스 배포 전의 개발 검증이다.
- 출력 이름을 0.3으로 구분한 실제 배포 빌드에서 다른 시드로 4경기를 추가 확인했다. 3승 1패: 일반 2승, 미로 1승 1패. 알고리즘은 같은 준비 벽 비용이며 첫 단계와 빌드 식별자는 다르다. 원시 보고서를 각각 보존한다.
- 두 단계 모두 500ms·4코어, 같은 바이너리의 보정 비활성 0.2와 비교했다. 모든 행동과 전체 기보 재현을 검증했고 전술 16건도 각 단계에서 통과했다.
- 15수 전 위치에서는 0.2의 원거리 벽 대신 이동을 고르는 사례가 확인됐다. 모든 패착을 해결했거나 사용자 경기를 이길 것이라는 의미는 아니다.
- 새 시드의 개발 배치이며 공식 홀드아웃이 아니다. 전체 12경기 8승 4패는 인간 상대 실력이나 확정적인 개선의 증거로 부족하다. 비교 실험을 위한 선택 기능으로 제공한다.

## 남은 순서

1. 0.3으로 실제 대국을 진행하고 저장한 JSON의 버전·추천·행동 이력을 분석한다.
2. 별도 미노출 일반·미로 대전 표본을 늘려 준비 벽 비용의 퇴보 여부와 계산 비용을 확인한다.
3. 상대의 다음 연결 벽으로 내 우회 거리가 급증하는 위협을 후보 선별과 탐색 연장으로 보강한다.
4. 한쪽 벽만 남은 종반의 정확한 승패 계산 범위를 확장한다.
